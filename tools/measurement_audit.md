## 本轮结论

2026-10-01，北京时间 17:37:44–19:25:01，完整计时约 107 分钟；前后环境检查
均为 OK。测量期间仅运行这个串行任务，没有另开 SSH、编译、检查、同步或监控。

针对初始五份参考，124 道 OJ 题的 main 均已同时优于参考的最佳 max、sum。
初始全量中 range_kth_smallest 的 max 未达标；独立复核确认后，压缩其前缀
工作集，最终 max 35.726、sum 296.491 ms，参考最佳为 43.328/358.628 ms。
仅这个题的 main 依赖 offline_kth.h；其他正式 binary 和测量记录保持原批次。

range_kth_smallest 的正式 binary 与候选 SHA-256 相同，复用其两轮完整记录；
五份参考和 naive 复用初始全量的两轮记录，不再次计时。跟进数据保存在
bench/kth-20261001/final/，该题 bench.txt 分别标明来源，未把不同源码的测量混取。

static_range_sum/naive 为 max 28.940、sum 222.977 ms，chaihf 为
29.776/229.428 ms，两项均更快。自建 checksum 只比较自有实现，不计入 OJ 达标题数。

Writer 布局与 checksum 成对读取扩展未显示值得采用的整体收益，io.h 保持原样。

## 卷积算法与编译器对照

范围只包含四题。模 998244353 的两题保留单模数 NTT 的主解、旧版 naive 和
无手写汇编版本，不保留 FFT/CRT 程序。模 2^64、模 10^9+7 才比较 FFT 与
多模数 NTT＋CRT。所有同题版本使用相同的最新数组读写模板。

Clang 23.1.2 在 fedora-toolbox-45 内使用宿主机 sysroot，保持 libc/libm 与
GCC 16 一致；报告逐程序列出编译器，未以容器的新运行库冒充编译器收益。
完整源码与哈希在 bench/conv-variants-20261001/，最终合并报告在 complete/。
原主解及用户提交按相同 binary SHA-256 复用原测量，不重新挑选额外轮次。

更新 I/O 后，普通 998 题的旧版 GCC NTT 为 31.348/736.817 ms，已经双项
胜过参考，因此该题不必依靠汇编才能达标。大规模 998 题目前仍由汇编主解满足
性能门槛。u64 的“旧 NTT＋新 CRT”GCC 组合为 184.757/3147.361 ms，本轮也
达标，但 sum 优势只有约 0.35%；主解仍保留更大优势的版本。模 10^9+7 主解
继续采用无手写汇编的 FFT，统一新 I/O 后为 70.209/1576.633 ms。

保留的 FFT 对照通过官方数据、GCC/Clang 23 的最大长度常数与进位边界对照，
以及 ASan/UBSan。FFT 的舍入条件与测试范围在对应头文件旁说明。
曾包含多余 998 FFT 对照的批次已中止，未保存完整一轮，未将其不完整观测用于报告。
后续 graph、string 恢复 GCC 流程，不新增 Clang 23 评测。
