# io

已整理的接口在 `include/toy/io.h`，标准头文件和类型别名集中在 `common.h`。
面向 x86-64-v3、Linux、GCC/Clang，使用当前 `cxx_flags.txt`，无需链接 libstdc++。
旧 `io.hpp` 暂供尚未迁移的 `.cpp` 使用；已整理的 `.h` 统一由 `common.h` 引入系统头文件。

命名函数统一标记 `[[gnu::always_inline]]`。类内定义本来就隐含 `inline`；
类外函数保留显式 `inline`，用于头文件的多编译单元定义规则。
`inline constexpr` 表格是变量，不是函数，不能用 `always_inline` 替代。
属性不意味着一定更快：本轮朴素版在只增加强制内联标记后，二进制哈希完全相同。

```cpp
#include <toy/io.h>
using namespace toy;

int main() {
    Reader in;
    Writer out;
    u64 a = in.read<u64>();
    i128 b = in.read<i128>();
    u32 index = in.read<u32, 6>();  // 可选：绝对值最多 6 位，符号不计
    auto [l, r] = in.read_pair<6>(); // 两个无符号整数；位数上界不超过 7
    out.write(a);                 // 默认附加换行；第二个参数可改成 ' '
    out.write(b);
    u64 values[] = {a, index};
    out.write(span(values));      // 批量整数输出
}
```

输入约定：stdin 是普通文件，十进制整数合法且可放进目标类型，没有前导零或 `+`，
token 之间恰好一个空格/换行，最后也有分隔符。每进程一个 Reader，按题目给出的数量读取。
`token()` 返回映射中的字符串视图。输出使用局部缓冲区，Writer 析构时刷新。
竞赛输入不做错误恢复；文件尾额外映射一页，保证 SIMD 尾部读取安全。

位数提示只限定范围，不承诺分布。单个数字、短整数、完整 8/16 位块分别走简单路径；
完整 128 位输入分成 16 位块；给出不超过 38 位的上界时，长数改为两个 u64 块，
最后只做一次 64×64→128 乘法。输出按 4 位分组，5–16 位结果用 SIMD 去掉前导零，
128 位结果用常数倒数乘法拆成 19 位组。SIMD、倒数常量和游标处理的注释就在实现旁边。

当前还保留了以下小优化：四位上界使用 32 位归约；9–13 位读取中的完整八位前缀
用两个独立乘法归约，其他短整数保留原路径。Reader 直接推进成员游标，不再保留局部副本。
5–16 位输出通过约 1 KiB 的偏置表和一次进位求十进制位数，省去原来的乘法估计与阈值查表。
长整数直接归约二位或三/四位尾部；类型或位数上界排除二十位时，编译掉四位路径。
短数的 SIMD 对齐索引直接用长度计算；`read_pair` 用一次 16 字节加载同时解析两个端点。
有符号 128 位读入先按无符号解析，再用一个 64 位字构造掩码恢复符号；
输出用算术右移生成掩码，并保留零的快速路径。普通整数保留更简单的路径。
完整整数范围和规范十进制输出保持不变。

常见输入范围与新题覆盖见下文。

```sh
make gen-integer_checksum gen-many_aplusb gen-many_aplusb_128bit
make check-integer_checksum check-many_aplusb-main check-many_aplusb_128bit-main
```

GCC、Clang 均通过四题八份解答的各 129 项检查，生产二进制使用 `-nostdlib++` 链接。
额外以 Python 整数核对完整 i64/u64/i128/u128 范围的 400496 个读写值，
覆盖极值和十进制进位；另验证 76340 个不超过 38 位的数和 49004 对短整数。
小输出缓冲区、成对读取和长数分块均以 ASan/UBSan 检查。

## 输入范围与校验和题

对 253 道原有题目做过一次源码统计，按题去重、负数按绝对值合并。
常见输入上界集中在模数 998244353、数组/下标范围 5e5，以及数值范围 1e9。

| 数值 | 参数中出现的题数 | 重复读取引用该参数的题数 |
| ---: | ---: | ---: |
| 998244353 | 87 | 77 |
| 500000 | 67 | 34 |
| 1000000000 | 66 | 64 |
| 200000 | 41 | 23 |
| 100000 | 37 | 12 |
| 1000000 | 25 | 7 |
| 1000000000000000000 | 18 | 11 |
| 524288 | 14 | 1 |
| 1000000000000 | 4 | 3 |

“重复读取”通过 verifier 的循环、批量读取方法和简单变量引用推断，
不是完整 C++ 语义分析。间接调用、运行时推导的界和字符串编码的 128 位整数可能漏计；
循环次数、数组长度也可能被计入。它用来定位常见范围，不代表实际输入 token 的占比或分布。
操作类型等写在代码中的小常数需要另外考虑。

例如 `static_range_sum` 包含最多 500000 个 `[0, 10^9]` 的值，
以及最多 500000 对端点 `0 <= l < r <= N`：应同时覆盖 `10^9` 和 `5*10^5`。
模 998244353 的系数实际取值通常是 `[0, 998244352]`。
即使生成器随机，端点经过排序、取值经过筛选后也未必仍然均匀。

`many_aplusb` 的 `digit_random` 先均匀选择位数，再选该位数范围内的值，
一对 A、B 共用位数；128 位版本分别选择两者的位数和符号。它们不是高斯分布。

读入 N、L、R 和 N 个整数，输出和模 2^64。L、R 仅承诺范围，不承诺分布。
输出只有一个数字，主要测读取；两道 `many_aplusb` 继续测完整读写。
16 组均匀数据每组最多约 128 MiB，使大多数读取测试超过 50 ms：

| uniform 编号 | 闭区间 |
| --- | --- |
| 00–03 | [0,1]、[0,9]、[0,99]、[0,1000] |
| 04–07 | [0,10^5]、[0,2*10^5]、[0,5*10^5]、[0,10^6] |
| 08–11 | [0,998244352]、[0,10^9]、[0,10^12]、[0,10^18] |
| 12–13 | [-10^9,10^9]、[-10^18,10^18] |
| 14–15 | 完整 u64、完整 i64 |

边界数据另含十进制位数切换、正负极值、零，以及末尾恰好落在 4096 字节页边界的输入。
独立标程使用标量 fread 解析，校验和自然溢出；不使用 toy 库。

```sh

make check-integer_checksum
make bench-integer_checksum
```

## 展开提交

`tools/bundle.py` 递归展开 toy、ACL 和项目内的相对 include，保留注释和系统头文件。
它做文本展开，不解释宏 include 或条件编译；当前库采用直接包含、单次定义的头文件。

```sh
make bundle-sample-many_aplusb-main  # 单个解答
make bundle-sample-many_aplusb       # 整题

make bundle                          # 全部已整理的 .cxx
```

产物为 `bundle/sample/many_aplusb/main.cxx`，可以作为单文件提交。

也可直接运行 `python3 tools/bundle.py src/sample/many_aplusb/main.cxx -o bundle/main.cxx`。

## 与 chaihf 的读写对照

这里的“修改前”是本轮开始时的 `io.h`，不是兼容旧题解的 `io.hpp`。
实验固定前缀和/逐查询输出的主流程，交叉替换读取器和输出器；
另用相同输入做读入校验和、用预解码答案做输出测试。
临时对照代码仅在 `build/`，没有把参考提交的实现复制进 toy 库。

修改前的诊断结果（task-clock 中位数，ms）：

| 单独测试 | toy | chaihf 的对应实现 |
| --- | ---: | ---: |
| max_random_00 读取 | 14.467 | 13.985 |
| random_02 读取 | 8.595 | 7.004 |
| max_random_00 输出 | 6.489 | 5.800 |
| random_02 输出 | 5.208 | 5.028 |

参考读取器采用四字节归约加短尾；toy 的短整数路径还要计算长度、对齐到八位。
在 `random_02` 的读取实验中，toy 执行约 2352 万条指令、分支失误约 1.2 万次，
参考版本约 2534 万条指令、分支失误约 17.1 万次，仍是参考版本更快。
结合汇编中的长度、移位、游标依赖，可以看出减少指令或分支本身并不保证低延迟。

输出差别更直接：参考版本允许前导空格，以固定四位组写出；toy 保持紧凑十进制格式，
需要计算有效位数和移除前导零。max_random_00 输出阶段，toy 约 3235 万条指令，
参考版本约 2628 万条。最终优化仍保持 toy 原有的输出格式。

保留了并行八位前缀归约、四位专用路径、位数偏置表和局部输入游标；
完整 u64 的尾部另外区分二位和三/四位。试过的六位专用路径、缓冲区加倍、
堆/静态输出缓冲等没有表现出足够稳定的整体收益，未保留。
统一内联属性是代码风格整理，不能把实际提速归因于属性本身。

正确性验证包括 GCC/Clang 各 107 项题目检查、完整 64/128 位整数读写、
一百万次归约/位数核对，以及 ASan/UBSan 短缓冲区检查。
最终比较采用相同的 `./binary` 执行名、通过环境检查、不绑核，
每个非样例轮换顺序运行六次；期间没有额外 SSH、编译或文件同步。
原始数据与各轮源码快照位于 `bench/io-investigate-20260929/`。

### 最终结果

每一行的修改前后在同批静默测量中对照，非样例各六次取中位数后求和。
尾部修正后，仅重测二进制变化的项目；其余均核对 SHA-256 一致。单位 ms。

| 解答 | 修改前 sum | 修改后 sum |
| --- | ---: | ---: |
| 朴素 static_range_sum | 224.281 | 217.328 |
| 批处理 static_range_sum | 185.503 | 182.649 |
| many_aplusb | 203.556 | 201.791 |
| many_aplusb_128bit | 376.263 | 377.095 |
| 校验和 bounded | 2048.707 | 1965.059 |
| 校验和 main | 2868.049 | 2837.198 |

本轮 static_range_sum 朴素版 max 为 29.164 → 28.262 ms，sum 减少约 3.1%。
同批 chaihf 为 max 29.095、sum 223.504 ms，新版分别快约 2.9%、2.8%。
random_02 仍略慢于 chaihf，不能说所有输入都胜出。

校验和 bounded 在完整 u64 范围从 118.530 降到 84.355 ms，约快 28.8%。
并非全面提速：例如 bounded 的 [0,10^18] 从 63.215 变为 64.235 ms，
有符号宽整数也有少量退步；128 位 Many A+B 总时间约慢 0.2%，不视为明显收益。
最终明细在 `final/summary.txt` 与 `final-tail/summary.txt`。

位数上界应尽量准确：Many A+B 保证输入不超过 10^18，因此使用 `read<u64, 19>()`。
20 位全范围尾部路径更适合宽度混合的 u64；固定 19 位数据不一定从中获益。
补充准确上界后，该解答二进制与此前通过完整回归的版本一致。

`Writer::put(char)` 输出单个字符（例如多项式空行）；数字格式化热路径不变。

`Reader::token()` 返回借用的 ASCII token，适合大整数等长文本；现在每次用 AVX2
扫描 32 字节寻找分隔符，沿用文件末尾的零页以保证尾部读取安全。
复制 Reader 只复制游标，不会重新映射输入。`Writer::append(string_view)` 分批复制
原始文本到输出缓冲。已有数字题解在这些接口新增后重新构建，二进制全部未变。
