# Lyndon 分解：从字典序条件，到 Duval 的重复块扫描

Lyndon 分解把字符串切成若干 Lyndon 单词，要求这些因子从左到右按字典序不增。高效算法利用候选前缀的周期结构，一次确认连续几个相同因子；无需枚举切分，也无需建立后缀数组。

## 阅读导航

第 1～2 节解释定义并手算 `banana`，第 3～4 节推导上游 Duval 状态与线性时间，第 5～6 节追踪五份快解具体合并了哪些比较，最后保留快照和验证设计。

## 1. 什么样的单词叫 Lyndon

一个非空字符串 W，如果它严格小于自己的每一个非空真后缀，就是 Lyndon 单词。等价地，它在所有非平凡循环移位中严格最小；“严格”排除了整段重复。

| W | 检查 | 是否 Lyndon |
| --- | --- | --- |
| `a` | 没有非空真后缀 | 是 |
| `an` | `an<n` | 是 |
| `aab` | `aab<ab`，且 `aab<b` | 是 |
| `aba` | 后缀 `a` 是更短的前缀，`a<aba` | 否 |
| `abab` | 后缀 `ab<abab` | 否 |
| `aa` | 后缀 `a<aa` | 否 |

分解要求 `S=W1 W2 ... Wk`，每块都是 Lyndon，而且 `W1≥W2≥...≥Wk`。相等块允许重复。每个非空字符串都存在唯一这样的分解。

[题面](../../../upstream/string/lyndon_factorization/task.md)只输出切分边界 `0=a0<a1<...<ak=n`，因子是半开区间 `S[ai,ai+1)`。[约束](../../../upstream/string/lyndon_factorization/info.toml)为小写字母，`1≤n≤500000`。

### 1.1 完整例子：`banana`

正确分解为

```text
b | an | an | a
0   1    3    5  6
输出：0 1 3 5 6
```

`b`、`an`、`a` 都是 Lyndon 单词；顺序满足 `b>an=an>a`。把它拆成每个字符虽然每块也是 Lyndon，却会出现 `a<n` 的上升，违反非增条件。

`aaaa` 的分解只能是 `a|a|a|a`，输出 `0 1 2 3 4`，不能把 `aaaa` 当一个 Lyndon 因子。

## 2. 朴素办法为何不适合大输入

最直接的校验器可枚举 `n-1` 个间隙切不切，共 `2^(n-1)` 种分法，再检查各因子与它的真后缀及因子间顺序。这只适合很短的字符串。

较自然的尝试是对当前剩余串的每个前缀检查是否 Lyndon，寻找最长合适前缀。但反复比较许多重叠后缀，又会多次扫描相同字符。比如 `ananana...` 里，一直在重新发现同一个 `an` 重复块。

Duval 保存“当前候选 Lyndon 块，及它的若干重复和一个未完成前缀”，用相等/大于/小于三种字符关系推进。

## 3. 三个位置如何维护候选块

采用常见记号：i 是尚未输出部分的起点，j 是当前向右扫描位置，k 是用于与 j 比较的参考位置。初始 `j=i+1,k=i`。

已经扫描的 `S[i..j)` 可以理解成某个候选 Lyndon 块 W 的若干完整重复，再接 W 的一个前缀。候选块长度由 `p=j-k` 给出。

### 3.1 三种字符关系

| 比较结果 | 动作 | 为什么这样做 |
| --- | --- | --- |
| `S[k]==S[j]` | `k++,j++` | 正好延续候选块的下一份重复，周期 p 不变 |
| `S[k]<S[j]` | `k=i,j++` | 首次不同处右侧更大，扫描到的新前缀可以成为更长的 Lyndon 候选，从头重新对齐 |
| `S[k]>S[j]` | 停止本轮 | 右侧出现更小字符，当前重复块不能继续吸收它，已有完整重复可以输出 |

到字符串末尾也结束本轮。随后用 `p=j-k` 连续输出边界，直到新的 i 大于旧 k。

```text
教学伪代码（零基）
bounds=[0]
i=0
while i<n:
    j=i+1; k=i
    while j<n 且 S[k]<=S[j]:
        if S[k]<S[j]: k=i
        else:          k++
        j++
    p=j-k
    while i<=k:
        i+=p
        bounds.push_back(i)
```

相等时向前移动 k，和严格变大时把 k 重置到 i，是完全不同的操作。把两者合并会丢掉周期信息。

### 3.2 完整跟踪 `banana`

首先 `i=0,j=1,k=0`，比较 b 与 a，右侧更小，立即得到长度 1 的因子 b，输出边界 1。

接着从 i=1 扫描：

| 比较前 j,k | 字符关系 | 比较后 j,k | 已扫描内容 |
| --- | --- | --- | --- |
| 2,1 | a<n | 3,1 | `an`，候选变为 an |
| 3,1 | a=a | 4,2 | `ana`，an 后接 a |
| 4,2 | n=n | 5,3 | `anan`，两个 an |
| 5,3 | a=a | 6,4 | `anana`，两个 an 后接 a |

到末尾时 `p=6-4=2`。输出 `i=1→3→5`，对应两个 `an`；剩余的最后一个 a 尚不足一个长度 2 块，留到下一轮。最后输出边界 6。

### 3.3 为什么输出的是正确的非增 Lyndon 因子

维护的候选 W 始终是 Lyndon：相等只是在重复它，严格变大使此前的比较在首次不同处获得正确的严格顺序；较小字符出现则说明不能把这一段再并入当前候选。结束时，已完成的 W 重复可以确定，而未完成的尾部要重新开始判断。

因此一轮输出若干相同的 W，下一轮得到的因子不会比 W 大；否则前一轮仍应能吸收那个严格更大的延伸。结合 Lyndon 分解的唯一性，这正是题目要求的分解，而不是任意选择的一种切分。

## 4. 为什么扫描里有回看，仍是线性时间

在一轮里，j 单调向右。设本轮扫描长度为 `j-i`，输出的完整重复总长为 D。由于只留下不足一个周期 p 的尾部，而已经至少输出一个 p，

```text
j-i = D + 剩余尾长 < D+p ≤ 2D
```

每轮扫描工作可以计入本轮已经输出的字符，至多一个常数倍；所有轮输出总长恰为 n。所以 Duval 字符比较为 `O(n)`，因子边界空间为 `O(k)`，最坏 `O(n)`。

这也解释了可以重新检查不完整尾部而不失去线性界。不能要求 j 在整个算法里永不回退，真正的摊还依据是“本轮扫描与本轮确认输出成比例”。

### 4.1 上游变量与教学记号对应

[上游 `correct.cpp`](../../../upstream/string/lyndon_factorization/sol/correct.cpp)的 `LyndonFactorization::FromStr` 正是这一过程：

| 上游变量 | 教学含义 |
| --- | --- |
| `seekBeg` | i，未输出起点 |
| `repEnd` | j，扫描位置 |
| `repEndPrev` | k，对齐参考位置 |
| `factorLen` | `j-k` |
| `pos` | 全部边界，初始含 0 |

上游读入静态字符缓冲、`strlen` 求长度，构造边界 vector，逐项 `printf`。它已经线性；快解主要减少标量比较、逐项边界追加及 I/O 成本。

## 5. #403380：把连续的 Duval 状态变化批量执行

[源码](../../selected/lyndon_factorization/403380.cpp)入口为 `main → lyndon_factorization::assign_bytes → lyndon_boundaries`。本题直接走字节串路径，没有调用通用对象编码、哈希等其他模板接口。

### 5.1 连续相等字符：一次找出最长相等段

若当前 `S[k]==S[j]`，普通 Duval 反复 `k++,j++`。源码调用 `extend_lcp(k+1,j+1,剩余长度)`，一次找到后续相等长度，再同时推进 k、j。

两指针增量相同，`j-k` 保持不变，所以这与逐字符相等分支严格等价。AVX2/机器字比较减少循环控制与逐字节比较指令，仍检查了真实字符，不是哈希猜测。

### 5.2 参考点已经在 i 时：跳过连续大于首字符的段

当 `k==i`，如果后面若干字符都严格大于 `S[i]`，普通算法每读一个都会执行同样的 `k=i` 重置。`skip_greater_bytes` 用向量比较找到第一个不大于 pivot 的字节，直接推进整段 j。

**只有 `k==i` 才能这样跳。** 若 k 正在候选块内部，参考字符未必是首字符，不能用一个固定 pivot 代替后续比较。代码保留这个前提，因此批处理的是原算法的一串确定状态变化。

### 5.3 已知重复数后，整块生成边界

本轮有 `p=j-k`，完整重复数为 `copies=(k-i)/p+1`。程序一次 resize 边界数组，再填 `i+p,i+2p,...`，避免每个因子单独做 vector 容量检查。

全相同串可以用长相等段跳过比较，但仍须输出 n+1 个边界；没有把必要的输出项省掉。源码是面向 AVX2、Linux 普通文件映射输入的导出版本，快照没有分离批量比较与 I/O 的收益。

## 6. 其他四份源码：相同原则，不同状态组织

### #221265：标准三指针 Duval

[源码](../../selected/lyndon_factorization/221265.cpp)的 `solve → duval` 就是第 3 节 i/j/k 分支，区别是每个因子先保存起点 i，最后追加 n；上游则先保存 0，再逐个保存终点，两种方式给出相同边界数组。

自定义 Scanner/Printer 提供缓冲 I/O，内核仍逐字符比较，没有 #403380 的批量 LCP/固定 pivot 扫描。它与第一名同为 9 ms，快照不足以把两者排出确定的内核速度高低。

### #394259：泛型投影接口上的三指针版本

[源码](../../selected/lyndon_factorization/394259.cpp)调用 `atl::lyndon_factorization(s)`，通过 `symbol(i)` 取字符，再执行同样的 `j/k` 比较与边界生成。默认投影为 identity，当前 string 的随机访问是常数操作，泛型接口不意味着为每个字符建立额外对象。

它使用 atl 自定义 reader/writer，保存完整边界后输出。相比上游主要是 I/O 和代码组织，未见改变 Duval 数学工作量的另一算法。

### #150297 / #154455：逐字节相同的重复区间版本

[第一份](../../selected/lyndon_factorization/150297.cpp)与[第二份](../../selected/lyndon_factorization/154455.cpp)原始源码及完整 SHA-256 都相同，不只是换行等价。它们的 `nachia::LyndonFactorization::FromStr` 使用 `sameBeg,prevBeg,prevEnd,pos`，并非把上游三变量简单改名。

`[prevBeg,prevEnd)` 记录当前重复块，`pos` 与块的对应位置比较；一份重复完整结束后，把 prevBeg/prevEnd 推到这份新重复。若出现严格更大字符，则把从 sameBeg 开始到新字符的整体设为更长候选；遇到较小字符或串尾，按块长从 sameBeg 到 prevEnd 逐个输出边界，再处理剩余尾部。

在 `banana` 的 `an|an|a` 一段中，识别出第二个完整 `an` 后，参考块从 `[1,3)` 移到 `[3,5)`；最后读到串尾时输出 3、5，把不完整的 a 留到下一轮。这是 Duval 重复结构的另一种维护方式，仍为线性级扫描。

输入输出使用 nachia 的 fread/缓冲流及数值查表。两份完全相同源码在快照上为 10 ms 与 13 ms，差异不能归因于算法改动或变量布局变化。

## 8. 误区与后续验证

| 易错点 | 应检查的事实 |
| --- | --- |
| 任意回文或重复块都是 Lyndon | 判定依据是严格字典序，`aa` 和 `abab` 都不是 |
| 每个字符单独切总能满足题意 | 还要求因子非增，`a|n` 就不满足 |
| 因子必须严格递减 | 相等因子允许，如两个 an |
| 相等与严格变大都重置 k | 相等应推进 k，才能保留周期 |
| 第一次差异结束后输出整个已扫区间 | 只能输出完整周期，未完成尾部留下一轮 |
| SIMD 跳过大于 pivot 的字符无条件成立 | 必须处于 k==i 的状态 |
| 同源码快照时间不同说明某函数被优化 | 本样本不存在对应源码变更 |

小规模可枚举所有切分，检查每因子严格小于自己的真后缀、因子序列非增，再与 Duval 边界逐项比对。必要样例有 `banana`、`aaaa`、递增串、递减串、很多完整重复后跟半个块，以及末尾突然出现更小字符的串。

未来实验可分别统计相等分支长度、pivot 跳段长度、因子数量、输入/内核/输出时间。固定 I/O 后比较标量和批量状态推进，才能验证收益。本文只做源码路径、哈希、重复文件、数学例和本地链接检查，没有性能 benchmark 或 OJ/API 调用。
