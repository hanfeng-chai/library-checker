# 不同子串个数：从集合去重，到后缀数组扣重与后缀自动机

题目只要求一个计数，却可能有上千亿个不同子串。高效算法不会把每个子串存下来，而是把同一后缀的前缀、或同一结束位置集合的子串归成一组，直接计算这一组贡献多少。

## 阅读导航

第 1～3 节给出完整例子与 SA/LCP 计数证明；第 4 节解释上游怎样在线性时间计算 LCP；第 5 节给后缀自动机的计数原理与 clone 手算；第 6～8 节逐份追踪快解的实际路径；最后保留快照和验证边界。

SA-IS 排序的完整手算见[后缀数组教程](../suffixarray/analysis.md)。本文仍保留理解当前计数所需的最小背景，教学伪代码与作者代码分开说明。

## 1. 题目：按内容去重，不按出现位置计数

[题面](../../../upstream/string/number_of_substrings/task.md)给长度 `1≤n≤500000` 的小写字符串，求不同的**非空连续子串**个数。子串不能跳字，位置不同但字符内容相同只算一次。

`S=aba` 的六个区间产生 `a,ab,aba,b,ba,a`，去重后为

```text
a, b, ab, ba, aba
答案 5
```

总区间数恒为 `n(n+1)/2`，它不是去重后的答案。全 `a` 的字符串只有 `a,aa,…,a^n`，答案为 `n`。

最大总区间数为 `500000×500001/2=125000250000`，必须用 64 位计数；不要先在 32 位里相乘再转宽类型。

## 2. 朴素方法与为什么不能枚举结果

教学上可以枚举所有 `[l,r)`，把 `S[l..r)` 插进字符串集合。共有 `O(n²)` 个区间；若每次复制子串，复制总字符数可达 `O(n³)`，再加集合比较或哈希成本。

即使某种哈希让每段取得一个固定大小指纹，仍有 `O(n²)` 个区间，且只用指纹去重还有碰撞问题。本题应直接统计组合结构，而不是仅把字符串换成哈希值后继续枚举。

每个起点 `i` 的所有子串，恰好是后缀 `S[i..n)` 的所有非空前缀。于是可以把问题改成：按顺序加入各个后缀，每次有多少新前缀？

## 3. 后缀数组：每个后缀只减去与前一个的 LCP

后缀数组 SA 把所有后缀按字典序排序。定义 `LCP[k]` 为排序后第 `k-1` 与第 `k` 个后缀的最长公共前缀长度，第一项视为 0。

### 3.1 用 `banana` 完整计数

| 起点 | 当前后缀 | 后缀长度 | 与前一个的 LCP | 新增不同子串 |
| ---: | --- | ---: | ---: | --- |
| 5 | `a` | 1 | 0 | `a`，共 1 个 |
| 3 | `ana` | 3 | 1 | `an,ana`，共 2 个 |
| 1 | `anana` | 5 | 3 | `anan,anana`，共 2 个 |
| 0 | `banana` | 6 | 0 | `b,ba,ban,bana,banan,banana`，共 6 个 |
| 4 | `na` | 2 | 0 | `n,na`，共 2 个 |
| 2 | `nana` | 4 | 2 | `nan,nana`，共 2 个 |

总数 `1+2+2+6+2+2=15`。所有后缀长度和是 `21`，相邻 LCP 和是 `1+3+0+0+2=6`，所以也可算 `21-6=15`。

### 3.2 为什么只看相邻的前一个就够

具有共同前缀 `P` 的字符串在字典序中占连续区间。如果当前后缀与更早的某个后缀共享 `P`，夹在中间的所有后缀也共享 `P`，特别是紧邻当前的前一个。

所以当前后缀与所有已处理后缀的最大公共前缀长度，恰是与前一个的 LCP，记为 `h`。长度 `1..h` 的前缀都出现过，长度 `h+1..n-SA[k]` 都是新的。这给出

```text
答案 = Σ (n-SA[k]-LCP[k])
     = n(n+1)/2 - Σ 相邻后缀LCP
```

这不是启发式地减去“部分重复”。字典序的连续性保证每个重复前缀都被准确覆盖一次，正好留下第一次出现的那份。

## 4. 上游：SA-IS 排序，再复用 LCP 的已知长度

[上游 `correct.cpp`](../../../upstream/string/number_of_substrings/sol/correct.cpp)的调用链为

```text
main
  → sa_is(s)：含唯一最小哨兵的后缀排序
  → SA(s,order)：建立逆排名 rsa 和相邻 lcp
  → int64 的 n(n+1)/2 减去所有 lcp
  → printf 一个答案
```

SA-IS 的步骤是：划分 S/L 后缀类型，找 L 后面紧接的 S 位置（LMS），按字符桶诱导，给 LMS 小块命名，递归排序缩小序列，再诱导完整顺序。LMS 不相邻，递归规模至多约一半；固定字母表下总时间和空间均为 `O(n)`。

内部多出的空后缀最小，与下一个后缀 LCP 为 0，不改变计数。主式中的 `n` 始终是原串长度，不能把哨兵算作一个可选子串字符。

### 4.1 相邻 LCP 也不能每对从零比较

全 `a` 的串相邻 LCP 很长，若逐对从零扫描仍会平方。上游按**起点 i 从左到右**处理，而不是按 SA 顺序比较，维护一个可复用的长度 `h`。

如果后缀 `i` 与其字典序前驱 `j` 相同了 `h` 个字符，去掉第一字符后，`i+1` 与 `j+1` 至少还相同 `h-1` 个。后者仍在 `i+1` 前面；而与 `i+1` 紧邻的前驱只会共享至少同样长的前缀。因此下一步可以从 `max(h-1,0)` 开始。

```text
教学伪代码：Kasai 的前驱版本
rank[SA[k]] = k
h = 0
for i = 0 .. n-1:
    h = max(h-1, 0)
    j = SA[rank[i]-1]       // 上游有空后缀作第一个元素
    while 两边未结束 且 S[i+h]==S[j+h]: h++
    lcp[rank[i]-1] = h
```

`banana` 的实际按起点处理如下：

| i | 字典序前驱起点 | 复用的起始 h | 最终 LCP |
| ---: | ---: | ---: | ---: |
| 0 | 1 | 0 | 0 |
| 1 | 3 | 0 | 3 |
| 2 | 4 | 2 | 2 |
| 3 | 5 | 1 | 1 |
| 4 | 0 | 0 | 0 |
| 5 | 6（空后缀） | 0 | 0 |

每轮 `h` 最多减 1，所有成功增加合起来线性，失败比较每轮最多一次，所以 LCP 构建为 `O(n)`。

### 4.2 上游保留了哪些数组

原串、SA、逆排名和 LCP 都保留到求和阶段，另外有 SA-IS 的类型、桶、LMS 和递归工作区。总空间仍为 `O(n)`，但只有最终 LCP 的**和**需要输出，快解可以不保存整个 LCP 数组。

## 5. 另一条路线：SAM 按长度区间计数

后缀自动机（SAM）不需要先把后缀排序。它按输入字符逐个构建，用状态合并具有同一组结束位置的子串。

### 5.1 一个状态为什么贡献一个长度区间

同一状态中，最长串的长度记为 `len[v]`。它的较短后缀只要仍有相同结束位置集合，就属于这个状态；第一次变成其他集合时，由 suffix link 指到另一个状态。

因此状态 `v` 恰好代表长度

```text
len[link[v]]+1, ..., len[v]
```

的各一个子串，贡献 `len[v]-len[link[v]]`。根代表空串，不参与非空计数。把所有状态贡献相加就是答案。

例如 `aba` 的一个状态可以同时代表 `ba` 与 `aba`：两者只结束于最后位置，长度为 2、3；它的 link 指向 `a` 的状态（长度 1），贡献就是 `3-1=2`。

### 5.2 clone 不是“多造一个子串”

用 `abb` 走一遍，会出现必须拆状态的情况：

| 新读入字符 | 新出现的子串 | 新增数 | 累计 |
| --- | --- | ---: | ---: |
| `a` | `a` | 1 | 1 |
| `b` | `b,ab` | 2 | 3 |
| `b` | `bb,abb` | 2 | 5 |

读完 `ab` 时，`b` 和 `ab` 都只结束于位置 1，可以放在同一状态 q（最长长度 2）。再读一个 `b`，`b` 的结束位置变成 `{1,2}`，`ab` 仍只有 `{1}`，它们必须分开。

算法建立长度 1 的 clone，接管 `b` 那一层，复制 q 的后续转移并调整相关链接。q 原来的贡献 2 被拆成 q 的 1 与 clone 的 1，总贡献不变；新状态 `abb` 最长长度 3、link 长度 1，新增 `3-1=2`，恰好是 `bb,abb`。

常规构建的教学步骤为：

```text
新建 cur，len[cur]=len[last]+1
沿 last 的后缀链接，给缺少字符 c 的状态补转移到 cur
若遇到已有转移 p --c--> q:
    若 len[q]=len[p]+1：cur 的 link 直接到 q
    否则复制 q 为 clone，令 len[clone]=len[p]+1
         把对应旧转移改向 clone，q 和 cur 的 link 都改向 clone
更新 last=cur
新增答案 = len[cur]-len[link[cur]]
```

这是教科书式组织。#402203 使用特定编号和根处理来写同一不变量；不能把伪代码里的数组和哨兵逐字当作作者实现。

## 6. #403163：只求 LCP 总和，另加可验证的排序分流

[源码](../../selected/number_of_substrings/403163.cpp)入口调用 `count_distinct_substrings(text,execution)`。

### 6.1 全相同串直接返回 n

在分配后缀数组以前，程序完整比较 `text[0..n-1)` 与 `text[1..n)`。如果全部相同，只有长度 `1..n` 的同字符子串，直接返回 `n`，省掉 SA、rank、LCP 及其工作区。

这不是检查一小段后猜整串相同。一般输入仍进入后缀排序和 LCP 求和。

### 6.2 用后继表替代 rank 与 LCP 结果数组

`adjacent_lcp_sum` 先建立

```text
successor[SA[k]] = SA[k+1]
```

最后一个后缀的后继记为哨兵 `n`。随后按起点 `i` 连续扫描，直接读 `successor[i]` 得到比较对象，使用与 Kasai 相同的 `h-1` 复用，边算边累加，不保存各位置 LCP。

`banana` 的后继表为 `[4,0,6,1,2,3]`。这与前驱版本方向不同，但求的仍是同一组相邻后缀 LCP，和都为 6。

相对上游，它省掉独立 rank 和 LCP 两数组的组织，改用一条约 `4n` 字节的后继表；同时避免先写完整 LCP 再读回来求和。字符扩展有受边界限制的块比较/AVX2 路径。

### 6.3 本份 SA 内核比后缀数组题的同作者版本多了分流

它保留了全串短周期验证、LMS 数量 `≤64` 时直接排少量后缀、有限前缀键完整验证后省递归、失败回退的路线；原理见相邻 SA 教程。除此之外，本份源码还实际开启以下选项：

| 机制 | 先验证什么 | 省掉什么 |
| --- | --- | --- |
| `separator_reduction` | 一个奇偶位置全是相同且严格最小的字符，另一侧都更大；检查全串，且 `n≥256` | 删除交替分隔符，排序规模近半，再恢复两组后缀 |
| `direct_lms_names` / `factor_reduction` | 每个完整 LMS 块能装进固定键，字典种类和探测数均不超预算 | 直接命名小块，省第一轮诱导 |
| `binary_induction` | 当前编码字母表恰为 `{0哨兵,1,2}` | 用两类符号专用队列诱导，省空槽扫描、清零与符号编码 |

分隔符的教学例 `abacabad` 删掉偶数位的 `a`，得到 `bcbd`。后者的后缀顺序为 `[0,2,1,3]`，对应原串非分隔符起点 `[1,5,3,7]`；把前一个分隔符加回来，得到先排的一组 `[0,4,2,6]`，完整 SA 为 `[0,4,2,6,1,5,3,7]`。若最后单独留下一个最小分隔符，要把这个最短后缀单列。该八字例仅说明映射，真实分流有长度门槛。

直接 LMS 命名把**完整块**编码，而非截断后赌没有碰撞；字节块最多容纳 8 字节，种类至多 128，哈希表至多探测 8 次，任何预算失败就回退。哈希撞槽时比较完整键，不能把它称为依赖随机哈希正确性的算法。块前缀边界采用专门填充顺序，也不能用普通字符串的短者先规则替代。

该提交编译目标为 AVX2，输入适配器面向 Linux 普通文件。各分流的全输入条件可由源码判断，但快照未记录每个测试具体命中的 backend。

## 7. #402203：构建 SAM 时直接累计新增子串

[源码](../../selected/number_of_substrings/402203.cpp)的 `main` 读入 `s`，调用 `suffix_automaton(std::move(s)).count_distinct()`。它使用原串构建普通 SAM，没有反串，也没有输出后缀顺序。

普通状态编号就是对应前缀长度，因此构建里用

```text
distinct += last - length(link[last])
```

累计第 5 节的新增区间，最终只返回这个 64 位和。相比上游，它完全省去 SA 排序、逆排名和 LCP 扫描，代价是维护 SAM 转移和 clone。

转移布局按实际字母表选择：1、2、至多 4 个字符时用固定宽度行；字母表 `≤16` 或 `n×alphabet≤2^23` 时用扁平稠密行；其余使用两个打包的内联转移，第三种字符出现后再升级为 26 路稠密行。字符先压到连续编码，因此宽度取决于真实使用字符数。

普通状态的长度和代表结束位置由编号推出，只给 clone 额外存元数据；较大存储使用页对齐及 huge-page 提示。它降低了某些输入的转移空槽或元数据读取，但宽度较大时仍可能比 SA 路线占更多内存，快照约 66.1 MB。

源码的 `cin/cout` 被 blazingio 宏替换，不能当作标准 iostream 的性能对照。类里的反串后缀数组与最长公共子串方法都未被这个 main 调用。

## 8. 其他三份实际路径

### #160592：Go 标准库排序，自己扫描 LCP 总和

[保存为 `.txt` 的 Go 源码](../../selected/number_of_substrings/160592.txt)调用 `suffixarray.New(s)`，通过 `unsafe.Pointer` 把内部布局视作含 `[]int32` 后缀数组的结构，再建立 rank，运行前驱版 Kasai，直接从答案减去 `h`，不保存 LCP 数组。

输入用 `syscall.Read`、`TrimSpace`，输出一次整数，`init` 关闭 GC。它依赖评测 Go 版本的标准库内部布局与 64 位 `int` 容量；这不是公开的后缀数组读取 API。提交没有携带该评测版本标准库内部实现，本文不据用户代码把底层强行认定为某个具体版本的 SA-IS 内核。已核查的是“库建 SA + 用户代码线性 LCP 求和”这条实际路径。

### #406077：复用 SA 工作区的 SA-IS，随后显式 LCP

[源码](../../selected/number_of_substrings/406077.cpp)调用 `akrbt::SuffixArray::Init`、`LCPArray::Init`，再求 `n(n+1)/2-ΣLCP`。小写字母触发按最小/最大值平移的编码分支，通用大值域比较排序压缩分支在本题不执行。

SA-IS 使用 `i8` 类型数组、SA 后半区存缩小名字、可复用桶缓冲；名字唯一时跳过递归。LCP 是后继版，保留 rank 与 LCP 两数组，再统一求和。它的计数流程接近上游，主要差别在工作区布局、字母表范围和 SA 内核，而不是省去 LCP。

### #235767：通用 SA/LCP 类，RMQ 没有被构建

[源码](../../selected/number_of_substrings/235767.cpp)的 `Suffix_Array(s)` 调用 SA-IS，并在构造时建立 `isa` 与 `LCP`，main 最后对 LCP 求和。字符按实际最小/最大值编码，递归名字唯一时省子递归，结果删去哨兵。

类里还定义了稀疏表、区间 LCP 查询和比较接口，但只有另调 `build_lcp()` 才会建立 RMQ；本题没有调用它。不能因为模板里出现 `Sparse_Table` 就把 `O(n log n)` 的预处理算成本题实际工作。它保留完整 LCP 数组，属于通用接口换取复用性的选择。

## 10. 误区与验证设计

| 误区 | 应检查的事实 |
| --- | --- |
| 子串个数就是区间个数 | 相同内容要去重，空串不计 |
| 与全部早先后缀都比较才安全 | 字典序相同前缀形成连续区间，只需相邻前驱 |
| 相邻 LCP 从零扫也是线性 | 需复用 `h-1`，全同串是典型反例 |
| SAM 每状态只代表一个子串 | 它代表一个连续长度区间 |
| 每个 clone 都增加新子串 | clone 拆旧贡献，新增量来自当前最长状态 |
| 文件里有稀疏表就执行 RMQ | #235767 本题没有调用 build_lcp |
| 标准库名字足以确定 OJ 内部版本 | #160592 的内部算法与布局需要对应工具链证据 |

小串可用集合枚举非空子串，同时核对 SA/LCP 公式与 SAM 各状态贡献。固定样例包括 `aba=5`、`abb=5`、`banana=15`、全同串答案为长度；检查 `n(n+1)/2` 的中间乘法是 64 位。

后续性能实验应固定输入，分别记录排序、LCP 求和、SAM 构造、clone 数、实际转移宽度与峰值内存；特殊分流必须记录完整验证是否成功。单答案输出很短，本题与需要输出几十万个编号的后缀数组题不能直接按 OJ 时间横向归因。

本轮完成源码入口、五份完整哈希、本地链接、计数/LCP/SAM/分隔符例子验证，没有新增性能 benchmark 或 OJ/API 调用。所有排名、AC 和内存仍是上述抓取时刻的快照。
