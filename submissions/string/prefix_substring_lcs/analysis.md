# 前缀—子串 LCS：从普通动态规划，到阈值表与离线计数

这里 LCS 指最长公共**子序列**，可以跳过字符。查询固定字符串 S 的某个前缀，与 T 的某个连续区间之间的子序列长度；两串本身不会修改。上游用一条阈值数组同时编码所有左端点，再离线统计，快解中也有直接扫描预存阈值行的方案。

## 阅读导航

第 1～2 节给完整查询与普通 DP，第 3～4 节从 DP 增量推导阈值交换规则，第 5 节解释上游按 a/c 分组加 Fenwick，第 6～7 节逐份对照五份源码的时间/空间取舍，最后是快照、边界与验证设计。

“seaweed/半局部 LCS”是这类共享计算的名称，本文直接推导此题使用的简化规则，不要求预先掌握几何图像或专门术语。

## 1. 输入、区间与完整小例

[题面](../../../upstream/string/prefix_substring_lcs/task.md)给 S、T 和 Q 个查询 `(a,b,c)`，回答

```text
LCS(S[0..a), T[b..c)) 的长度
```

[参数](../../../upstream/string/prefix_substring_lcs/info.toml)为 `|S|=M≤1000`、`|T|=N≤1000`、`Q≤500000`，允许 a=0 或 b=c。查询只要求长度，不要求恢复具体子序列。

取 `S=ab,T=aba`：

| 查询 `(a,b,c)` | 比较的两个串 | 一个最长公共子序列 | 答案 |
| --- | --- | --- | ---: |
| `(0,0,3)` | 空串，`aba` | 空 | 0 |
| `(1,0,3)` | `a`，`aba` | `a` | 1 |
| `(1,1,3)` | `a`，`ba` | `a` | 1 |
| `(2,0,3)` | `ab`，`aba` | `ab` | 2 |
| `(2,1,3)` | `ab`，`ba` | `a` 或 `b` | 1 |
| `(2,2,3)` | `ab`，`a` | `a` | 1 |
| `(2,1,1)` | `ab`，空串 | 空 | 0 |

应按输入顺序输出 `0,1,1,2,1,1,0`，每项一行。

## 2. 普通 LCS DP 能解决一问，但重复太多

对两个具体串 A、B，普通 DP 为

```text
D[i+1][j+1] = D[i][j]+1                      若 A[i]==B[j]
D[i+1][j+1] = max(D[i][j+1],D[i+1][j])       否则
```

第一行、第一列为 0。它允许从左格或上格继承，表示跳过一个字符；与连续子串 DP 遇到不同字符就清零的规则不同。

每问重新计算需 `O(a(c-b))`，最坏 Q 次接近 `5×10^11` 个格子。预存 S、T 的所有前缀 LCS 也不够：区间左端可以不为零，答案不能由两个前缀答案相减。

反例是 `S=a,T=aa`：两个 T 前缀的 LCS 都是 1，相减为 0，但 T 的第二个字符单独组成 `a`，答案应是 1。不同区间可以重新选择匹配位置，没有普通区间和那样的可减性。

## 3. 用一个阈值描述“追加 T[j] 是否增加答案”

固定 S 前缀长度 a，记

```text
F_a(b,c) = LCS(S[0..a), T[b..c))
```

右端从 j 增到 j+1 时，只加入一个字符，答案增量只能是 0 或 1。可以用一个阈值 `h_a[j]` 表示对所有合法左端 b 的这个增量：

```text
F_a(b,j+1)-F_a(b,j) = 1，当且仅当 h_a[j] < b
```

其中 `-1≤h_a[j]≤j`。从 b 一路累加到 c，得到关键查询式：

```text
F_a(b,c) = #{ j∈[b,c) : h_a[j] < b }
```

这不是声称 h 存 LCS 值。h 存的是**开始位置的门槛**，所以可以为 -1；-1 表示对任何非负 b 都产生这一步增量，j 表示对任何合法 b≤j 都不产生增量。

### 3.1 主例的全部阈值行

```text
S 前缀空串：h0 = [ 0, 1, 2]
S 前缀 a ：h1 = [-1, 1, 0]
S 前缀 ab：h2 = [-1,-1, 1]
```

例如 `h2[2]=1`：加入 T 的最后一个 a，只有左端 b>1 才增加答案。

- b=0 时，前面的 `ab` 已经给长度 2，加最后 a 不会增加。
- b=1 时，比较 `ab` 与 `b` 已有 1，扩成 `ba` 仍为 1。
- b=2 时，从空区间扩成单个 a，答案由 0 变 1。

查询 `(2,1,3)` 看行 h2 的位置 1、2，值为 -1、1，只有 -1<1，答案就是 1。

## 4. 从普通 DP 推出交换与 max/min，不把规则当黑箱

最初 a=0，空 S 不会因追加 T 字符增加 LCS，所以设 `h0[j]=j`，对所有 b≤j 都有 `h0[j]<b` 为假。

现在向 S 追加字符 x，扫描 T 的第 j 列。令 h 是该列旧行阈值，v 是从左一格带来的阈值，初始 v=-1。固定任意合法 b，观察一个普通 LCS DP 小格：

```text
左上角 A              右上角 A+U
左下角 A+V            右下角待求
```

这里

```text
U = [h < b]     // 旧 S 行，增加当前 T 字符的增量
V = [v >= b]    // 当前 T 前缀，增加新的 S 字符的增量
```

方括号是真为 1、假为 0。左边起始为空 T 区间时 V=0，v=-1 正好表示它。

### 4.1 字符相等时

右下角为 `A+1`。因此新水平增量为 `1-V`，新垂直增量为 `1-U`。

```text
1-V = [v < b]，所以新水平阈值是 v
1-U = [h >= b]，所以新垂直阈值是 h
```

于是交换 h、v。

### 4.2 字符不等时

右下角是 `A+max(U,V)`。新水平增量为 `U 且非 V`，新垂直增量为 `V 且非 U`：

```text
新水平为 1 ⇔ h<b 且 v<b ⇔ max(h,v)<b
新垂直为 1 ⇔ h>=b 且 v>=b ⇔ min(h,v)>=b
```

所以新 h 取 max，向右带走的 v 取 min。把两种情况合并，正是上游的短代码：

```text
v = -1
for j = 0 .. N-1:
    if x==T[j] 或 h[j]<v:
        swap(h[j],v)
```

这同时对所有左端 b 更新了一整行答案，而不是每个 b 再算一次 DP。每格只做常数次比较/交换，处理全部 S 字符需 `O(MN)`。

### 4.3 主例逐格更新

| 追加 S 字符 | j / T[j] | 旧 h[j] | 进入的 v | 动作 | 新 h[j]、新 v |
| --- | --- | ---: | ---: | --- | --- |
| a | 0 / a | 0 | -1 | 相等，交换 | -1，0 |
| a | 1 / b | 1 | 0 | 不等，max/min | 1，0 |
| a | 2 / a | 2 | 0 | 相等，交换 | 0，2 |
| b | 0 / a | -1 | -1 | 不等，max/min | -1，-1 |
| b | 1 / b | 1 | -1 | 相等，交换 | -1，1 |
| b | 2 / a | 0 | 1 | 不等，交换成 max/min | 1，0 |

所以得到第 3 节三条 h 行。每步还保持 `h[j]≤j`：旧 h 不超过 j，从左带来的标签也不超过 j-1。这个性质会让上游的 Fenwick 查询只需扫 T 的前缀。

## 5. 上游实际采用离线分组与 Fenwick

[上游 `correct.cpp`](../../../upstream/string/prefix_substring_lcs/sol/correct.cpp)先读完全部查询，按 a 分组。a=0 的答案直接置零。随后逐字符推进 S 的阈值行；处理完长度 a 时，回答该组查询。

题目要求按顺序输出，但查询参数不依赖前一答案，也没有交互。因此可以离线重排计算顺序，最后按原查询编号输出，仍满足题意。

### 5.1 把阈值统计换成二维计数

查询需要数 `[b,c)` 中 `h[j]<b` 的位置，等价于

```text
(c-b) - #{ j∈[b,c) : h[j]>=b }
```

因为 `h[j]≤j`，任何 j<b 都不可能满足 `h[j]>=b`，所以上式的坏位置也可在整个 `[0,c)` 中统计。

固定当前 a，按右端 c 从小到大扫描；将遇到的非负 h 值加入 Fenwick，count 记录加入的总数。`sum(b)` 统计其中严格小于 b 的 h 值，故

```text
答案 = (c-b) - (count-sum(b))
```

-1 不必加入：它对任何合法 b 都是好位置，不会被减去。

### 5.2 Fenwick 小例

对 h2=`[-1,-1,1]` 扫到 c=3，树中只有标签 1，count=1：

| b | `sum(b)`：标签 <b 的个数 | 公式结果 |
| ---: | ---: | ---: |
| 0 | 0 | `3-(1-0)=2` |
| 1 | 0 | `2-(1-0)=1` |
| 2 | 1 | `1-(1-1)=1` |

Fenwick 把一个下标加 1 和查询前缀和都压成 `O(log N)` 次数组访问。API 的 sum(b) 是 `[0,b)`，不是包含 b 的前缀，否则严格不等号会错一位。

### 5.3 实际调用和复杂度

上游为每个 a 建立 `sep_c`，把查询挂到 c-1；扫描到相应位置时求值，a=0 或 c=0 单独处理。每一行都会更新阈值、扫描 T 并建立 Fenwick，即使该行查询较少也有相应准备成本。

时间为 `O(MN log N + Q log N)`，存储阈值只需 `O(N)`，另有全部查询和分组，合计 `O(M+N+Q)` 级。上游没有保存所有 h 行，也没有为每问重新跑 LCS DP。

## 6. 三份预存全表、查询直接扫描的实现

### #261415：存水平与垂直标签，连续读取一行回答

[源码](../../selected/prefix_substring_lcs/261415.cpp)建立 `ih[M+1][N+1]` 与 `iv[M+1][N+1]`。它把所有标签加 1：旧 -1 变成 0，h 的初始第 j 个一基标签为 j。

相等字符交换来自上方 ih 与左方 iv 的标签；不等时 ih 取 max、iv 取 min。查询直接扫描该行的 `[b+1,c]`，统计 `ih[a][j]≤b`；源码先执行 `++b`，再写成 `<b`，与零基公式 `h<b` 完全等价。

它省掉全部查询的存储/分组与每问 Fenwick 的树跳转，预处理后可读一问答一问。代价是保存两张约百万格的整数表，以及最坏 `O(c-b)` 查询。编译目标包含 AVX2 等指令，查询比较连续且无跨项依赖，利于优化；本轮没有查看汇编来断言具体向量化指令。

### #398847：只保存每个前缀的 h 行

[源码](../../selected/prefix_substring_lcs/398847.cpp)实际 `main → run → PrefixSubstringLCS`，头部与尾部的自包含宏结构只是组织方式。构造时保存 `(M+1)×N` 个 int，每一新行复制上一行，再用单个局部 v 更新；不保留整张 iv。

`query(a,b,c)` 就是第 3 节的 `sum(h[a][j]<b)`。省掉第二张标签表，同时仍能在预处理后在线回答查询，代码中的大量通用模板没有改变这条热路径。

### #356663：16 位标签与局部 carry

[源码](../../selected/prefix_substring_lcs/356663.cpp)也保存全表，但用 `uint16_t dp[1005][1005]`，采用标签加 1 的约定。这里只存 `0..N` 的门槛标签，N≤1000，16 位足够；它并不是把某个巨大的 LCS 状态压得可能溢出。

更新时用 `lst` 保存向右的标签，从上一行逐格读取，不需要完整 iv 数组。查询用 `r[i]≤b`。它减少表内存，却使用普通关闭同步的标准流；快照 92 ms 不能简单证明 16 位比较比 32 位慢，I/O 与代码生成也不同。

三份共同复杂度是 `O(MN+Σ(c-b))`，最坏 `O(MN+QN)`，空间 `O(MN)`。在 N 仅 1000 时，简单连续扫描可能比树查询更便宜，但这依赖查询分布和机器常数，不能把一次排名当作普遍结论。

## 7. 两份离线 Fenwick 实现

### #109670：与上游同公式，复用分组和树缓冲

[源码](../../selected/prefix_substring_lcs/109670.cpp)读完所有查询，用紧凑整数编号存入 `ending_s`；每推进一行，把对应查询分到 `ending_t[c-1]`，扫描后立即清空桶。

Fenwick 对象在外面建一次，每行结束 `reset()` 清零复用。与上游的查询指针分组相比，整数编号通常更紧凑；复用 ending_t 和树避免每行重新建立这些容器。实际仍执行 `c-b-cnt+f.query(b)`，算法阶没有变化。

### #227569：相同离线组织，泛型 Fenwick 每行重建

[源码](../../selected/prefix_substring_lcs/227569.cpp)同样用 `phuS/phuT` 存查询编号，单条 x 数组更新阈值，按 c 扫描 Fenwick 并最后按原顺序输出。

它的 Fenwick 带 Monoid 接口，每行结束以 `ft=FenwickTree(...m)` 重新构造，区别于 #109670 对已有数组直接 fill/reset。I/O 为自定义 Scanner/Printer。泛型树里定义的其他区间、查找操作未被本题调用。

两份仍为 `O(MN log N+Q log N)`，查询存储 `O(Q)`。相同离线公式不意味着源文件相同，也不能把快照差异只分配给一处 reset。

## 9. 误区与验证设计

| 易错点 | 应明确的事实 |
| --- | --- |
| 把 LCS 当连续子串 | 此题是子序列，不等时取 max，不清零 |
| 区间答案等于两个前缀答案之差 | 匹配位置可以重选，`a` 对 `aa` 是反例 |
| h[j] 是 LCS 长度 | 它是左端点门槛，允许 -1 |
| 相等字符也做 max/min | 相等应交换两个标签，来自 DP 的对角 +1 |
| 零基 `<b` 与一基 `≤b` 互相矛盾 | 标签和列下标都加了 1 |
| 按顺序输出就禁止离线处理 | 本题查询不依赖答案，可以重排计算后还原顺序 |
| O(QN) 一定比 O(QlogN) 实测慢 | N≤1000，连续扫描与间接树访问的常数不同 |

本轮用普通 LCS DP 独立核对主例，并穷举长度 1～3 的二元字符串、所有合法 `(a,b,c)`，验证阈值更新与统计公式；这是数学小例检查，不是性能 benchmark。

后续性能比较应记录区间平均长度、a 的分布、空查询占比、预处理/读写/查询各段时间。固定 I/O 后对比扫描与 Fenwick，再比较标签宽度和复用方式；只看大 O 或整体 37～92 ms 无法拆分每项收益。
