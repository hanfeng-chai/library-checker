# Aho–Corasick：从前缀树、最长后缀到五份快解的存储选择

这题只给一组单词，要输出前缀树及每个节点的 suffix link；没有另一段文本需要匹配，也不要求出现次数。先理解节点代表哪个字符串、失败时应保留哪个后缀，再看数组和位掩码，就能读懂这些快解减少的工作。

## 阅读导航

- 第 1 节手工建树，给出完整编号、父节点、失败链接与终点输出。
- 第 2～3 节从枚举后缀的朴素办法，推导 BFS 构建与上游的完整转移表。
- 第 4 节解释直接位置表、位掩码与原位覆盖，和各份源码对应。
- 第 5 节专门区分节点数 `M` 与输入总长 `L`，给出失败链追溯的摊还证明。
- 后半部分保留五份源码逐一复核、排名快照、误区和实验边界。

教学伪代码说明算法，不是原提交逐行转写。真实函数名和未执行的辅助函数在源码复核部分单列。

## 1. 题意：每一个不同前缀对应一个节点

前缀是从字符串开头取一段，例如 `she` 的前缀为 `""`、`s`、`sh`、`she`。把所有输入串的不同前缀各建一个节点，从前缀 `u` 向 `u+c` 连一条字符 `c` 的边，得到 Trie，也称前缀树。根节点代表空串。

题目要求三类输出：节点总数；每个非根节点的父节点与 suffix link；每个输入串到达的终点。所有字符为小写英文字母，输入总长 `L≤10^6`，节点总数 `M≤L+1`，字母表大小固定为 `σ=26`。

### 1.1 编号顺序不是字典序，也不是 BFS 顺序

按输入顺序插入单词，在一个串里从左往右走，遇到此前没有的前缀才分配下一个编号。这正好实现题面“最早的 `(输入串编号,前缀长度)`”排序。

取输入：

```text
5
he
she
his
hers
she
```

插入过程为：

| 输入串 | 新节点 | 终点 |
| --- | --- | ---: |
| `he` | `1=h`、`2=he` | 2 |
| `she` | `3=s`、`4=sh`、`5=she` | 5 |
| `his` | 复用 `h`，新建 `6=hi`、`7=his` | 7 |
| `hers` | 复用 `h,he`，新建 `8=her`、`9=hers` | 9 |
| `she` | 全部复用 | 5 |

树结构可以直接画成：

```text
0:空串
├─h→ 1:h
│     ├─e→ 2:he
│     │     └─r→ 8:her
│     │           └─s→ 9:hers
│     └─i→ 6:hi
│           └─s→ 7:his
└─s→ 3:s
      └─h→ 4:sh
            └─e→ 5:she
```

节点 `2` 深度为 2，节点 `3` 深度却是 1，所以按节点编号处理不等于按深度处理。重复输入没有新节点，但终点数组仍须保留第二次的 `5`。

### 1.2 父节点和 suffix link 是两种不同的“删字符”

父节点删掉**最后一个字符**：`parent(she)=sh`。

Suffix link 找的是“所有真后缀中仍是某个前缀的最长者”。真后缀必须比原串短，可以是空串：`she` 的候选是 `he,e,""`，其中 `he` 已在 Trie 中，所以 `fail(she)=he`。

完整结果为：

| 节点 | 代表字符串 | 父节点 | 最长合法真后缀 | suffix link |
| ---: | --- | ---: | --- | ---: |
| 0 | 空串 | 不输出 | 根的内部约定 | 不输出 |
| 1 | `h` | 0 | 空串 | 0 |
| 2 | `he` | 1 | 空串，`e` 不在前缀集合 | 0 |
| 3 | `s` | 0 | 空串 | 0 |
| 4 | `sh` | 3 | `h` | 1 |
| 5 | `she` | 4 | `he` | 2 |
| 6 | `hi` | 1 | 空串 | 0 |
| 7 | `his` | 6 | `s` | 3 |
| 8 | `her` | 2 | 空串 | 0 |
| 9 | `hers` | 8 | `s` | 3 |

`h` 不是完整输入单词，却仍是 `sh` 的合法链接目标。题目查的是**所有前缀节点**，不是只查单词终点。

该例完整输出为：

```text
10
0 0
1 0
0 0
3 1
4 2
1 0
6 3
2 0
8 3
2 5 7 9 5
```

## 2. 从朴素枚举后缀，到复用已知的链接

最直接的教学算法是：对每个节点代表的字符串，依次删除开头 1、2、3…个字符，查询剩余后缀是否在前缀集合中，第一次成功就是答案。

`she` 只试一次 `he` 就成功；`aaaaac` 则可能依次试 `aaaac,aaac,aac,ac,c,""`。每个节点都重新构造这些字符串、从根查询，会反复扫描相同字符。若一个深度 `d` 节点尝试 `d` 个后缀，每次又复制或查询 `O(d)` 字符，该直接实现单节点可花 `O(d²)`。

### 2.1 父节点的失败链接给出了候选顺序

设真实 Trie 边为 `v --c--> w`，也就是 `str(w)=str(v)+c`。`w` 的合法真后缀应从 `v` 的真后缀接上 `c` 得到。因此先试 `fail(v)` 有没有字符 `c` 的真实边；没有就试 `fail(fail(v))`，直到找到或回根。

```text
教学伪代码：仅保存真实边
根的每个直接孩子 w:
    fail[w] = 0
    入队 w
while 队列非空:
    v = 出队
    for 每条真实边 (v,c,w):
        f = fail[v]
        while f != 0 且 f 没有字符 c 的边:
            f = fail[f]
        fail[w] = f 的字符 c 孩子（若没有则为根）
        入队 w
```

根孩子必须单独处理。若直接拿根自己的字符边当根孩子的失败链接，会让它链接到自己，违背“真后缀更短”的条件。

### 2.2 跟着例子构建一次

根孩子 `h,s` 的链接先设为 0。处理 `s --h--> sh` 时，候选是根，根有 `h` 边，所以 `fail(sh)=h`。处理 `sh --e--> she` 时，候选是 `fail(sh)=h`，`h` 有 `e` 边，故 `fail(she)=he`。处理 `hi --s--> his` 时，`fail(hi)=0`，根有 `s` 边，得到 `fail(his)=s`。

以单词 `aaaaac` 为另一个小例：处理最后的 `c` 边时，从 `aaaa` 开始尝试，沿 `aaa,aa,a,空串` 退回；都没有 `c` 边，答案为根。源码没有复制这些后缀，只移动节点编号。

### 2.3 为什么按 BFS，而不是节点编号或任意 DFS

`fail(v)` 的深度严格小于 `v`。按深度从小到大处理时，当前边要用到的较浅节点都已建立链接，根也已准备好。

主例的一种 BFS 次序是 `0,1,3,2,6,4,8,7,5,9`；它与首次插入的编号顺序不同。若后输入单词新建了某个很浅节点，早创建的深节点失败链接可能正要指向它，不能简单假设“目标编号更小”。

## 3. 上游如何用完整转移表消除反复追链

定义 `δ(v,c)`：从状态 `v` 读入字符 `c` 后，保留的最长、仍在 Trie 中的后缀。若有真实孩子就走过去，否则沿失败链接找；根仍找不到就留在根。于是

```text
fail[w] = δ(fail[v], c)       对非根父节点的真实边 v --c--> w
```

这里的 `δ` 是方便构建 suffix link 的中间结果。本题最终不要求输出它，也不会用它去扫描另一段文本。

### 3.1 `ch` 与 `nxt` 的区别

上游每节点有两行 26 个整数：`ch[c]` 只表示真实 Trie 边，`nxt[c]` 表示补全后的 `δ(v,c)`。缺失边只会在 `nxt` 里变成失败转移，不能把它当作真实孩子再次入队。

实际 `calc_suffix_link` 先把根的 `nxt` 全设为 0。BFS 处理非根节点 `v` 时，复制 `nxt[fail[v]]` 到 `nxt[v]`；随后遍历真实孩子，**先**从继承的这一格取孩子的 fail，**再**把这一格改为真实孩子编号。

```text
上游逻辑的教学摘要
nxt[root][所有字符] = root
根入队
while 队列非空:
    v = 出队
    if v != root: nxt[v] = nxt[fail[v]]
    for c = a .. z:
        if ch[v][c] 存在:
            w = ch[v][c]
            fail[w] = nxt[v][c]   // 此时还是继承来的转移
            nxt[v][c] = w         // 再覆盖为真实边
            入队 w
```

### 3.2 手算 `sh` 的转移行

主例中 `fail(sh)=h`，因此先继承 `h` 的行：

| 字符 | 从 `h` 继承的目标 | `sh` 是否有真实边 | `sh` 最终转移 |
| --- | --- | --- | --- |
| `e` | `he`（2） | 有，指向 `she`（5） | 5，同时先得到 `fail(she)=2` |
| `i` | `hi`（6） | 无 | 6 |
| `s` | `s`（3） | 无 | 3 |
| `z` | 根（0） | 无 | 0 |

`δ(sh,i)=hi` 的含义是读完 `shi` 后保留后缀 `hi`。`hi` 不是 `sh` 的真实孩子，所以它不会出现在 Trie 的父子输出里。

### 3.3 上游为此付出的成本

按 32 位 `int` 算，两份转移行共 `2×26×4=208` 字节，再加父节点与 suffix link 约为每节点 216 字节，未计向量容量、BFS、终点和输入输出存储。

初始化、复制和扫描每行都涉及 26 个槽，构链 `O(σM)`，加输入处理为 `O(L+σM)`，空间 `O(σM+N)`。固定 `σ=26` 时整体仍是线性级别，但“一条真实边的节点也分配和处理整行”正是快解可以减少的常数工作。

## 4. 三种存边方式：查字符与存转移可以分开设计

### 4.1 直接位置表：26 个字节指向紧凑边数组

#307744 用 `to[v][c]` 记录字符 `c` 在真实边列表里的位置，一个节点最多 26 条边，所以这个位置可以放进一字节。查到位置后，再从列表取真正的孩子编号。

假设一个教学节点依次插入 `f→30,a→12,c→7`：

```text
紧凑边列表：[f→30, a→12, c→7]
位置表：to[f]=0, to[a]=1, to[c]=2，其余=-1
查 c：先得到位置 2，再读列表[2]，得到孩子 7
```

列表按插入顺序追加，不必按字符排序。源码还把边装成 `(child_id<<8)|char_id`，高位是节点，低 8 位是字符。它减少空的整数槽，同时保持每次字符查询为常数时间。

#389965 采用相似的位置表，却为真实边列表也预留完整的 26 个整数槽。因此“只遍历真实边”不代表“只为真实边分配空间”。

### 4.2 位掩码 + `popcount`：只保留有边的字符

#307580 与 Rust #373052 用 26 位掩码和按字符顺序排列的孩子数组。教学节点有 `a,c,f` 三条边，掩码为二进制 `100101`，孩子数组为 `[12,7,30]`，按字符排，不要求孩子编号大小有序。

字符 `c` 编号为 2：先测试第 2 位存在，再数它前面的置位数：

```text
mask & ((1<<2)-1) = 100101 & 000011 = 000001
popcount(...) = 1
孩子在 child[1]，值为 7
```

查 `f` 时，低五位有 `a,c` 两个置位，索引就是 2。新插入 `b→99`，它前面只有 `a`，所以把 `99` 插入数组位置 1，得到 `[12,99,7,30]` 并置上 `b` 位。

插入数组会移动后面的元素，但每节点最多 26 条边，固定字母表下移动量受常数限制。遍历则重复取最低置位的位置，再用 `mask &= mask-1` 清掉它，只访问真实边；只有 `mask!=0` 时才取最低置位。

### 4.3 一份完整表原位补全：覆盖之前先保存孩子

#380150 保留 26 整数转移行，再用一个 mask 记下哪些是原始孩子。构建时按 mask 读出真实孩子和字符，暂存到局部数组；计算孩子 fail；复制失败状态整行；再把真实孩子覆盖回去。

这样最终 `nxt` 同时承担原来的 `ch` 和完成后的 `nxt`，省掉第二份 26 整数表。mask 不能省，因为复制之后无法仅凭非零转移判断哪些是真实边。例如上面的 `sh→hi` 仅是补全转移，如果把它再次当孩子入队，就破坏了树结构与父编号。

## 5. 复杂度：单条失败链很长，不等于总输入上的平方时间

设 `M` 为不同前缀节点数，`L` 为所有输入串长度之和。多个串共享前缀、重复输入时，`L` 可能远大于 `M`。分析中必须说明用哪个参数。

稀疏实现单次查字符为 `O(1)`，一条边可能沿失败链退很多次。只对每条边粗暴使用 `O(depth)` 再相加，可以写出 `O(Σdepth)⊆O(M²)` 的宽松界，但这忽略了**本题给出了覆盖全部 Trie 边的输入串，总长度为 L**。

### 5.1 沿一条输入路径做摊还

令 `h(v)=depth(fail(v))`，根记 `h(0)=0`。对真实边 `v --c--> w`，设构建时实际回退次数为非负数 `t(w)`。一次失败跳转至少减少一层深度，最后成功沿字符边最多增加一层，因此

```text
t(w) ≤ h(v) - h(w) + 1
```

若最终在根也找不到字符，答案深度是零，同一不等式仍成立；使用 `-1` 根哨兵的写法把最后一次哨兵退回也计入，右侧的 `+1` 仍足够。根的直接孩子按特判设 fail=0，不做这段追溯，也满足不等式。

沿一条长度为 `k` 的输入串路径求和，相邻项的 `h` 抵消：

```text
Σ t(w) ≤ k + h(root) - h(terminal) ≤ k
```

这说明某条边虽然可以退很多次，沿同一个完整输入路径的总回退不超过路径长度。

### 5.2 从各输入路径得到全树上界

每条 Trie 边至少属于一个输入串路径，且 `t(w)≥0`。把所有输入串路径上的回退次数相加，会重复计算共享边，因而只会更大：

```text
全树每条边只算一次的回退总数
≤ 所有输入串路径的回退总数
≤ 所有输入串长度之和 L
```

所以本题固定 26 字母、常数时间查边的稀疏追链构建，可按 `L` 给出 `O(L)` 摊还界；插入和读入同样 `O(L)`，另加输出及节点初始化。它不保证**每条边**都只走一步，也没有证明任意独立查询都能最坏 `O(1)`。

| 路线 | 主要构建工作 | 存储特点 |
| --- | --- | --- |
| 上游双表补全 | `O(L+σM)`，每行扫描/复制 `σ` 个槽 | 两份完整表 |
| 直接位置或 mask 的稀疏追链 | 按输入总长可得 `O(L)` 摊还；单边可长链 | 真实边 + 查询索引，省缺失转移 |
| #380150 单表补全 | `O(L+σM)` | 一份完整表 + mask |

这里忽略了输出整数转换的字符成本，并把固定上限静态数组初始化作为实现额外成本单列。若节点编号变长，完整端到端时间还要计算实际输出字节数。快解的优势应解释为少存、少复制许多空槽及不同的访存行为，不能简单说它从平方算法变成了线性算法。

## 7. 上游真实入口与共同不变量

插入任一串时，从根 0 沿原有 Trie 边走；遇到不存在的边才分配新节点。父子关系由真实边确定，可以在插入时记录父节点，也可以像 #307580 那样在 BFS 枚举真实边时记录。因此每个节点编号仅取决于第一次遇到对应前缀的时刻，重复串、共享前缀都复用已有节点；终点数组仍逐输入串保留。设最终节点数 `M≤L+1`，小写字母表大小 `σ=26`。

对 Trie 边 `v --c--> w`，失败链接满足 `s_w = δ(s_v,c)`，其中 `δ` 从 `s_v` 开始沿 suffix link 向上，直到找到一条字符 `c` 的 Trie 边，找不到则回根。`s_v` 的串严格短于 `v`，因此按 Trie 的广度优先顺序构造时，处理 `w` 之前需要的较短节点链接都已求出。根的直接孩子链接为 0。这里的 suffix link 可以指向**任何前缀节点**，不要求该节点是一个完整输入串的终点；五份代码都遵守这一点。

[upstream](../../../upstream/string/aho_corasick/sol/correct.cpp)的每个节点同时存 `ch[26]`（真实 Trie 边）和 `nxt[26]`（补全的自动机转移），再存 `parent`、`suffix_link`。BFS 处理节点 `v` 时，先从 `s_v` 复制完整 `nxt` 行，再逐字符把真实 Trie 边 `v --c--> w` 写回，并令 `s_w` 取复制后的 `nxt[v][c]`。处理过的行满足 `nxt[v][c]=δ(v,c)`，所以每条失败转移可 O(1) 读取。代价是每节点两份 26 整数数组，约 `2×26×4=208` B/节点（未计容器和其他字段），建链时间 `O(σM)`、空间 `O(σM)`。其通用结构还有 `words`、`BFS` 和未被本题 `solve` 调用的 `calc_count()`；这里不应将计数工作算作实际执行。

另一条路线只保存真实边并逐级追溯失败链接。单边可花 `O(depth(v))`，但第 5 节按输入总长 `L` 的势能求和证明总追溯为 `O(L)`。它省去了每节点补全 26 个转移；不能把仅按节点数写出的宽松 `O(M²)` 界，误当成本题总输入上的紧界。

## 8. #307744：字符位置表 + 紧凑真实边，当前第一

`solve()` 先把全局 `to[M][26]` 填为 `-1`，然后逐串调用 `add(s)`。每个节点用 `basic_string<int> tr[v]` 仅保存实际存在的孩子边；元素把字符编号放在低 8 位、孩子节点编号放在高位。`to[v][c]` 存的是这条边在 `tr[v]` 中的**位置**，不是孩子编号，因而只需一个 `char`；`get_to(v,c)` 才从压缩元素取出目标节点。插入新边时将其追加到 `tr[v]`，使已记录的位置始终有效；每个节点的边数最多 26。`par[sz]` 在新节点诞生时记录，串终点保存在局部 `vector<int> v` 中。

`build()` 以根为起点 BFS，仅迭代 `tr[v]` 中真正存在的边。对边 `v --c--> w`，先以 `link[v]` 作为候选，沿 `link[]` 追溯到可通过字符 `c` 的节点，再令 `link[w]` 为相应 Trie 孩子；根的孩子特判为 0。这里没有生成缺失边的完整自动机转移表，也没有执行匹配计数。`print()` 最后按编号输出 `par` 与 `link`，再输出插入阶段保存的终点。

这份实现与 upstream 的最大结构差别是用约 26 B/节点的 `char` 位置表加按实际度数分配的边列表，取代两份完整的 26 整数转移表。查边依然直接按字符下标取得位置，避免在每一级失败链上扫描邻接边；代价是每节点 `basic_string<int>` 对象、边列表容量及可能的动态分配，还有单条失败链上的多次访问。源码还打包了 `blazingio`：`cin`/`cout` 宏被替换成自定义映射或缓冲读写，不能把它当作普通 `iostream` 基准。路径上有 `checkpoint` 调用，是否真正输出计时由 `CP_ALGO_CHECKPOINT` 编译宏控制，它不是构链算法的一部分。102 ms 是整个提交的 OJ 时间，无法单独分离边布局与 I/O 的贡献。

## 9. #307580：位掩码定位孩子，约 26 种字符仍可紧凑存放

`main` 使用自制 `fastio::rd/wt`。每个 `node` 有 `mask`、按字符递增排列的 `vector<int> child` 和 `suffix_link`。对字符 `c`，先测 `mask >> c & 1`；存在时，其孩子下标为 `popcount(mask & ((1<<c)-1))`。新边以同一秩插入 `child`，保证掩码第 `k` 个置位字符对应 `child[k]`。单次 `vector::insert` 最多移动 26 项；在固定小字母表下是常数工作，不是按整个 Trie 大小移动。

所有串插完才分配 `que[p]` 与 `par[p]`。`que` 初始零元素就是根，`l=0,r=1` 开始 BFS；每处理节点 `x`，循环 `child`，用 `countr_zero(mask)` 逐个解出递增字符标签。对其孩子 `c`，从 `nds[x].suffix_link` 向上走到存在同字符边的节点；根的 `suffix_link=-1` 是哨兵，因此根孩子的链接设为 0。此时才写 `par[c]=x`，而不是在插入时写。输出使用插入时存好的 `pos[i]`。

相对 upstream，这里每节点只有一个 32 位掩码、一个孩子向量和链接字段，不保留 26 路完整转移；查找成本是位运算与 `popcount`，失败链仍可能走多级。与 #307744 相比，它不用 26 字节的直接位置表，节约了稀疏节点的空槽，却在每次查边时做秩计算，并在插入新字母时移动小向量。两份 OJ 时间差不能只归因于这些位运算，因为 I/O 库和内存分配方式也不同。

## 10. #373052：Rust `SmallSet` 的相同稀疏思路

`main` 用 `fast_io::stdin()` 读完整串，调用 `to_vec()` 保留所有输入单词，再把每字节减去 `b'a'`。`Builder::<26>::insert` 逐串走 Trie，只有缺边才建节点，并返回终点编号。`SmallSet<u32>` 用 `u32 mask` 和紧凑 `Vec<u32>` 存真实孩子；`get(c)` 通过比 `c` 小的置位数定位，`insert` 按这个位置插入，迭代器每次清最低置位位。其子节点顺序只是字符顺序，不会改变**首次插入时**分配的题目编号。

`Builder::build` 用 `VecDeque` BFS。它临时 `take` 当前节点以便借用 `nodes[link]`，逐条真实边从当前节点的 suffix link 向上追溯，直到找到对应字符边或根，再写孩子的 `link`，最后把当前节点放回。处理根时这个细节还承担了特判：根暂时被替换成空的默认节点，查根孩子的字符时找不到边，因而孩子链接自然设为 0；若不保留这一步而机械抄成普通查根边，可能得到指向自身的错误链接。对非根节点，失败目标严格更浅，因此不会需要刚被临时取走的当前节点。`AhoCorasick::trans` 定义了对已建自动机的按需失败链转移，但 `main` 不调用，建链也只用节点自身的稀疏 `trans(c)`；不能把这里说成预先补全转移或做文本查询。输出阶段读 `prefix()/suffix()`，终点来自插入时的 `v`。

相对 upstream，它把节点转移从两份 26 路数组缩为一个掩码与实际孩子。输入单词、终点数组、Trie 节点同时保留，会额外占 `O(L+N)`；其构造同样适用第 5 节按 `L` 的摊还分析。其 I/O 在普通文件上尝试 `mmap`，否则整份读入；输出用 256 KiB 缓冲。136 ms 包含 Rust 编译产物、输入复制与输出，不能仅按语言解释它与 C++ 的差异。

## 11. #389965：边的查找仍是标量，SIMD 辅助函数没有进入主路径

`main` 用 `fastio_init` 读输入：对普通文件尝试 `mmap`，否则读入内存；输出是 1 MiB 缓冲。`ac_add` 用 `to_node[v][c]` 直接定位 `tr_edges[v][edge_idx]`，其中每个边同样以低 8 位装字符、高位装孩子编号。和 #307744 不同，`tr_edges[MAXN][26]` 为**每个节点**预留 26 个 `int` 槽，即使该节点只存在一条边也占满静态行；另有 `to_node[MAXN][26]` 的字符位置表、父/失败链接、队列及 I/O 空间。这与其 162,660,352 B 的较高 OJ 内存读数相符，但该读数不等同于静态数组大小之和。

`ac_build` 从根 BFS，对每条真实边用 `link_node[v]` 开始逐级追溯，查找调用的是 `has_to` / `get_to`。文件里定义了 AVX2 的 `get_to_simd`，但它**没有调用点**；`#pragma GCC target` 和辅助函数的存在不代表失败边查找在实际执行中使用 SIMD。该版建链路线与 #307744 的核心不变量相同，单条边可能多级回退，而按输入总长 `L` 的总追溯界为线性；主要差异落在固定行边存储和独立 I/O 实现。

## 12. #380150：用一份 26 路数组原位补全自动机

`FastInput` 直接读取字符，`insert_string` 在 `nxt[v][c]==0` 时分配新节点并记录 `par`、`mask_node[v]`；`terminal_node[i]` 保存每个输入串的终点。此时 `nxt` 仍仅含真实 Trie 边，0 表示缺边。`main` 先把根的真实孩子入队，它们的 `link_node` 默认为根；随后按 BFS 处理每个非根节点。

处理节点 `v` 时，`f=link_node[v]` 的整行 `nxt[f]` 已补全。程序用 `mask_node[v]` 只枚举 `v` 的真实孩子，先保存这些边到局部 `child[26]`，并令每个孩子 `u` 的 `link_node[u]=nxt[f][c]`。然后 `memcpy(nxt[v],nxt[f],26*sizeof(uint))` 把缺失边补成失败转移，再用 `child[]` 恢复真实孩子。因而处理结束后 `nxt[v][c]=δ(v,c)` 对全部 26 字母成立，同时父节点、终点编号仍是原 Trie 的。这正是正确性关键：**先记录真实孩子，再覆盖整行，最后还原**；若直接遍历补全后的行，队列会误把失败转移当新边。

相对 upstream，#380150 复用同一份 `nxt[26]`，通过 `mask_node` 区分真实边与补全边，不需要再存一份 `ch[26]`；每节点约 104 B 的主转移行加一个 4 B 掩码，代价仍为 `O(26M)` 时间和空间。输出时并不再做匹配，补全表是为了让**后续建链**能 O(1) 查失败转移。源码还用 1 MiB 输入缓冲、8 MiB 输出缓冲和静态队列；143 ms 不能单独归因于稠密算法，尤其前五中它与 #389965 同为 143 ms 而内存布局与 I/O 均不同。

## 13. 可复用结论与比较边界

1. 当前第一名的关键设计是“`char` 直接位置表 + 实际存在的孩子边”，在每级 suffix 链查找时保持 O(1) 字符定位，却避免 upstream 的两份完整 26 路整型表。它选择了较轻的平均存储和按需追溯；不是新的匹配统计算法。
2. 位掩码路线用 `popcount` 将字符映射到紧凑孩子数组，适合 26 字母的小字母表。它减少空槽，但无法消除最坏情况下的多级 suffix 链追溯。Rust 和 C++ 两份实现共享这个结构思想，不能仅看语言或排名断言算法优劣。
3. 原位稠密补全路线的关键是不变量 `nxt[v][c]=δ(v,c)`，以及 `mask_node` 保留真实 Trie 边身份。它以 `O(26M)` 的可预期建链工作换取较高内存；比 upstream 少一整份 `ch[26]`，但仍对每个节点复制 26 个槽。
4. 这些时间是 OJ 对完整程序的总时间：输入解析、节点分配、失败链、输出约 `M+N` 个整数共同计时。没有逐阶段同机实验，也没有更广候选池的代码审阅，因此本文只给出源码机制和当前前五之间可核对的差异，不给“某家族最快”的全站结论。

## 14. 常见误区、检查方法与后续实验

| 容易混淆的概念 | 本题应保持的关系 |
| --- | --- |
| 节点编号与 BFS 顺序 | 编号来自首次插入，BFS 仅决定构链顺序 |
| 父节点与 suffix link | 父节点删末尾一字，suffix link 删若干开头字符 |
| 前缀节点与单词终点 | 链接可指向未单独作为输入的前缀，如 `sh→h` |
| 真实孩子与补全转移 | 只有真实孩子决定父节点、入 BFS 队列 |
| 查字符的位置与目标编号 | #307744 的一字节表保存边列表位置 |
| mask 索引与孩子编号排序 | child 按字符排序，节点编号仍按首次出现分配 |
| 单条失败链长与总复杂度 | 对本题输入路径求和可得 `O(L)` 摊还界 |
| 定义 SIMD 函数与实际调用 SIMD | #389965 的 `get_to_simd` 没有调用点 |
| 定义匹配接口与本题执行匹配 | 五份 main 都只构建并输出，不扫描额外文本 |
| 当前五个用户与全部算法族 | 样本不能证明某路线的全站最快提交 |

正确性检查可先用第 1 节小例同时验证节点编号、父节点、fail 和重复终点，再用 `a,aa,aaa` 验证一字符一层后缀，用 `aaaaac` 检查一次多级失败。也应测试后输入才出现浅前缀的情况，例如 `she,he`：先创建的 `sh` 需要链接到后创建的 `h`，说明不能依编号假设目标更早。

小规模可显式列出每个节点字符串的所有真后缀，用前缀集合查最长者，与优化实现逐项比较。额外不变量包括：非根 `depth(fail[v])<depth(v)`；每个节点沿 parent 回到根恰得到自己的标签；按输入单词走真实边会到达记录的终点；重复串终点相同。

性能实验应分别测输入/插入、分配/初始化、构链、输出，并记录节点数、总输入长度、每节点度数分布、总失败跳数和最长单次失败链。随机串、长共享前缀、很多重复串、短周期串和几乎单链的树会产生不同访存行为；题库已有 [short_period](../../../upstream/string/aho_corasick/gen/short_period.cpp)、[fibonacci](../../../upstream/string/aho_corasick/gen/fibonacci.cpp)、[almost_single](../../../upstream/string/aho_corasick/gen/almost_single.cpp) 等生成器可作为后续固定版本实验来源。

比较布局时应保持 I/O 和输入相同，一次替换一种边表示，记录构链时间与峰值内存；比较稀疏追链与稠密补全时同时报告 `L`、`M`，不能只报告节点数。此处是实验设计，本轮没有新增性能 benchmark 或 OJ 重测。
