# Eertree 回文树：从不同回文，到两个根、扩展边和后缀链接

回文树为每个**不同的非空回文内容**建立一个节点。相同回文出现在不同位置时复用节点；每读入一个新字符，维护当前前缀的最长回文后缀。它与 Manacher 按中心保存最大半径是不同的索引方式。

## 阅读导航

第 1 节手工建立完整输出，第 2～4 节解释朴素法、两种边和逐字符插入；第 5 节追踪上游实际开销；第 6～8 节比较五份源码的转移存储；最后是快照与验证。教学伪代码不代表任一提交逐行实现。

## 1. 题目究竟要输出什么

[题面](../../../upstream/string/eertree/task.md)给小写串，长度上限为 [1000000](../../../upstream/string/eertree/info.toml)。要求输出：

1. 不同非空回文的数量。
2. 每个回文节点的父节点与 suffix link。
3. 对原串的每个非空前缀，输出它的最长回文后缀节点。

非空节点按该回文**第一次出现的结束位置**编号。另有两个特殊节点：`ODD=-1`、`EVEN=0`。父节点表示去掉首尾字符后的内层回文；suffix link 表示最长的更短回文后缀。长度 1 的父节点是 ODD，没有非空真回文后缀时链接到 EVEN。

### 1.1 完整例子：`abbaabacb`

| 新字符位置 | 当前前缀 | 最长回文后缀 | 是否新建 | 返回节点 |
| ---: | --- | --- | --- | ---: |
| 0 | `a` | `a` | 新建 1 | 1 |
| 1 | `ab` | `b` | 新建 2 | 2 |
| 2 | `abb` | `bb` | 新建 3 | 3 |
| 3 | `abba` | `abba` | 新建 4 | 4 |
| 4 | `abbaa` | `aa` | 新建 5 | 5 |
| 5 | `abbaab` | `baab` | 新建 6 | 6 |
| 6 | `abbaaba` | `aba` | 新建 7 | 7 |
| 7 | `abbaabac` | `c` | 新建 8 | 8 |
| 8 | `abbaabacb` | `b` | 已有，复用 2 | 2 |

两种边要分别手算：

| 节点 | 回文 | 去首尾后的父节点 | 最长真回文后缀 | suffix link |
| ---: | --- | ---: | --- | ---: |
| 1 | `a` | -1（ODD） | 空 | 0 |
| 2 | `b` | -1 | 空 | 0 |
| 3 | `bb` | 0（EVEN） | `b` | 2 |
| 4 | `abba` | 3（`bb`） | `a` | 1 |
| 5 | `aa` | 0 | `a` | 1 |
| 6 | `baab` | 5（`aa`） | `b` | 2 |
| 7 | `aba` | 2（`b`） | `a` | 1 |
| 8 | `c` | -1 | 空 | 0 |

完整输出是：

```text
8
-1 0
-1 0
0 2
3 1
0 1
5 2
2 1
-1 0
1 2 3 4 5 6 7 8 2
```

`abba` 的父节点是 `bb`，后缀链接却是 `a`。二者都通向较短回文，但不能互换。最后再次出现 `b` 没有新建节点，也不会改变第一次出现顺序。

## 2. 朴素方法与节点数为什么只有线性

直接枚举所有区间、检查是否回文再按字符串去重，可有 `O(n²)` 个候选，每个检查或复制又可花 `O(n)`。即使先用 [Manacher](../enumerate_palindromes/analysis.md)快速判断回文，逐个枚举所有回文出现次数仍可能平方：全 `a` 有 `n(n+1)/2` 个回文区间。

但不同回文内容最多只有 n 个。原因是：追加一个字符后，新出现的回文必须是新前缀的后缀；其中只有最长者可能是新的。任何更短的回文后缀也是这个最长回文的前缀，因对称性已经在它的左边出现过，结束位置早于新字符。

因此每步至多新增一个回文节点。回文树利用这个性质，只维护不同内容，不为每次出现建立副本。

## 3. 两个特殊根让扩展公式统一

若已有回文 P，在两侧放同一个字符 c，得到 `cPc`，仍然是回文。定义转移

```text
next[P][c] = 表示 cPc 的节点
```

它就是父子树边：新节点父亲为 P，长度增加 2。偶回文从长度 0 的 EVEN 出发，例如 `b + 空 + b = bb`；奇回文需要一个形式长度为 -1 的 ODD，使加 2 后得到长度 1。

ODD 不是实际存在的负长度字符串，只是统一边界的哨兵。实现把新字符放在位置 i 后，判断候选后缀 v 能否被扩展的公式是：

```text
j = i - len[v] - 1
若 j>=0 且 S[j]==S[i]，则 v 可以在两侧加 S[i]
```

对 ODD，`len=-1`，恰好得到 `j=i`，一定匹配新字符本身。所以向 suffix link 回退最终总能停在一个可扩展候选，不用另写“所有候选都失败”的造单字符分支。

## 4. 追加一个字符时实际做什么

设 last 是旧前缀的最长回文后缀。新最长回文的中间部分一定是旧前缀的某个回文后缀，所以沿 last 的 suffix link 从长到短查找可扩展者。

```text
教学伪代码
追加 c 到文本末尾
x = 从 last 沿 suffix link 找到第一个可被 c 扩展的节点
若 next[x][c] 已存在：
    last = next[x][c]
否则：
    新建 v，len[v]=len[x]+2，parent[v]=x
    若 v 长度为 1：link[v]=EVEN
    否则：
        从 link[x] 开始，找下一个可被 c 扩展的节点 y
        link[v] = next[y][c]
    next[x][c]=v
    last=v
保存本前缀的 last
```

### 4.1 为什么计算新 link 时要从 `link[x]` 开始

从 x 自己开始会得到新节点 v 本身，不能作为“更短”的回文后缀。必须先退一条链接，再找可扩展的更短回文 y，取 `c y c`。

这个目标已经存在：它比新最长回文短，由第 2 节的一步至多一个新回文性质，已经在先前前缀出现过。因此可读取已有转移，不需要递归新建一串节点。

### 4.2 在例子中追加第 6 位 `a`

旧最长回文后缀是 `baab`，长度 4。尝试扩展时，左侧位置为 `6-4-1=1`，字符是 b，不能与新 a 配对。沿 link 到 `b`，长度 1，此时左侧位置为 4，字符 a，成功得到 `aba`。

新节点父亲是 `b`。为求它的 link，从 `link(b)=EVEN` 开始：位置 5 是 b，不匹配 a，再退 ODD，取得已有单字符 a。因此 `link(aba)=a`。

最后追加位置 8 的 b 时，退到 ODD 后发现其 b 转移已经是节点 2，直接复用即可。

### 4.3 在线性质与复杂度

构建只看已读前缀，可以逐字符在线完成；题目把节点总数放在输出开头，所以提交通常先保存各前缀 last，整串完成后统一输出。保存答案不等于构建算法需要未来字符。

普通追加式 eertree 的 suffix-link 查找具有摊还线性字符检查界，单次追加仍可能退很多级。直观地看，最长后缀长度每步最多增加 2，失败跳转会缩短候选，不能把每次都可能走长链当作每次都从最大深度重新开始。创建新 link 的查找也属于标准追加构建的摊还分析。

固定 26 字母、常数代价查询转移时，构建为 `O(n)`，节点数为 `O(n)`；若每次查边线性扫描最多 26 条，写出字母表因子就是 `O(26n)`，本题仍是线性级别。这里讨论只有追加的过程，不能将同一摊还结论直接用于反复删除、再添加的 deque 题。

## 5. 上游 `correct.cpp` 的真实开销

[上游源码](../../../upstream/string/eertree/sol/correct.cpp)内部编号为 0=ODD、1=EVEN，新节点从 2 起，输出统一减 1。每个节点保存 `TO[26]`、link、length 与首次出现区间。

构造函数从左到右执行第 4 节两段 suffix-link 查找，创建节点时将 26 个转移槽填为 -1。`path` 在每步之前保存旧 last，最后再补最后一个，因此 solve 会复制 path、删掉第一项、再转换编号。

父节点没有单独存储。构造完成后，solve 扫描**每个节点的全部 26 个 TO 槽**，对真实转移 `u→v` 写 `par[v]=u`。这是额外 `O(26P)` 扫描，P 为不同回文数。

按 32 位整数算，光转移就约 `104P` 字节，再加其他字段、向量容量和路径数组。上游还定义了把出现次数沿 link 累加的 `count()`，但 main 没有调用；不能把计数传播算进本题时间。

## 6. 前两份：稀疏转移与直接保存父节点

### #394036：按随机字母顺序组织同一父节点的孩子

[源码](../../selected/eertree/394036.cpp)的 `main → eertree<26>::extend` 使用 `hashed_child_pool`。每个回文节点既保存回文信息，也保存 `symbol,left,right`，用于成为父节点孩子集合中的一个二叉搜索树节点；父亲用 `children` 记录这棵小树的根。

查找时先检查字符本身是否相等，再按 `splitmix64(symbol+seed)` 的顺序向左右走。它不是一张满 26 路表，也不是带旋转的平衡树；随机种子改变字符排序，但命中依据始终是实际字符，哈希碰撞不会被直接当作相等。固定字母表下，最坏也只有 26 个孩子可查。

节点集中在一个预先 reserve 的 vector 池里，省掉每节点 26 槽初始化和满行扫描；创建时直接存 parent，输出时直接取值。它仍维护文本数组、last、suffix link，并更新 `hits/suffix_depth`，虽然题目不要求这两个统计字段的输出。

种子来自时钟和 `random_device`，会影响小树形状和复现实验，但不改变合法字符串的数学答案。I/O 是自定义 reader/writer。68 ms 是整份程序的快照，不是对随机孩子树的一次独立计时。

### #400577：紧凑链表，两个根直接查表

[源码](../../selected/eertree/400577.cpp)的 `add_letter` 使用 `stack_union` 集中存边，将孩子编号放在高位、字符放在低 8 位。普通节点沿短边链逐个查字符；两个访问很频繁的根额外有 `root_to[2][256]`，可以直接定位，避免每次在根的孩子中扫描。

内层 get_link 通过带哨兵的字符数组比较 `s[n-1]` 与 `s[n-len[v]-2]`，减少边界处理。len/link/par 分开存入连续数组，并按最大可能节点数预分配。创建时记 par，所以也省上游的末尾 26 槽扫描。

内部根顺序与上游相反：0=EVEN、1=ODD，`yosupo()` 专门转换，不能一律对内部编号减 1。主路径的 `cin/cout` 被 blazingio 替换，模板里的其他设施不代表本题额外算法。

## 7. 两份稠密转移与一份最直接的稀疏实现

### #343633：静态 26 整数行

[源码](../../selected/eertree/343633.cpp)直接在 `solve` 中构建，使用静态 `nxt[][26]`、len/link/par 与前缀答案数组。每次新建节点清零一行，字符转移常数时间，父节点即时记录。内部 1=ODD、2=EVEN，输出减 2。

它避免节点 vector 扩容与末尾反推父亲的扫描，但仍为每节点预留、初始化完整转移行。输出前还把 `suf_ans` 复制到一个 vector，不能笼统说“完全没有结果复制”。快照内存约 146.8 MB。

### #270261：节点指针指向完整孩子行

[源码](../../selected/eertree/270261.cpp)每个节点有 `node* child[26]`、parent/link 指针与首次出现区间。`nodes.reserve(n+2)` 除减少扩容外，也保证后续插入时已有节点指针不因重分配失效，这是正确性条件。

它直接存父指针，跳过上游的反推扫描；但在 64 位指针平台，仅 26 个孩子指针就需要 208 字节，是 26 个 32 位编号的两倍，尚未计其他字段。快照约 271.3 MB 与这种更重的节点布局一致，不能只凭它的时间说指针查找本身更慢。

### #377437：分数组边链，容易对应教科书伪代码

[源码](../../selected/eertree/377437.cpp)使用 len/link/parent/head 向量，以及 edge_to/edge_next/edge_ch 三条真实边数组。`find_edge` 线性扫一个节点的孩子，`can_extend` 显式检查左下标非负，两个根与上游顺序相同。

它省掉满 26 路转移空间，保留较直观的分支和向量增大方式，使用关闭同步的普通 `cin/cout`。每个节点至多 26 条边，查找不随整棵树规模增长；仍需区分“少存空槽”和“每次查边多比较几个字符”的取舍。

## 9. 误区、边界与验证设计

| 易错点 | 应检查的事实 |
| --- | --- |
| 每个回文出现一次就建节点 | 节点按不同内容复用，一步至多新建一个 |
| parent 就是 suffix link | parent 去两端，link 取最长更短回文后缀 |
| ODD 代表某个实际负长度串 | 它是使单字符扩展统一的形式哨兵 |
| 根编号可以直接照搬 | 三种内部编号在这些提交中并存，输出需显式映射 |
| 有 count 接口就传播了出现次数 | 上游 main 未调用 count |
| 稀疏孩子查询会扫所有节点 | 只扫当前父亲的孩子，最多 26 个 |
| 指针 vector 扩容只是性能问题 | 原始指针可能失效，#270261 的 reserve 很关键 |

小串可枚举所有回文内容，按第一次结束位置编号，独立核对 parent、link 和每前缀最长后缀。建议包含 `a`、`aa`、`aaa`、本页 `abbaabacb`、重复回文但不新建节点的前缀，以及小字母表长周期串。

未来实验应分别记录不同节点数、真实边数、根查询占比、失败跳数、分配量、输入输出时间和峰值内存；固定同一 I/O 后比较边布局，才能测出稀疏结构和根缓存的作用。本轮只做源码路径、完整哈希、手算及链接检查，没有性能 benchmark 或 OJ/API 调用。
