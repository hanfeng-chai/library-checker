# 通配符匹配：从逐位置检查，到精确失配卷积与随机指纹

本题的 `*` 只匹配**一个任意字符**，不会吞掉任意长度文本。文本和模式两边都可能有 `*`，需要输出每个完整对齐位置是否匹配。上游把所有对齐的非负失配分数用卷积一次算出；快解通过更短的变换和指纹减少卷积组数，但判定保证也不同。

## 阅读导航

第 1～3 节完整手算匹配与三卷积公式，第 4 节解释上游三模精确恢复和单模陷阱，第 5 节解释为什么可以缩短变换，第 6～8 节追踪五份快解的真正判定与 I/O，第 9～10 节保留快照、误区和验证方法。

FFT/NTT 的基本数据流可参阅[模卷积](../convolution_mod/analysis.md)，CRT 与浮点舍入可参阅[任意模卷积](../convolution_mod_1000000007/analysis.md)。下面仍会自足地推导本题公式。

## 1. 题意和所有对齐的手算

[题面](../../../upstream/string/wildcard_pattern_matching/task.md)给文本 S 和模式 T，`1≤m=|T|≤n=|S|≤524288`。一个位置相配，当且仅当字符相同，或任一边是 `*`。每个对齐的 m 个位置都相配才输出 1。

取 `S=a*babb`、`T=a*b`：

| 起点 i | 文本窗口 | 三个位置的检查 | 输出 |
| ---: | --- | --- | ---: |
| 0 | `a*b` | a=a，星号可配，b=b | 1 |
| 1 | `*ba` | 星号可配，模式星号可配，a≠b | 0 |
| 2 | `bab` | b≠a，模式星号可配，b=b | 0 |
| 3 | `abb` | a=a，模式星号可配，b=b | 1 |

输出是连续的二进制字符 `1001`，长度恰为 `n-m+1`。

朴素算法枚举起点，再逐字符检查，最坏 `O((n-m+1)m)`。只要遇到一个普通字符失配即可提前结束，但全匹配或星号很多时会反复读相同区域，不能依赖随机数据上很快失败。

## 2. 用非负分数表达“这个位置失配”

将 `*` 编码为 0，`a..z` 编码为 `1..26`。两个编码 x,y 的分数定义为

```text
d(x,y) = x*y*(x-y)^2
```

它非负，且恰在三种合法情况中为零：x=0、y=0、x=y。若双方都是不同的普通字符，分数严格为正。

因此对齐 i 的总分

```text
D[i] = Σ(j=0..m-1) S[i+j]*T[j]*(S[i+j]-T[j])²
```

为零，当且仅当每个位置都相配。这里非负性很关键，不同失配项不会在整数中正负抵消。

主例编码为 S=`[1,0,2,1,2,2]`、T=`[1,0,2]`：两个错误对齐分别有一个 `(1,2)` 或 `(2,1)`，分数为 `1×2×1²=2`。所以总分为 `[0,2,2,0]`，零的位置正是 `1001`。

## 3. 为什么能由三次卷积得到全部对齐

展开分数：

```text
x*y*(x-y)² = x³*y - 2*x²*y² + x*y³
```

每项都是“文本位置的某个函数 × 模式位置的某个函数”，可以作为相关运算。把模式反转，就变成普通卷积：令 `rev(T)[k]=T[m-1-k]`，则

```text
conv(A,rev(B))[i+m-1] = Σ(j=0..m-1) A[i+j]*B[j]
```

因此计算三条卷积：

| 卷积 | 提取的贡献 |
| --- | --- |
| `S³ * reverse(T)` | `Σ x³y` |
| `S² * reverse(T²)` | `Σ x²y²`，乘 -2 |
| `S * reverse(T³)` | `Σ xy³` |

其中幂是每个系数分别取幂，不是把整个多项式先自乘。

### 3.1 主例的三个中间结果

只列需要的卷积下标 `m-1..n-1`，它们对应四个对齐：

| 对齐 i | `Σxy³` | `Σx²y²` | `Σx³y` | 相加 `第一列-2第二列+第三列` |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 17 | 17 | 17 | 0 |
| 1 | 8 | 4 | 2 | 2 |
| 2 | 18 | 20 | 24 | 2 |
| 3 | 17 | 17 | 17 | 0 |

例如 i=1 窗口 `[0,2,1]` 对 `[1,0,2]`，只有最后一对同时非零，三项为 `1×2³=8`、`1²×2²=4`、`1³×2=2`，总计 2。

```text
教学伪代码
把 * 映射成 0，其余映射 1..26
C0 = 整数卷积(S, reverse(T³))
C1 = 整数卷积(S², reverse(T²))
C2 = 整数卷积(S³, reverse(T))
for i = 0 .. n-m:
    score = C0[i+m-1]-2*C1[i+m-1]+C2[i+m-1]
    输出 score==0
```

## 4. 上游 `correct.cpp` 为什么使用精确整数卷积

[上游源码](../../../upstream/string/wildcard_pattern_matching/sol/correct.cpp)的 `make_vectors` 建立一、二、三次幂数组，main 反转 T，按三项调用 `atcoder::convolution_ll`，再以 64 位整数累加分数。

### 4.1 64 位整数足够，但一个 NTT 模数不够

单项卷积系数至多 `m×26^4≤239587033088`，可以放进 64 位。失配分数的一个粗界是 `m×26²×25²≤221511680000`，也远低于 64 位上限，却可能远大于 `998244353`。

若只计算 `D[i] mod q`，余数为零只说明 D 是 q 的倍数，不能证明 D=0。非负整数证明在取模后失去了“非零和不可能抵消为零”的保证。

[配置](../../../upstream/string/wildcard_pattern_matching/info.toml)明确把单模版本 `mod998244353.cpp` 标为预期 WA；[针对生成器](../../../upstream/string/wildcard_pattern_matching/gen/hack_998244353.cpp)构造的就是非零总分模 `998244353` 为零的情况。这是实际题库边界，不是只在超出约束时才发生的问题。

### 4.2 三模恢复与实际变换数

`convolution_ll` 内部使用 `754974721`、`167772161`、`469762049` 三个 NTT 素数，分别卷积再 CRT 恢复整数结果。三者乘积远大于本题系数界；最终系数又确实在有符号 64 位范围内，所以整数恢复具有确定性。

常规完整变换长度为 `L=bit_ceil(n+m-1)≤2^20`。一次整数卷积有三组“两个正 NTT、一个逆 NTT”；三项相加，大输入通常共 **18 次正变换、9 次逆变换**，再加三次 CRT 重建。

当较短数组长度 `≤60` 时，所含单模卷积走 ACL 的朴素分支，不执行这些大 NTT。源码函数虽叫 `convolution_fft`，这里实际是整数模数域的 NTT，并非浮点 FFT。

总时间为常数较大的 `O(L log L)`，空间 `O(L+n+m)`。上游同时保留六条幂数组，逐次返回完整卷积结果，而最终只读取中间的 `n-m+1` 项。

## 5. 只需有效对齐，所以可以把变换缩短

完整线性卷积会有 `n+m-1` 项，但本题只要下标 `[m-1,n-1]`。如果用长度 `K≥n` 的循环卷积，高位 `K..n+m-2` 会折回到 `0..n+m-2-K`，后者至多为 `m-2`，恰好落在不用的低段。

例如 n=8、m=5，所需下标是 4～7；长度 8 的循环卷积把高位 8～11 折回 0～3，完全不影响所需结果。于是可以取 `K=bit_ceil(n)`，不必补到 `bit_ceil(n+m-1)`。

另一种写法把模式第 j 项放在循环下标 `-j mod K`，就直接在下标 i 读相关结果。两种布局只是输出坐标不同，仍需确保 `0≤i≤n-m`，不能把受折回污染的其他位置当完整线性卷积使用。

快解的复数打包内核可能带相位、将前后半段装进实部和虚部，不等同于直接套一个普通 FFT。共同节省来自“只需要有效对齐的那段”，打包布局与内核必须配套。

## 6. 三份浮点指纹：相等贡献 1，星号贡献 0

这些提交不再求非负失配分数，而是随机给字符分配数值，使合法对齐得到整数。它们通常只需两个正 FFT、一个逆 FFT，但“接近整数”不是匹配的确定性充分条件。

### 6.1 #282602：实数及其倒数，半长复数打包

[源码](../../selected/wildcard_pattern_matching/282602.cpp)给每个普通字符随机值 `r(c)∈[0.5,2)`，文本用 r，模式用 `1/r`，双方星号都映成 0。一个非星号相等位置贡献 `r(c)/r(c)=1`，涉及星号贡献 0。

因此合法对齐的相关和为“两边都非星号的位置数”，一定是整数。源码 `is_integer` 检查距最近整数小于 `1e-8`，不用另算该整数应是多少。

但失配也可能碰巧接近整数。教学上若 r(a)=1、r(b)=1.5，`bb` 对 `aa` 的和是 3，虽完全不匹配仍是整数。随机取值使这类等式通常不出现，却不能把检测条件变成全输入证明；浮点误差还可能影响阈值。

实际 `matches` 将最多 n 个实数拆到复数实部/虚部，复数长度为 `max(4,bit_ceil(ceil(n/2)))`，调用 `semicorr → fft,fft,dot,ifft`。末端向量叶块与打包约定配合，不能把它当三次完整长度 `n+m-1` 的常规复数变换。

输入直接 mmap，两行长度用换行确定；输出则重新以读写方式打开 stdout 对应文件、`ftruncate` 后共享映射写入。前后额外页容纳向量化边界写，输出文件长度只保留有效答案。这依赖可定位、可截断和可映射的普通文件环境，不是通用管道输出方案；5 ms 包含这个特化 I/O 的作用。实际投影种子来自 `random_device`，文件另定义的 rng 并未负责这组实数映射。

### 6.2 #365123：同一实数倒数思想，循环相关布局

[源码](../../selected/wildcard_pattern_matching/365123.cpp)的 `WildcardMatcher` 也生成 `[0.5,2)` 实数及倒数。`get` 将模式第 j 项放在 `K-j`，调用自写实数打包 FFT，直接在答案下标 i 检查距整数小于 `1e-8`。

main 显式传 `'*'`；类默认参数虽然是 `'?'`，并不是本题实际通配符。种子含时钟与 `random_device`。它使用自写 radix-4 复数内核与普通关闭同步的 `cin/cout`，不能把它归为 #282602 那份相同 SIMD/映射输出实现。

两份都省掉三幂数组、九组单模卷积与 CRT，代价是随机指纹和数值舍入边界。

还有一个小尺寸实现前提不能略去：#365123 没有给 n=1、2 单设分支，`fconv` 把 K/2 当复数长度，而内部固定访问 `F[1]`、`G[1]`；这时逻辑缓冲不足以容纳该访问。此处是静态路径核查，本轮没有运行它来声称复现某个 OJ 结果，快照 AC 也不等同于覆盖全部合法边界。

### 6.3 #281763：随机单位复数，相等贡献实数 1

[源码](../../selected/wildcard_pattern_matching/281763.cpp)为普通字符生成单位复数 `z(c)`，模式用其共轭。相等时 `z(c)*conj(z(c))=1`；星号为 0。失配贡献带随机相位，相关和一般不在实整数上。

判断同时要求虚部接近 0、实部接近整数，阈值也是 `1e-8`。相位可能抵消，浮点也有误差，所以仍是指纹判定。它使用长度约 `bit_ceil(n)` 的复数数组，没有实数倒数版本的那种半长打包；构造完整候选字符串后再 `substr` 截取有效位置。

源码带阶段 checkpoint，投影使用以时钟初始化的随机发生器。它与 #282602 的算法目标相近，实际数值表示、缓冲大小和 I/O 路径不同，不能按相同作者接口视作逐字节相同实现。

## 7. 两份单模 NTT 指纹：算术精确，指纹仍可能碰撞

### #283569：随机字符比值减去非星号数量

[源码](../../selected/wildcard_pattern_matching/283569.cpp)的 `main → meow(pattern,text)` 使用模 `998244353` 的随机字符值与逆元。构造两项相关：

```text
R[i] = Σ 非星号双方的 r(text_char)/r(pattern_char)
C[i] = Σ 双方非星号的 1
判断 R[i]-C[i] == 0 (mod q)
```

合法对齐逐项抵消为零；失配项仍可能在模数下抵消。这个证明还要求普通字符映射非零；源码直接用固定种子 `mt19937(12345)` 的 `%q` 值并求逆，没有额外的零值重采样，不能把“随机生成”替代非零前提。

实际使用 AVX2 Montgomery NTT，长度 `max(8,bit_ceil(n))`。两条卷积在频域做差后共用一次逆变换，共四次正变换、一次逆变换，避免分别逆变换再相减。三条工作数组来自映射分配，输出经 blazingio，stderr 还有阶段计时。

固定种子意味着每次采用相同映射，并不构成对任意构造输入的随机正确性保证。NTT 无浮点误差，也不能消除指纹表达式本身的碰撞。

### #211809：每个模式位置独立随机权重的线性差

[源码](../../selected/wildcard_pattern_matching/211809.cpp)给模式非星号位置 j 选随机权重 `r_j`，计算

```text
E[i] = Σ(j双方非星号) r_j*(code(S[i+j])-code(T[j])) mod q
```

这是两个卷积之差：文本字符乘模式权重，减去文本非星号标记乘模式的 `r_j*T[j]`。模式星号处两项均置零，文本星号也不会贡献。

合法对齐必为零。对固定失配对齐，在理想独立均匀权重模型下，至少一个非零差的权重能使总式均匀分布，误判概率为 `1/q`；源码使用伪随机发生器，这仍不等于确定性证明。

实现直接调用 ACL 的内部蝶形：四次正 NTT、频域相减、一次逆 NTT，不做 CRT。逆变换后没有乘 `K⁻¹`，因为只检查是否为零，而 K 在模 q 中可逆，整体乘 K 不改变零判定。输出先收集匹配起点，再生成二进制答案串。

## 8. 各路线省掉了什么

| 路线 | 核心变换工作（大输入一般路径） | 正确性条件 |
| --- | --- | --- |
| 上游非负分数 | 三整数卷积，各三模，通常 18 正 + 9 逆 NTT | 系数界内精确整数恢复 |
| 实数倒数 FFT | 一组相关，通常 2 正 + 1 逆，实数可打包 | 随机指纹不碰撞且数值判定可靠 |
| 单位复数 FFT | 一组复数相关，通常 2 正 + 1 逆 | 相位指纹不碰撞且舍入可靠 |
| 比值/位置权重 NTT | 两项在频域合并，4 正 + 1 逆 | 模指纹不碰撞 |

此外，快解只取有效中间区间，常把变换长度从 `bit_ceil(n+m-1)` 降为与 `bit_ceil(n)` 有关的规模。变换数量、每元素类型、打包和 I/O 都不同，不能直接用调用次数相除预测加速倍数。

## 10. 误区与验证设计

| 易错点 | 应检查的事实 |
| --- | --- |
| `*` 可以匹配任意长字符串 | 本题只替代一个位置，输出对齐长度固定 |
| 只考虑模式里的星号 | 文本星号同样必须屏蔽失配 |
| 把字母 a 也编码为 0 | 上游非负分数只允许星号为 0 |
| 总分模 q 为零就是真正零 | 题库已有这种单模方案的反例生成器 |
| NTT 精确，所以随机指纹一定精确 | 算术误差与指纹碰撞是两个问题 |
| 任意卷积都能只补到 n | 此处只读取特定中间区间，完整卷积不成立 |
| 映射 stdout 对普通管道同样适用 | #282602 对可截断普通文件有明确依赖 |

小规模按定义逐对齐检查，并核对本页三条整数卷积表。边界包含 m=1、m=n、两串全星号、只有一边有星号、无星号且完全相同、仅一处普通字符不同，以及有效窗口靠两端的情况。

后续实验应记录变换长度、随机种子、整数距离/虚部残差及误判位置；与上游精确结果逐项比较，区分指纹碰撞与 FFT 舍入。I/O 对比必须保留各实现实际要求的输入输出形式，不能把普通文件特化计时直接推广到管道环境。

本轮仅核查源码热路径、完整哈希、数学例、系数界和本地链接，未新增性能 benchmark，也没有访问 OJ/API。排名和 `is_latest` 保留原快照含义。
