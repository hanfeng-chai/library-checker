# 单点替换、区间函数复合：在线线段树与批量求逆的宽树

## 1. 题目和复合方向

给定N个函数f[i](x)=a[i]x+b[i]。操作0替换某一个函数，
操作1给l,r,x，依次执行f[l]、f[l+1]、…、f[r−1]并输出结果。
[题面](../../../upstream/data_structure/point_set_range_composite/task.md)
规定N,Q≤500000，模数p=998244353，所有斜率a及新斜率都**非零**。

例如[f,g,h]分别为2x+1、3x+4、5x+6。
查询[0,3)、x=5得到h(g(f(5)))=191；
将g替换为x+2后，同样查询得到h(f(5)+2)=71。
查询[1,3)则只执行被替换的g和h，结果为41。

每次顺序执行区间的全部函数，最坏O(NQ)。
两段连续函数合并仍是一个仿射函数：

~~~text
combine(l,r) = r∘l
(al,bl) ⊙ (ar,br) = (ar·al, ar·bl+br)
~~~

结合律让我们缓存区间，非交换性要求所有合并保持从左到右的顺序。
详细的小函数例可参阅[队列复合教程](../queue_operate_all_composite/analysis.md)。

## 2. 一般解法：线段树为什么适合替换和区间复合

把整个下标范围不断二分，每个节点保存对应连续区间的总函数。
叶子保存一个f[i]，父节点为“左子树先执行、右子树后执行”的combine。
替换一个叶子后，只有其到根的O(log N)个祖先可能改变。

区间查询也只需O(log N)个互不相交的节点。
但迭代查询从左右两端取节点时，发现顺序不同：
左边发现的块按从左到右出现，右边发现的块按从右到左出现。
因此上游用两个累加器：

~~~text
left_acc = combine(left_acc, 新发现的左块)
right_acc = combine(新发现的右块, right_acc)
最后 combine(left_acc,right_acc)
~~~

例如区间由连续块U、V、W组成，右端先找到W时，
以后找到V应放到它之前，形成W∘V；若错误地追加就会变成V∘W。
对加法这类交换运算可能看不出错误，对仿射复合必须处理方向。

## 3. 上游 correct.cpp 的实际开销

[correct.cpp](../../../upstream/data_structure/point_set_range_composite/sol/correct.cpp)
将容量补到2的幂sz，申请2sz个F{long long a,b}，
空叶用单位元(1,0)填充，自底向上构造。
set替换叶子并更新每层祖先；sum使用上一节的左右累加器，
返回区间总函数后再作用于x。
初始化O(N)，每次更新/查询O(log N)，空间O(N)。

这里一个F用两个64位整数，虽然系数本身小于p、可用32位存；
模乘则仍须64位中间积。快解可减少存储宽度和补齐空间，
也可利用查询只需要一个最终数值的事实。
上游输入输出是scanf/printf，因此比较完整程序时间还混有I/O差异。

## 4. 在线快解：按顺序直接把节点作用于x

若已按实际执行顺序找到覆盖区间的节点G1、G2、…，
可以直接x=G1(x)、x=G2(x)…，无需先合成完整函数。
每个节点求值只需一次模乘，两个函数合并则需要两次模乘，
因此这能减少查询的算术量。

#278231及#399691把叶子**逆序**放入紧凑的2N布局，
节点combine定义为左函数作用在右函数之后。
布局和合并方向一起反转，最终仍应按题目顺序执行。
查询借边界最高不同位和最低置位位，直接枚举需要的兄弟节点。

用N=4、原函数[f0,f1,f2,f3]看得最清楚：
叶子4、5、6、7分别存[f3,f2,f1,f0]，
节点2保存f3∘f2。查询[1,4)时，
按位枚举先取得叶6的f1，再取得节点2的f3∘f2，
顺序作用于x，得到f3(f2(f1(x)))。

这种紧凑2N布局不补齐为二次幂。N非二次幂时，
不能把根节点简单解释为通常从0到N−1的整段线性顺序；
正确性依赖查询的具体覆盖和枚举顺序。
位操作是在跳过不需要的层和确定兄弟块，不是允许任意顺序应用节点。

## 5. 榜首另一条路线：每个宽节点存前缀的逆函数

### 5.1 非零斜率为什么成为核心条件

f(x)=ax+b的逆为f⁻¹(x)=a⁻¹x−a⁻¹b，仅当a非零时存在。
令F[k]为前k个函数的复合，区间[l,r)的函数为F[r]∘F[l]⁻¹。
若存I[k]=F[k]⁻¹，并记I[r](z)=Ar·z+Br，则：

~~~text
y=I[l](x)
答案z满足 I[r](z)=y
z=(y−Br)/Ar
~~~

因此一次查询可以先返回分子y−Br和分母Ar，
暂时不做模逆。所有函数斜率非零，保证这个分母也非零。

直接存全局每个前缀会使单点替换影响很长后缀。
榜首把前缀分层：每个16路节点只存各孩子**之前**的前缀逆
I_d(x)=I_d·x+J_d，槽0为单位元。
跨多层组合即可取得端点所需的局部前缀逆，
节点大小固定，因此可以用SIMD批量修正节点的一段后缀。

### 5.2 替换一片叶子，怎样变成同一后缀上的仿射更新

旧函数为o(x)=ax+b，新函数为n(x)=cx+d。
先算E=n⁻¹∘o，它是

~~~text
E(x)=s·x+t，s=a/c，t=(b−d)/c
~~~

设更新位置之前的前缀为P，P⁻¹(x)=I·x+J。
对包含被改函数的后续前缀，其逆函数需要在外侧复合
P⁻¹∘E∘P。展开后：

~~~text
P⁻¹(E(P(x))) = s·x + I·t + (1−s)J
~~~

所以令v=I·t+(1−s)J，所有受影响的逆前缀系数统一更新为
I_d←s I_d、J_d←s J_d+v。每层只对更新孩子之后的槽做这件事，
然后把修正继续传到上一层。
这就是源码apply_delta与update_suffix里SIMD掩码更新的数学含义。

模17的小例：P=2x+1，旧o=3x+4，新n=5x+6。
5⁻¹=7，故s=4、t=3；P⁻¹=9x+8，
v=9×3+(1−4)×8=3 mod17。
旧整段P后接o为6x+7，逆为3x+13；
外复合4x+3后得到12x+4，
正是新整段10x+11的逆。这个例子也核验了复合方向。

### 5.3 一次快速幂可以求出很多逆元

对非零数u0,…,um−1，先保存各位置之前的前缀积Pi，
并计算全部乘积T。只求一次T⁻¹，
从后往前用T⁻¹Pi取得当前元素的逆，再把逆累积量乘ui，
就转成更短前缀积的逆。

模17例子u=[2,3,5]，前缀积为[1,2,6]，
总积13的逆是4；逆序得到[9,6,7]，
分别满足2×9、3×6、5×7都模17为1。
成本是线性次乘法加一次快速幂，而非m次快速幂。
若有零元素，这套总积求逆会失败，不能跳过非零条件。

## 6. 为什么第一名需要先读完整操作流

#402223在读入全部Q条操作时收集所有新斜率，批量求它们的逆。
随后只沿原数组模拟每个位置被依次替换成什么，
预计算每条更新的E=n⁻¹∘o；这一步不执行树查询，也不依赖查询答案。
然后按照**原时间顺序**真正更新树、记录查询得到的分子/分母，
最后对所有答案分母再做批量求逆并输出。

预处理和延迟输出不等于重排更新。每个分数仍在对应查询的正确历史状态下计算，
后来只进行代数上的分母还原。
这是一条需要保存操作流和答案、使用O(N+Q)空间的做法；
它不能原样用于下一条输入依赖前一条输出的交互式流。

构造树时，源码也批量求各节点总乘数的逆，
再逆序恢复节点内所有独占前缀逆。层间的共享高位前缀会在查询分子/分母里相消，
所以只访问左右端点最高不同位以下的层。
query_fixed组织三条独立链：左逆作用于x、右逆作用于0、
右逆斜率；这些链最终组成第五节的分数。

### #402223：把数学条件、向量后缀更新和批处理接起来

inverse_prefix_tree默认fanout16，节点将16个逆斜率和16个逆偏移分数组存放，
方便AVX2以8个32位槽批量更新后缀。模数内核使用Montgomery表示和固定乘数预处理。
求值返回分数，最后逆元累积从普通表示开始，
与编码分母相乘后保持普通表示，使输出少一次独立解码。

它还提前预取未来更新的原叶值、回放时未来4条操作的低层节点；

## 8. 实现选择与可验证结论

在线线段树不要求预读操作，O(N)空间，单次更新/查询O(log N)。
逆前缀宽树以非零斜率为前提，查询O(log_B N)，
更新每层修正至多B个槽，标量工作O(B log_B N)；
固定B=16并用SIMD改变常数，另付出O(Q)预处理/答案存储。

应固定I/O比较“返回区间函数”与“直接作用x”，
再比较普通二叉与逆前缀宽树，并单独计入读完整操作流和批量求逆时间。
验证重点是复合方向、同位置多次覆盖、跨节点边界、
斜率接近p−1、重复设置及N不是2的幂。
本文核对公式、按位查询的小模型和五份源码，没有新增性能benchmark；
49–83ms的整体差距不能被简单归给某一条SIMD指令。
