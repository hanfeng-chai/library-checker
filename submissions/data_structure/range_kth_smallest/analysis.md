# Range Kth Smallest：从排序到稳定分流与批量查询

## 题意：k 从 0 开始，重复值分别计数

数组不修改。每问 `l r k`，把半开区间 `A[l..r)` 的值排序，输出下标 k
的值，即第 k+1 小。`N,Q≤200000`、`0≤A[i]≤10^9`、`0≤k<r-l`，
见 [`task.md`](../../../upstream/data_structure/range_kth_smallest/task.md)、
[`info.toml`](../../../upstream/data_structure/range_kth_smallest/info.toml)。

```text
输入                 输出
6 4                  2
5 1 4 2 1 3          1
1 5 2                5
0 6 0                4
0 6 5
2 3 0
```

第一问是 `[1,4,2,1]`，排序为 `[1,1,2,4]`，下标 2 是 2。
两个 1 各占一个名次。全数组最小值为 1、最大值为 5；单元素区间 `[2,3)`
只能返回 4。查询参数不依赖前一次输出，因此允许预先读完并批量求解。

## 朴素方法与要共享的工作

每问复制区间并排序，长 m 的查询花 `O(m log m)`；也可以做一次选择
算法，平均 O(m)，但二十万问仍会反复扫描相同元素，最坏规模不可接受。
另一想法是二分一个值 x，统计区间内有多少元素小于等于 x，决定答案在
哪一侧。若每次统计还要扫区间，就没有解决重复工作。

波列矩阵把这次“按值二分”预先落实到每个二进制位：先区分高位 0/1，
再在被选的一侧区分下一位；每层只要知道区间中落在较小侧的数量，就能
决定目标排名去哪。为了继续查询，还要把原来的两个端点映射到下一层。

## 稳定划分为什么能映射任意区间

在当前数组某一位上，先把所有 0 位元素放前面，所有 1 位元素放后面，
且各侧保持原来的相对顺序，这叫稳定划分。记
`rank1(i)=当前位置 [0,i) 中 1 的数量`，`rank0(i)=i-rank1(i)`，
Z 是全层 0 的总数。区间 `[l,r)` 的 0 元素数为
`z=rank0(r)-rank0(l)`。

如果 k<z，答案在 0 侧，下一层区间就是
`[rank0(l),rank0(r))`，k 不变；否则在 1 侧，下一层区间为
`[Z+rank1(l),Z+rank1(r))`，k 减去 z，并把答案当前位设为 1。
稳定性保证原区间中选中的元素在该侧仍然连续；不稳定地交换元素，就不能
只靠两个前缀计数描述下一层区间。

```text
for bit 从最高位到最低位:
    l1=rank1(l), r1=rank1(r)
    z=(r-l)-(r1-l1)
    if k<z:
        l=l-l1; r=r-r1
    else:
        k-=z; answer |= 1<<bit
        l=Z+l1; r=Z+r1
```

不变量是：当前区间包含的正是原查询中，具有已选答案高位前缀的那些
元素，k 是它们之中的剩余名次。每层排除不可能的一侧，最后得到完整值。
每层的整个数组不一定按数值排序；保存的是稳定分流所需的位置关系。

## 把第一问逐位走完

示例值都小于 8，先只看三位；上游固定 30 位时，前面高位全零的层不会
改变这几个值的相对区间。三层的当前序列与当前位为：

| 位 | 当前数组 | 当前位 | Z | 划分后数组 |
|---:|---|---|---:|---|
| 2 | `5,1,4,2,1,3` | `1,0,1,0,0,0` | 4 | `1,2,1,3,5,4` |
| 1 | `1,2,1,3,5,4` | `0,1,0,1,0,0` | 4 | `1,1,5,4,2,3` |
| 0 | `1,1,5,4,2,3` | `1,1,1,0,0,1` | 2 | 最后一层之后无需再查询 |

对 `[l,r,k]=[1,5,2]`：

| 当前位 | 当前 `[l,r)` / k | 区间 0 个数 | 选择与新状态 |
|---:|---|---:|---|
| 2 | `[1,5)` / 2 | 3 | 选 0，变 `[0,3)` / 2 |
| 1 | `[0,3)` / 2 | 2 | 选 1，变 `[4,5)` / 0 |
| 0 | `[4,5)` / 0 | 1 | 选 0，变 `[1,2)` / 0 |

选中的三位为 `010₂=2`。第 1 位选择较大侧时，前面两个更小的候选
已经占了名次 0、1，所以要把 k 从 2 减成 0。

## 沿上游 `correct.cpp` 看 rank 和建表

上游 [`correct.cpp`](../../../upstream/data_structure/range_kth_smallest/sol/correct.cpp)
实际构造 `wavelet_matrix<int>(30,a)`。每层先生成 vector<bool> 当前位，
把它打包进 bit_vector，再用 v0、v1 收集两组元素，复制回工作数组。
查询 quantile 正是上述逐位映射，读一问即可答一问。

bit_vector 每个机器字存位图 bit，以及此前完整字中的 1 的总数 sum。
查询 rank1(i) 时，先读完整字前缀，再对当前字低 `i%64` 位做 popcount。
例如位图前缀 `1,0,1,0,0` 的 rank1(5)=2；如果 i 正好为 64 的倍数，
字内贡献为 0，只读边界累计值，不能构造移位 64 的表达式。

因此每层 rank 为 O(1)，构造 `O(30N)`、查询 `O(30)`；按可变值域
U 写作 `O(N log U)` 与 `O(log U)`。位图加按字摘要占
`O(N log U/64)` 个机器字，另有 O(N) 构造缓冲。上游已经是位图索引，
不是每层一条完整 N 项的整数前缀数组。快解还可以减少层数、分配和扫描，
并改变查询调度方式。

## 先压缩值域，为什么不改变第 k 小

把不同原值从小到大排列为 `decode[0..S)`，每个元素换成其下标。
大小关系和相等关系都保留，名次自然不变，最终查 decode 还原。
示例 decode 为 `[1,2,3,4,5]`，编码为 `[4,0,3,1,0,2]`。
只需 `ceil(log₂S)` 位，S≤200000 时至多 18 位，比固定 30 位少很多层。

排序本身也有成本。非负值最多 30 位，可用两轮稳定计数排序：先按低
15/16 位分桶，再按高位分桶。第二轮稳定，才会在高位相同处保留低位次序。
这叫基数排序，代价约为 `O(N+桶数)` 每轮，另需临时数组。
小 N 时清空三万或六万多个桶未必划算，一些源码会退回比较排序。

## #403008：不用保存整张矩阵的离线流水

main 调 `offline::range_kth_smallest`，先消费全部查询，存成 first、last、
rank、answer 四条连续数组。对每一位，构造当前层 rank，立即让所有查询
通过这一层，再稳定划分值数组并复用 rank 缓冲。未来不再访问旧层，
所以源码明确没有保留完整 wavelet matrix。

正常 rank 表是 N+1 个 32 位前缀数，单次读取很简单；与上游位图相比，
同一层更大，但始终只有一层。总工作为 `O((N+Q)H)` 加值域编码，
工作空间 O(N+Q)，H 是所用位数。代价是无法在预处理后接受一个此前
不知道的新查询，必须重新跑各层或另存索引。

它还会避免不必要的排序：若 `bit_width(max-min)≤bit_width(N-1)`，
直接令 code=value-min，不去掉值域空洞；位数已经不多于通常压缩的上界。
否则用两轮 16 位基数排序生成真正的不同值排名。全相同数组所需位数为 0，
直接把零编码解码即可。不能把所有分支都描述成“先排序压缩”。

### 八个槽如何同时推进八条查询

AVX2 每槽一个查询的 l/r/k，分别 gather 读取 prefix[l]、prefix[r]。
逐槽算 0 数量和 `k<z` 的真假掩码，再 blend 更新两个端点、剩余排名。
八条查询互不依赖，所以它们确实并行；单条查询仍要按高位到低位依次推进。
与仅把 scalar 查询包在八次循环里的批处理不同，这里使用了向量 gather
和向量选择指令。

构建时八槽放八个当前值，用移位加 movemask 收集它们当前位，查一个
256 项小表得到八个局部前缀数。稳定划分也用此掩码查重排表，把 0 或 1
侧元素依原槽顺序压紧后写到两条输出流。最后边界用受控掩码写入，
私有缓冲补八项，避免零流覆写已写的一流或越界读输入。

### 四个前缀压成一字，以及最后一位才写答案

端点分散且 N/Q 足够大时，源码选择压缩 rank 表：一个 32 位字的高
24 位存四位置块前的 1 数量，低八位分成四个两位字段，存局部排他前缀
`0,b0,b0+b1,b0+b1+b2`。这些局部数最大为 3，恰能放两位。
例如局部位 `[1,0,1,1]`，四前缀为 `[0,1,1,2]`；读取块内偏移 3
时，从全局基数加 2 得到 rank。表体积约缩为普通整数前缀的四分之一，
代价是 gather 后再移位解码。

选择条件包括 N≥32768、查询数≥4096，并抽样端点是否覆盖至少 12 个
粗位置区；这只是性能启发式，正确性不依赖分布。进入这套调度后，可按
每层位置分布选择普通或压缩前缀，但都不反复读写 answer：最后一位时，
当前区间元素的更高位已经相同，从 current[l] 取得高位，再补选中的最低位。
它省掉每层四条查询数组中的答案那条读写。需要 AVX2 与预期的 Linux
文件读入环境，20 ms 同时含这些布局、编码与 I/O 变化。

## #393928 / #376681：完整位图索引，外层循环换成“层”

两份都先建完所有位图层，再存全部查询的 l/r/k/answer，循环顺序为
“当前层的所有查询处理完，再去下一层”。与上游逐问跨 30 层相比，
一行位图能够被大量查询反复使用，缓存局部性更集中。
每个查询仍只做相同的二分名次递推，总时间 `O((N+Q)log S)`；
空间为 `O(N log S/64+N+Q)` 个机器字。

无分支选择用 `mask=-(k≥z)`，其值为全 0 或全 1：
`new_l=(l0 & ~mask)|((Z+l1)&mask)`，k 减 `z&mask`，答案 OR 当前位
与 mask 的按位与。这减少难预测的 if，不减少算法所需的 rank 次数。

#393928 使用 `CompressedWaveletMatrix`，30 位输入按两轮 15 位基数
排序，小数组退回 stable_sort。Block 为一个 64 位位图加此前 1 数量与
填充字段；同一扫描中打包位图、分别收集 0/1 元素。main 调 kth_batch，
同文件未实例化的普通 WaveletMatrix 与 MergeSortTree 不参与本题。

#376681 把 `(值<<18)|原下标` 放入 64 位数，用两轮 16 位基数处理
值的部分；18 位下标足够覆盖 200000 个位置。它用 malloc 的连续数组、
16 字节 Blk 和独立查询数组，构建与批量映射基本同形。全相同数组仍留
一层。POPCNT 用于 rank，输入优先 mmap、失败可整段读取，输出查表缓冲。
两份同为 35 ms，不能从这一快照拆出容器、基数位宽与 I/O 的单项收益。

## #401815：一次处理两位，四个数字桶

Rust 实例化 `WaveletMatrix::new(a)`，先按值比较排序并压缩。
构造同时保留普通 bit_vectors 和 quad_vectors；后者把相邻两位的
低/高位图及四类前缀数量放在一起，主 quantile_batch 优先使用四路路径。
区间的 `00,01,10,11` 数量给出四段累计名次，直接选择目标数字 0…3，
一次跳过两个二进制层。

存储顺序有一个容易忽略的细节：连续两次“全层 0 在前、1 在后”的稳定
划分，四类的物理顺序会是 `00,10,01,11`，不一定是数值顺序。
源码 starts 因此分别记录真实起点；选数字时按 0、1、2、3 的数值名次，
映射时却必须加对应的物理 starts，不能直接用四桶累计频数当物理偏移。

quantile_batch 先收集全部查询，再按 16 问分块，每个小批通过所有层，
与前两份“所有 Q 问共享一层”的全局批次不同。CPU 支持相应 AVX-512
人口计数后端时可用四路向量内核，否则保留标量/POPCNT 路径；构建在
AVX2 可用时做位图打包和稳定重排。不能因文件含 AVX-512 代码就断定
当前 OJ 使用了它。额外四路索引减少查询层数，也增加构造和存储常数。

## #391951：保留在线单问接口，按 CPU 选择内核

main 建 `WaveletMatrix<int>` 后边读边调用 kth_smallest，不保存全部
查询。整数压缩先检查值域高位是否相同、减最小值是否减少基数轮数，再
进行 16 位一轮的排序。构建位图可用 AVX2；稳定划分若支持 AVX-512F
可用压紧存储指令，否则用 AVX2 查表重排或标量分流。

查询在检测到 POPCNT/BMI2 后用 BZHI 清掉字中指定偏移以上的位，再
popcount；普通路径用移位掩码。两种都执行同一个 O(log S) 的在线
递推。文件中的 top-k 频率、前驱后继和范围频数接口未由 main 调用。
80 ms 与批量方案的差异可能来自查询调度、CPU 路径、额外索引构造和 I/O，
不能把“支持更多接口”本身当成运行时一定有开销。

## 本仓库与验证边界

本地 [`batched_wavelet_matrix.cpp`](../../../problems/data_structure/range_kth_smallest/batched_wavelet_matrix.cpp)
对应完整矩阵的批量方案，说明见 [`tutorial.md`](../../../problems/data_structure/range_kth_smallest/tutorial.md)。
另有 [`merge_sort_tree.cpp`](../../../problems/data_structure/range_kth_smallest/merge_sort_tree.cpp)：
它每个位置线段树节点保存有序数组，统计不大于 x 需要 `O(log²N)`，
实际 kth 还在不同值域上二分，因此该源码查询应计为
`O(log S*log²N)`，不能把一次计数的复杂度直接当成完整第 k 小。

小规模用直接排序核对，覆盖所有值相同、重复值、单元素、k=0、k=长度-1、
值域整体很大但跨度很小，以及位图边界 63/64/65 与 r=N。
批量版还要检查同一输入按原顺序输出、尾部不足八或十六问的路径。
本篇只复核本地代码、元信息与算例，没有访问 OJ 或新增性能 benchmark；
历史 tutorial 的墙钟变化不当作当前五份之间的控制实验。
