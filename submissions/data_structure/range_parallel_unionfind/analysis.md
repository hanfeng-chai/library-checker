# Range Parallel Unionfind：记住整段对应关系，跳过重复合并

## 题意与完整小例子

初始有 N 个孤立点，点 i 的固定权值为 x[i]。一次操作 `k a b` 添加
`(a,b),(a+1,b+1),…,(a+k-1,b+k-1)` 这些边。
它是两段区间**逐位置配对**，不是把两段里任意两点都连起来。
每问后输出所有已经连通的无序不同点对的权值乘积之和：

```text
X = sum(x[i]*x[j]，其中 i<j 且 i,j 已连通) mod 998244353
```

`N,Q≤500000`，`0≤k≤N`、`0≤a,b≤N-k`，权值在模数内。
详见 [`task.md`](../../../upstream/data_structure/range_parallel_unionfind/task.md)
和 [`info.toml`](../../../upstream/data_structure/range_parallel_unionfind/info.toml)。
k=0 可以取 a=b=N，但不应实际访问下标 N 的顶点。

```text
输入                  输出
6 6                   14
1 2 3 4 5 6           14
2 0 3                 85
2 0 3                 175
3 0 2                 175
1 4 5                 175
0 6 6
6 0 0
```

第一问连 0–3、1–4，分组为 `{0,3}`、`{1,4}`、`{2}`、`{5}`，
贡献为 `1*4+2*5=14`。第二问重复这些边，没有新点对，仍为 14。
第三问连 0–2、1–3、2–4，最终点 0…4 全部连通，贡献为 85；
第四问把它们与点 5 连通，新增贡献 `(1+2+3+4+5)*6=90`，总计 175。
最后两问是空操作和所有点各与自身连接，答案都不变。

## 先解决答案维护，再解决区间长度的瓶颈

普通并查集可以逐对合并，每组维护权值和 S。合并两个不同组 C、D 时，
新增的点对恰为一端来自 C、另一端来自 D，贡献为

```text
sum(i∈C,j∈D) x[i]*x[j]
  = (sum(i∈C)x[i]) * (sum(j∈D)x[j])
  = S[C]*S[D]
```

所以只需 `answer+=S[C]*S[D]`，新组和设成 `S[C]+S[D]`；
已经同组则什么都不加。这里没有除以 2，因为两个旧组不相交，每个新无序
点对已经唯一地由“第一组一端、第二组一端”枚举一次。

示例第三问的过程：先把权值和 5 的 `{0,3}` 与权值 3 的 `{2}` 合并，
加 15，答案变 29；再把和 8 的 `{0,2,3}` 与和 7 的 `{1,4}` 合并，
加 56，变 85；最后的 2–4 已同组，不能再加一个“组和平方”。

但若每条长度 k 的输入都循环 k 次，时间是
`O((sum k)α(N))`，最坏 sum k 可到 `NQ`。虽然底层真正成功的合并
总共最多 N-1 次，失败的重复 find 仍可能做几千亿次。
优化需要记住“一整段配对已经处理过”，而不只记住单个点的分组。

## 上游的多层并查集：每个元素代表一个块的起点

第 h 层的元素 p 表示长度 `2^h` 的区间 `[p,p+2^h)`。
所有合法起点都建一个元素，因此这一层有 `N-2^h+1` 个元素；
**不是只为对齐的、不重叠块建 N/2^h 个元素**。

`unite(h,a,b)` 表示两块的相同偏移都应连通。其不变量是：
若 h 层已经判定两个起点同组，那么对应的所有底层点已经连通。
反过来未必成立：两对点分别在第 0 层合并过，不会自动向上更新第 1 层。
上层是一份足以安全跳过的证明记录，不是每次都精确反映全部底层关系的双向表。

```text
unite(h,a,b):
    若 h 层两起点已同组: return
    合并这两个块标签
    if h==0:
        按两个底层组的权值和更新答案
    else:
        half=2^(h-1)
        unite(h-1,a,b)
        unite(h-1,a+half,b+half)
```

例如 N=8，要配对 `[0,4)` 与 `[4,8)`：

```text
第2层：unite(0,4)，块长4
  第1层：unite(0,4)，块长2
    第0层：合并0与4，合并1与5
  第1层：unite(2,6)，块长2
    第0层：合并2与6，合并3与7
```

再次出现同一长度 4 的配对，第 2 层发现两标签已同组，整棵展开树都跳过。
若 A 块与 B 块、B 块与 C 块已经等价，传递性说明每个偏移的 A 点与 C 点
也已连通，所以并查集允许用同组关系跳过，不必只记录原封不动的操作二元组。

正确性可按 h 归纳：叶层执行普通点合并；新高层关系通过左右半块完整
展开，建立所有需要的点关系；已有高层等价由先前展开及传递性保证，故
跳过不会漏边带来的连通效果。高层只记对应关系，不把一个块内部所有点
当成一个底层连通组。

## 任意长度怎样只需两个块调用

最容易理解的是取 `h=floor(log₂k)`、w=`2^h`，用前 w 项和后 w 项：
`[a,a+w)`、`[a+k-w,a+k)`，另一端取相同偏移。因为 `w≤k<2w`，
两块覆盖整个区间，中间可能重叠，但重复合并是幂等操作，不会改变答案。
例如 k=6，用偏移 `[0,4)` 与 `[2,6)`，偏移 2、3 重复处理也会被跳过。

上游 [`correct.cpp`](../../../upstream/data_structure/range_parallel_unionfind/sol/correct.cpp)
具体选择稍有不同：k=0 返回，k=1 直接点合并，其余取
`h=topbit(k-1)`。若 k 是二次幂，它使用两个相邻的半长块；若 k 不是
二次幂，就与上面的最大块方案相同。k=4 因此调用两个长度 2 的块，
而不是一个长度 4 的块。这与它只分配到该层的方式配套。

`merge_inner` 在高层只在 DSU 合并成功时递归；底层先找两根，合并后再
确定哪个是新根 c，把回调参数设为“新根 c、被吸收根”。
`a xor b xor c` 正好从两个不同旧根中消掉新根，取得另一个根。
main 的回调才执行 `ANS+=x[new]*x[old]、x[new]+=x[old]`。
因此分块逻辑不负责模数算术，只有真实底层合并影响分数。

### 摊还界来自所有层的成功次数，不是每问都很短

第 h 层有 `m_h=N-2^h+1` 个块标签，最多成功合并 m_h-1 次。
每次高层成功仅产生两个更低调用，加上每个输入至多两个顶层调用，
总 DSU 尝试数为 `O(N log N+Q)`。按大小并压缩的每层 DSU 给出
总时间 `O((N log N+Q)α(N))`，空间 `O(N log N)`。
首次大区间操作可能真的展开很多叶子，不能把摊还总界写成每问 O(log N)。

N=500000 时，完整二次幂各层总共约 898 万个父槽，32 位槽约 35.9 MB，
还要另存底层权值和与其他数组。代价是大量上层记忆，换取以后重复区间
不必再次逐点访问。底层分数乘法只发生最多 N-1 次，热点未必在模乘，
可能更多是各层 find 与缓存访问。

### #251479 / #251469：最大块、静态层和底层特殊分支

输入转为一基下标，`dsu[19]` 每层都预留约 500009 个父槽，实际初始化
合法起点区间。顶层用 `floor(log₂k)`，k 恰为二次幂时只调用一次；
否则调用前后两个重叠块。上游用两个半块的情形，在这里可以一次高层
判同组就结束。固定数组省掉各层动态容器，但为较高层保留了无效尾部容量，
所有层核心父槽约 38 MB，而非精确按 m_h 分配。

高层 `union_` 正确按负大小把小组接到大组，递归 fat 完整压缩。
但第 0 层单独的手写分支写成：若 `fa[u]<fa[v]` 就交换，然后将 v
接到 u。负值更小表示集合更大，这样反而让**较大组接到较小组**。
连通与分数公式不依赖根方向，仍能算对应结果；平衡合并的树高/α 证明
却不能直接套到这份底层。仅路径压缩没有阻止单次构造很长父链，
复用时应修正这个比较方向再重新验证，而不是只看函数名字。

答案与组和用 MontgomeryModInt，以模数为常量的编码/约减处理乘法，
输出时解码；FastIO 使用映射/缓冲和查表格式化。
因为分数乘法最多 N-1 次，而上层可能有数百万次 DSU 操作，不能把
239 ms 的位置主要归功于 Montgomery，尤其两份相同源码还有 12 ms 差异。

### #393929：所有层平铺到一个父数组

`ParallelUnionFind` 计算 offsets，把每层恰好 `N-2^h+1` 个父槽放入
一条 parents 向量，根仍存负大小。unite 先保存原始块起点 first/second，
再查根、按大小合并；递归下探使用的是**原始起点**及其 half 偏移，
不能把 DSU 根标签当成输入区间位置而随意替换。

第 0 层直接更新 component_sum 和 answer，使用 64 位乘积 `%M`，
不需要上游回调中的再次查根。所有层均按正确大小方向合并，适用前述
标准摊还界。顶层对 k 为二次幂也调用前后两次，第二次完全相同并立即
返回；它没有 #251479 的“相同块只调用一次”分支。
I/O 用 direct_mapping 和字段上界特化。连续存储减少分配和无效尾容量，
未改变基本多层记忆化算法。

### #214473：四份展开换更少层数

这里第 h 层块长为 `4^h`，而不是 `2^h`。首次成功时递归四个长度
`4^(h-1)` 的对应子块。若某层已同组仍直接跳过；证明与二叉版本相同，
只是每个成功节点产生四个孩子。

顶层选 w 为满足 `4w<k` 时继续放大的四次幂。对于 k>1，有
`w<k≤4w`，然后从尾部往前铺长度 w 的块，最多四次，最后一块落在
偏移 0，可能与前一块重叠。例如 k=10、w=4，偏移依次为 6、2、0，
覆盖 `[6,10)`、`[2,6)`、`[0,4)`，并集正好是所需十项。

更少层降低父槽数量，N=500000 时四次幂层约 465 万槽，但每次展开
分四份，顶层可能多于两次调用。因此是层数、内存与分支数的取舍，
不是无条件少一半时间。总成功/尝试次数仍为 `O(N log N+Q)` 量级，
只是对数底和常数不同。

`paruf.unite` 返回这次**真正成功的底层点合并对**列表，main 再用
另一个 DsuFast 按同一列表维护组和与答案。两个底层连通结构重复存储，
但职责清楚：一个供块记忆化，一个供业务权值聚合。列表由成功合并组成，
所以 main 不会对本来同组的一对再加组和乘积。文件里还有另一种 Dsu
模板，实际业务选择的是 DsuFast，不能混为同一实例。

### #271843：保留上游结构，主要更换读写包装

真正入口 `SolveMain` 构造 `OY::RPUF::RangeParallelUnionFind`，
接收回调更新 x 和 ans。顶层仍取 `topbit(k-1)`，k 为二次幂时展开

初始化和读写环境，不能因为源码长就当作执行了更多算法。

## 适用条件与验证

上层标记之所以可永久跳过，是底层只会合并、不会拆分。一旦允许删除边、
回滚或修改历史版本，这些标记就不再自动有效，必须另做可撤销设计。
题名中的 parallel 指对应下标同时提出合并，不代表多线程并行执行。

本地 [`overlapping_power_blocks.cpp`](../../../problems/data_structure/range_parallel_unionfind/overlapping_power_blocks.cpp)
与 [`binary_decomposition.cpp`](../../../problems/data_structure/range_parallel_unionfind/binary_decomposition.cpp)
分别用重叠两块和按 k 的二进制位拆成不相交块，说明见
[`tutorial.md`](../../../problems/data_structure/range_parallel_unionfind/tutorial.md)。
后一种每问顶层最多 O(log N) 调用，便于对照两块覆盖的幂等性。

小规模直接逐对合并并枚举点对求分数即可核验。重点包括 k=0、k=1、
a=b、二次/四次幂长度、两段相交、重复长区间、经不同操作间接已经连通、
权值为 0 或 M-1。性能实验应拆分层数、块展开次数、失败 find 次数和模乘，
并统一 I/O；本篇没有新增 OJ 请求或 benchmark，本地历史测量不当作
本轮五份代码之间的纯算法比较。
