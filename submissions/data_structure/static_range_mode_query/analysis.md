# Static Range Mode Query：从频数扫描到回滚 Mo 与自适应索引

## 题意：输出最常见的值，也要输出它的准确次数

每问给半开区间 `[l,r)`，返回出现次数最多的一个值及其次数。
多个值并列时任选一个，不要求最小值。众数不必超过一半，这与严格多数元素
不同。数组不修改，`N≤100000、0≤Q≤100000`、值在 `[0,10^9]`，
见 [`task.md`](../../../upstream/data_structure/static_range_mode_query/task.md)、
[`info.toml`](../../../upstream/data_structure/static_range_mode_query/info.toml)。

```text
输入                    一种正确输出
9 5                     1 4
2 1 2 3 1 2 1 1 3       1 2
0 9                     1 3
1 6                     3 1
2 8                     2 2
3 4
0 3
```

全数组的 1 出现四次，2 三次，3 两次；`[1,6)` 中 1、2 都出现两次，
输出 `2 2` 也正确。`[2,8)` 是 `[2,3,1,2,1,1]`，众数为 1、次数 3。
单元素区间的次数为 1。Q=0 时只有数组输入，不应输出任何答案。

## 朴素统计与删除最大值的困难

每次扫描区间，用字典或压缩值域后的数组统计次数，再取最大，单问 O(r-l)。
十万次长区间最坏要读约 `10^10` 个元素。离线 Mo 可以重排查询，只增删
当前区间边缘；加入 x 很容易：`freq[x]++`，超过当前最大次数就更新众数。
删除却麻烦：如果删掉当前唯一最高频值的一次，新的最大频数/候选在哪？
只保存“目前众数和次数”不足以回答。

普通 Mo 可以额外维护按频数分桶的值链表，但上游选择另一条路：
**只让长期状态增加，短期增加之后完整回滚**。这样不用寻找删除后的新众数。

## 上游 `correct.cpp`：回滚 Mo 的实际执行方式

上游 [`correct.cpp`](../../../upstream/data_structure/static_range_mode_query/sol/correct.cpp)
先排序不同值、把数组压缩为 ID，再把全部查询交给 Rollback_Mo。
相同原值用相同 ID，频数数组只需按不同值数分配，输出用 key[ID] 还原。

把左端按位置块分组，每组查询按右端递增。组内取 `LMAX=最大的实际左端`。
长期状态维护 `[LMAX,R)`，R 只向右增加；处理某问 `[L,R)` 时：

```text
向右加入新元素，扩大长期状态到当前 R
保存历史长度、当前众数、当前最大频数
从 LMAX-1 向左加到 L（至多一个块）
记录此问答案
撤销本次临时加入，恢复保存的众数与频数
```

freq 的每次增加都会把相应值 ID 压入 history。rollback 将保存时刻之后
的 ID 逐个弹出、频数减一，并直接恢复 save_max_freq/save_argmax。
因为恢复的是以前真实存在的整份状态，所以不必在删完后重新寻找最大频数。
开始新左块时 reset 清空整份长期状态。

### 用例子看一次保存与恢复

教学取左块 `[0,3)`，处理 `[1,6)`、`[2,8)`，LMAX=2。
先建立 `[2,6)` 的 `[2,3,1,2]`，长期众数为 2、次数 2。
保存后临时加入位置 1 的值 1，得到 1、2 各两次；记录任一众数，
再撤销该 1，回到原长期状态。

下一问 R 从 6 增到 8，加入两个 1，长期状态变成 `[2,8)`，
1 的次数达到 3；此问 L=LMAX，不用临时左扩，直接输出 1、3。
前一问临时加入的值没有错误地留到下一问。

同块短查询先在空状态中直接扫描、记录、回滚，不强行建立长期右侧状态。
源码块数约 sqrt(Q)、块宽取有效最大右端除块数向上取整；Q=0 时 calc
立即返回，不会除以零。总增量工作约 `O(N²/B+QB)` 加排序，
B≈N/√Q 时约 O(N√Q)，空间 O(N+Q)。这是离线算法，不能新增未知查询后
直接访问一个永久索引；读取、分桶、保存答案也是成本。

## 在线块众数表：只枚举两端碎片的候选

另一种方案把数组按宽 B 分块，预存每个完整块区间的众数和次数。
从每个左块开始向右扫一次、维护计数，建表 O(N²/B)，表项
O((N/B)²)。查询取中间完整块的众数，剩下只有左右不足 B 项的碎片。

为什么只检查边缘出现的值就够？设中间众数次数为 c。一个值若两端都没
出现，它在全区间的次数仍不超过中间最大值 c，无法超过当前候选。
所有可能改善答案的值，要么是中间候选自身，要么在某个边缘出现，
因此扫描边缘覆盖了全部可能获胜者。

### 出现位置表怎样把“能否超过 c”变成一次下标读取

给每个值保存有序出现位置，并给每个数组位置记录它是该值第几次出现。
示例为：1 在 `[1,4,6,7]`，2 在 `[0,2,5]`，3 在 `[3,8]`。
如果从左边缘位置 i 看到某值，其出现序号为 t，检查位置表的第 t+c 项
是否仍小于 r：若是，说明从 i 起至少有 c+1 次，可改善答案。
然后继续向后数到 r 前，得到新次数。右边缘反向检查第 t-c 项是否≥l。

查询 `[2,8)`，教学 B=3，中间 `[3,6)` 为 `[3,1,2]`，初始 c=1。
左端位置 2 是值 2 的第二次出现，向后第 1 次在位置 5，仍在区间，
于是把次数扩到 2。右端位置 7 是值 1 的第四次出现，向前第 2 次在位置 4，
还能扩到 3；再向前到位置 1 已出界，所以准确答案为 1、3。

从左向右扫描时，一个能真正改善当前最大值的候选，必在它的区间内第一
次出现处被处理；若之前已经见过同值，要么当时就已完整扩到其次数，
要么它当时不能胜出，现在更不能胜出。右端反向扫描同理取最后一次出现。
所以这些扩展得到的是候选的**准确频数**，不是只从某个中间位置开始的下界。

c 单调增加，而最终次数不超过“中间最大 c 加全部边缘元素数”，故所有
while 扩展总共至多 O(B)，加上扫描边缘仍是每问 O(B)，不会藏一个 O(N)
的逐次统计。准确频数达到区间一半后，其余所有值总共也不超过它，可停止；
必须先把当前候选数完整，再做早停，不能只拿一个频数下界输出。

## #403022：先识别数据形状，再选需要保存的统计

main 在 Q>0 时构造 `static_range_mode<u32,avx2>`，边读查询边输出。
Q=0 则只消费数组，不建立索引。`static_occurrence_index` 先稳定基数
排序压缩值，把每值所有位置、组起点和每位置的组内序号放在连续 CSR 数组，
并计算不同值数 σ、全局最大频数 F。以下分支都由这些精确统计选择。

### 全同、全异、二值：省掉通用块表

σ=1 时，答案就是唯一值和 r-l；F=1 时，任意区间元素都是众数，次数 1。
σ=2 时，只存第一个值的前缀次数 c，另一值次数为区间长度减 c，比较
两者即可。构造 O(N)，每问 O(1)，不用执行根号个边缘检查。
全区间查询也直接返回预先算好的全局众数。

### 小值域：按块边界保存全部值的频数

一般 σ≤1024 时可选 dense_prefix。σ≤8 就每个位置存一行前缀，
否则每 32 个位置存一行。查询把完整块范围两行相减，得到所有值的中间
频数，再加入至多两段边缘。短区间长度≤64 直接统计，只把会访问的值槽
先清零；所有清零在计数前完成，重复值不会在中途被清掉。

AVX2 八槽各对应一个值 ID 的频数，向量做“右前缀减左前缀”，同时保留
每槽遇到的最大数和 ID，最后水平规约取得整体最大者。
它不是八个查询并行，而是同一查询的八个候选值一起计数。
时间/空间约为 `O(N+Nσ/B)` 建表、O(σ+B) 查询（向量减少常数），
B 为 1 或 32；σ 过大就不会用这条路线。

### 全局频率小：存“f 次相同值最早到哪结束”

若 F≤128，可以换一个维度：对每个左端 l 和次数 f≥2，保存
`E_f(l)=从 l 开始能容纳 f 次某个相同值的最早末位置`，不存在记 N。
那么区间 `[l,r)` 存在至少 f 次的值，当且仅当 `E_f(l)<r`。
E 随 f 单调，所以可二分最大合法 f，并由该末位置的值给出众数。

示例在 l=2 时，值 2 的连续出现 `[2,5]` 最早提供两次，故 E₂(2)=5；
值 1 的 `[4,6,7]` 提供三次，E₃(2)=7；四次不可能，E₄(2)=N。
对 r=8，最大合法 f 为 3，末位置 7 的值是 1，正是答案。

构造从右往左扫描。加入一个起点 i 时，其值的后续第 f-1 次出现位置
提供一个新证据，拿它与此前“起点大于 i”的最早证据取 min，复制成该行。
这是完整的归纳不变量，不是抽样。最多存 N(F-1) 个整数，
建表 O(NF)、每问 O(log F)；F 很小时比所有位置块对轻得多，F 大则禁用。

### 少数高频值：单独计数，再查低频层

出现次数超过 128 的值称为重值；这只是按**值频率**分类，与树的重链
剖分无关。重值不超过 32 个、且占值种类足够少时，为它们存每位置的
频数前缀，轻值继续用 E_f 表。
查询先精确统计所有重值，当前最好次数若已不小于轻值的全局上界，直接
返回；否则在轻值层里二分还有没有更好者。

默认判据还考虑重值的总出现量是否至少占 N/4，从而在“小值域前缀”与
“重轻分开”之间选路。这些阈值只影响时间/空间，不影响答案语义。
若重值数为 H、轻值最高频率为 F_l，资源约为
O(N(H+F_l)) 建表/存储、O(H+log F_l) 查询；这里 H≤32、F_l≤128。

### 其他输入：块表，并可用全局上界证书早返

若以上分支均不适用，退回前面推导的块众数表，块宽为不超过 sqrt(N)
的二次幂。表只保存左块≤右块的三角部分，减少无效下三角槽。
查询仍用出现位置组检查两端候选。

另有一个可选证书：全局最大频数 F 是任何子区间频数的上界。如果某个
全局众数的第一次到最后一次出现都包含在查询内，就已达到上界 F，
无需查块表。源码对这些值的完整支撑区间构造后缀最小右端
certificate[l]，若它小于 r，返回那个末位置的值和 F。
仅在有全局众数集中于较短位置段时才分配这张 O(N) 表；这仍是确定性
包含关系验证，不是根据一段看起来像连续游程就猜答案。

所以 19 ms 可能来自大量查询走特殊形状的短路径，不能归因于一个通用
RMQ 或一句“用了 AVX2”。I/O 也采用 Linux 映射与批量数值解析。

## #401534 / #393941：固定使用块表的清楚对照

两份 `main` 都构造 `toy::StaticRangeMode`，核心与调用代码相同，差别
主要是打包注释。值排序压缩后，出现位置存一条 grouped_positions，
group_start 划分每个值的段，position_in_group 让边缘位置 O(1) 找到
对应的出现序号，不必每次 lower_bound。

σ≤64 时块宽取 sqrt(N) 向上的二次幂，其他情况向下取二次幂。
较宽的块减少建表块对，较窄的块减少边缘扫描；这是实际预设的取舍，
不是每个输入上都证明最优。block_modes 分配完整块数平方的矩形表，
构造只填写有效的上三角位置。

查询的左候选先向后扩展，右候选先向前扩展，得准确频数后才能触发
`2*count≥length` 的早停。构造 `O(N²/B+N log N)`、每问 O(B)，
空间 `O(N+(N/B)²)`，可在线查询。文件里另一套 mode 维护器未被 main
选择。读写使用 direct_mapping 和缓冲 Writer。

## #211820：同一不变量，接口右端包含

main 实例化 `OY::RangeMode<uint32_t>`，把输入 `[l,r)` 转成
`query(l,r-1)`。内部保存 m_pos/m_start/m_pos2、每完整块区间的值与

77 ms 与 74 ms 不同就说用了新的众数索引。

## #212105：实际调用 solve2 的回滚 Mo

`main` 先收齐查询，调用 `OFFLINEMODE::Solver::solve2`。
文件还有 solve 的普通 Mo 路线，但此处没有调用。
solve2 按左块分组、右端升序，同块短查询直接统计再减掉；长查询保留
单调增加的右侧计数，把左边缘临时加入，下一问前撤销左边缘并恢复
base_c/base_mx。与上游用 history 保存每次临时添加相比，它直接按
位置区间减计数，避免额外历史条目，但仍不能任意删除长期右侧再寻找众数。

它选择的基准左位置是 `start+block_size-1`，不是所有版本都统一写作
块右端；应按其 l/r 游标约定读加减循环。所有短查询先处理、长查询右端
单调，保证被恢复的 base 状态对应正确的长期区间。
时间为常见的 `O(N²/B+QB+Q log Q)`，空间 O(N+Q)，最后按 ID 输出。

Q=0 是题目允许的边界，但 solve2 的块宽表达式直接除以 sqrt(查询数)，
缺少上游 calc 的空查询提前返回。迁移应先处理空列表，避免除以零及
非有限浮点数转整数的实现依赖；本篇没有把它写成已复现的 OJ 错误。
