# Static Range LIS Query：从最小结尾到临界位置与半局部合并

## 题意：保持原顺序，允许空区间

输入是 `0…N-1` 的一个排列 P，查询半开区间 `[l,r)` 中最长严格递增
子序列的长度。子序列可以跳过元素，但不能重排位置；子串则不能跳过，
二者不同。`N,Q≤100000`，允许 `l=r`，答案为 0。
见 [`task.md`](../../../upstream/data_structure/static_range_lis_query/task.md)、
[`info.toml`](../../../upstream/data_structure/static_range_lis_query/info.toml)。

```text
输入                 输出
5 5                  3
2 0 4 1 3            2
0 5                  2
1 4                  1
2 5                  0
0 2
3 3
```

全数组可选位置 1、3、4 的值 `[0,1,3]`，长 3。
`[1,4)` 的 `[0,4,1]` 可取 `[0,4]` 或 `[0,1]`，长 2；
`[2,5)` 的 `[4,1,3]` 可取 `[1,3]`；`[0,2)` 的 `[2,0]` 只能取一个。
把区间直接排序再计数会把位置条件丢掉，不能求 LIS。

## 单个区间的基线：保留每种长度的最小结尾

最直接的 DP 是 `dp[i]=1+max(dp[j])`，其中 j<i 且 P[j]<P[i]，
每问长度 m 需要 O(m²)。更快的单问方法维护 tails[t]：在已读前缀里，
长 t+1 的递增子序列所能达到的最小结尾。新值 x 替换第一个不小于 x
的结尾，若没有则追加。较小结尾更容易接后续元素，因此只保留最小者不损失
最优长度；tails 递增，可二分定位，每问 O(m log m)。

示例依次变为 `[2]→[0]→[0,4]→[0,1]→[0,1,3]`，长度为 3。
tails 是每个长度的最优摘要，不保证它的各项来自同一条实际子序列。
十万次长区间仍会重复处理数十亿个位置，需共享不同左端、右端之间的工作。

## 先理解所有左端一起维护的“阈值槽”

固定已经处理的右端 r，令 `F_v(l)` 为 `[l,r)` 中只允许使用值不大于 v
时的 LIS 长度，`F_-1(l)=0`。从允许值 v-1 扩大到 v，只新增排列中
至多一个位置，因此长度最多增 1。它的增量可表示为一个临界位置：

```text
F_v(l)-F_(v-1)(l) = 1，当且仅当 l < w[v]
```

槽 w[v]=0 表示这个值阈值不带来增量；正值采用“原位置加一”作为标签。
把所有值阈值的增量相加，中间 F 项抵消，得到
`LIS(l,r)=#{v : w[v]>l}`。因此 w 存的不是一条 LIS 的元素，
而是**同时服务所有左端 l 的临界位置集合**。

下面从递推直接证明这种阈值表示在每次加元素后仍然成立，不把它当作需要
预先知道的“半局部 LIS 定理”。

### 加入新值后的 min/max 传播从哪里来

加入新位置 r、值 x，先只考虑旧边界 `0≤l≤r`。
对 v<x，允许值里没有新 x，F 不变；对 v≥x，新最优序列或者不取新点，
或者以 x 结尾，前面只能接值小于 x 的序列。因此

```text
F'_v(l) = max(F_v(l), F_(x-1)(l)+1)，v≥x。
```

P 是排列，x 以前没出现，所以旧 `F_x=F_(x-1)`，新槽可直接设
`w[x]=r+1`。接着看一个 v>x。令 c 为旧槽 x+1…v-1 中标签的最大值。
旧 `F_(v-1)` 比 `F_(x-1)` 已经多出至少 1，当且仅当 l<c。
若 l≥c，这一步 max 会把新旧两个阈值都抬到同一高度，v 的增量消失；
若 l<c，v 仍可保留原增量。故

```text
新 w[v] = min(旧 w[v],c)
新 c    = max(旧 w[v],c)
```

初始 c=0，从 x+1 向更大值依次传播即可。新的空区间 l=r+1 时所有
标签都不大于 l，计数为 0，也自然符合定义。
这正是快解中的“若槽值比携带值大就交换”，并不是普通 tails 的二分插入。

```text
w[x]=r+1
carry=0
for v=x+1..N-1:
    if w[v]>carry: swap(w[v],carry)
最终 carry 若非0，表示被逐出的旧位置标签
```

每个 min/max 门保持槽与 carry 的多重集合，因此整个传播只从活动标签中
删掉最终 carry，再加入新标签 r+1。正标签始终不重复，一旦被逐出不会重新
加入。用 Fenwick 给活动位置记 1，就能在当前右端回答任意左端的区间计数。

### 示例的每一步槽状态

对 P=`[2,0,4,1,3]`，槽顺序为值 0…4，正标签减一才是原位置：

| 加入位置 / 值 | 传播后的 w | 逐出的原位置 | 活动原位置 |
|---|---|---|---|
| `0 / 2` | `[0,0,1,0,0]` | 无 | `{0}` |
| `1 / 0` | `[2,0,0,0,0]` | 0 | `{1}` |
| `2 / 4` | `[2,0,0,0,3]` | 无 | `{1,2}` |
| `3 / 1` | `[2,4,0,0,0]` | 2 | `{1,3}` |
| `4 / 3` | `[2,4,0,5,0]` | 无 | `{1,3,4}` |

处理完位置 3，活动位置在 `[1,4)` 有 1、3 两个，LIS 为 2；
处理完整个数组，在 `[2,5)` 有 3、4 两个，LIS 也为 2。
直接传播每次最多扫 N 个值槽，总计 O(N²)。这是下面两类快算法共同要
加速的明确过程：一类分块维护传播，另一类一次构造所有逐出事件。

## 把全部区间答案压成一组二维临界点

每个原位置 i 最初会成为活动标签，之后至多被逐出一次。定义
`E[i]=逐出它的新位置`，从未逐出记为无穷。示例只有事件
`E[0]=1、E[2]=3`，其他为无穷。

右端为 r 时，原区间 `[l,r)` 的 r-l 个位置里，已经失效的恰是
`i≥l 且 E[i]<r` 的位置，所以

```text
LIS(l,r) = (r-l) - #{i≥l : E[i]<r}
```

把每个有限事件画成点 `(i,E[i])`，问题变成二维计数：横坐标在 `[l,N)`、
纵坐标小于 r 的点有多少。每行、每列至多一个有限点，因为一个旧位置
只被删除一次、一个新位置最多逐出一个旧标签。
这就是一个长度 N 的部分排列；无需存全部 N² 个区间答案。

例如 `[1,4)` 长 3，只包含事件 `(2,3)` 的影响，答案 `3-1=2`。
空区间不会被任何事件命中，因为真实事件总有 E[i]>i。
保留所有事件后，可用波列矩阵回答 `count_less_than(l,N,r)`，每问
O(log N)，不再需要提前知道查询。其 rank/区间映射推导见
[`Range Kth Smallest`](../range_kth_smallest/analysis.md)，这里只选择计数接口。

## 上游怎样更快构造事件：按值分治与最小加法积

上游 [`correct.cpp`](../../../upstream/data_structure/static_range_lis_query/sol/correct.cpp)
实际走 `range_lis_query→convert→seaweed_doubling→subunit_monge_dmul`，
并没有维护后文的根号堆。seaweed 是边界路径的配对表示，Monge 是其
矩阵满足的四点不等式；先解释它们在这里计算哪一个量。

### 按值分半，递增序列只能先低值、后高值

把值域分成小于 mid 和不小于 mid 两半。任意递增子序列中，低值都在
高值之前，因此可在位置 t 切开：

```text
L_all(l,r) = max(l≤t≤r) [L_low(l,t)+L_high(t,r)]
```

示例全区间 `[0,5)`，低值为 0、1，高值为 2、3、4：

| 切点 t | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|---:|
| 低值部分 `L_low(0,t)` | 0 | 0 | 1 | 1 | 2 | 2 |
| 高值部分 `L_high(t,5)` | 2 | 1 | 1 | 1 | 1 | 0 |
| 合计 | 2 | 1 | 2 | 2 | 3 | 2 |

最优 t=4，取低值 `[0,1]` 后接高值 `[3]`。
令缺少量 `D(l,r)=(r-l)-L(l,r)`，上式变成

```text
D_all(l,r)=min_t [D_low(l,t)+D_high(t,r)]。
```

这是“最小加法积”：把普通矩阵乘法的乘、加换成加、取最小。
若直接枚举 l、r、t，仍太慢；可利用 D 的边界变化只由上面的临界点决定。

### 为什么这类表有单调边界，而不用枚举每个切点

LIS 也等于区间序列与有序序列 `[0,1,…,N-1]` 的最长公共子序列。
画一个网格：横向走过原位置，纵向走过有序值；跳过元素的边得分 0，
相等处走对角线得分 1，最高分路径就是 LIS。
取两个端点交错的最优路径，它们必相交；从交点交换尾段仍是合法路径，
总分不变。因此有

```text
L(l,r)+L(l+1,r+1) ≥ L(l,r+1)+L(l+1,r)
```

换成 D，方向相反，这就是 Monge 四点性质。其相邻差分又只有 0/1，
临界点每行每列至多一个，所以可用部分排列描述边界。
分治合并时，最佳切点边界随行单调移动；只维护边界转折，不把完整
N×N 的 D 表展开。这是 unit/subunit-Monge 乘法要利用的结构。

### 对应源码的三个阶段

1. `seaweed_doubling` 按 P 的值分为 lo、hi，保留 lo_map、hi_map
   将各半的局部位置映回原位置。递归得到两半的边界配对；扩到完整位置
   时，未属于该半的槽用恒等连线填充，有效缺口保留 none=-1。
2. `subunit_monge_dmul` 把带缺口的配对补成完整排列，保存有效行列
   映射与逆排列，调用完整积，再裁回原来的有效位置。填充节点只是辅助
   连线，不是原序列新增的值，不能把 none 当作数值 -1 参加 LIS。
3. `unit_monge_dmul` 再按连线标签分成两半递归，映回 c_row/c_col，
   然后从最后一行向上扫描。neg、pos 两游标的 col 只向右移动，delta
   记录当前分界处的贡献差；right 根据 b 的半区和 c_col 所在侧加一，
   up 根据 a 的半区和 c_row 所在侧减一。两个零差边界交错时重接该行
   配对。每个游标至多走 N 列，故这一合并扫描是线性的，不枚举全部 t。

完整乘法递推 `T(N)=2T(N/2)+O(N)`，为 O(N log N)；外面还有一次
按值分治，每层要做这些乘法，所以本源码整体构造为 O(N log²N)，
之后波列矩阵构造 O(N log N)、每问 O(log N)。临时数组按递归规模
分配/复用，核心存储为 O(N) 个配对与位图索引，未存平方矩阵。

本篇用上游的实际 seaweed_doubling 在五项例子上核对，返回
`[1,-1,3,-1,-1]`，与逐出事件表一致。convert 把 -1 改成 N，方便
后面的“小于 r”计数不命中无限事件。位图 set 的可移植写法应移位
`i%32`；原稿直接写 `uint(1)<<i`，不能把机器可能屏蔽高位的行为当成
标准 C++ 对超宽移位的保证。

## 另一条路线：给 min/max 传播按值分块

一整个块收到 carry=c 后，连续做 `slot=min(slot,c)、c=max(slot,c)`。
从多重集合看，若块最大值≤c，块完全不变；否则整块只是在集合层面
把一个最大值换成 c，并把旧最大值传到下一块。
所以完整块只需最大堆，不必逐槽走 B 步。**槽顺序仍会改变**，不能只
改堆却永远不恢复槽，否则将来 x 落在块中间时无法处理局部后缀。

为此记下进入块的延迟替换。需要展开块时，从左到右看每个槽，把它与
待办最小值比较，较小的留在槽，较大的回到待办堆。为什么可这样批量做？
原来每次传播到第一个槽，最终留下所有输入与原槽中的最小者，其他数
继续流向右边；按槽归纳，同样的 min/max 网络只需要待办的多重集合，
不必重新播放每次完整传播。

新值 x 所在块必须展开并扫描 x 后面的槽；后面的完整块只执行一次
“比较最大值、必要时替换堆顶”。查询按右端分桶，处理新位置时向活动
Fenwick 插入新位置、删除最终 carry，再回答这一右端的所有查询。
这样用离线 O(N+Q) 查询组织替代永久的事件二维索引。

### #331206：堆元素最低位标记延迟替换

值与位置都改成一基，块宽 floor(sqrt(N))。每块 Q 是最大堆，元素编码
为 `位置标签<<1`；完整块被替换时写成 `新标签<<1|1`，最低位记“此项
还没落实到 b 的槽”。旧的延迟项若后来又被逐出，会自然离开这个堆，
不用另外永久保留已经失效的待办记录。vis 表示是否需要 materialize。

展开时只收集堆中仍有效的带标记值，交给小根堆 pq，从左到右落实到 b；
处理完当前块后重新 make_heap，清除标记。堆固定容量约 320，依赖本题
N≤100000 和根号块长。相较普通 priority_queue，它合并“弹出堆顶再
压入”的操作为 replace，并复用数组。没有 SIMD 或更改 LIS 定义。

活动位置使用方向反过来的 Fenwick：update 向较小下标跳，query 向大
下标跳，返回活动位置后缀计数。查询先按右端计数排序，再用一个指针顺序
回答；这些只是计数组织上的变化。

**已复现的边界问题：**N=1、P=[0]，查询依次为 `[0,0)`、`[0,1)`，
应输出 0、1。未改源码以 `g++ -std=c++23 -O2` 编译，实际输出 0、0。
计数排序把 r=0 查询放在最前，而扫描从右端 1 开始，答案指针永远卡在
这条 r=0 记录，后面查询都没有被处理。应先处理/跳过空的初始右端桶。
这是一份最小正确性核对，不是性能测试，也未在本篇向 OJ 提交。

### #393940：分离的两个堆与一次性查询桶

`main→static_range_lis_permutation→PermutationLisBumping` 真正
使用自写 IntHeap。最大堆只保留非零活动标签；每次完整块替换把传入值
记入独立最小堆，carry=0 时从最大堆直接删除最大者。materialize 用
push_pop，rebuild 只在首块确实发生交换时执行，避免无条件重建。

right=0 的空查询不进扫描，answers 的默认 0 已是正确答案，不阻塞后续桶。

初始 reserve(B) 只是预留容量，不是待办记录个数的上限。若用 E 表示
尚未物化的延迟记录，额外堆空间需计入 E；不能仅由 reserve 推出严格
O(N) 空间。自写堆减少重新分配和复合堆操作常数，但本篇未给出所有输入
下 E 的更紧上界。I/O 使用 direct_mapping 与固定字段解析。

### #324427：相同传播，计数“已经逐出的位置”

这份用标准 priority_queue 分别存每块最大值和延迟最小值，展开时将
旧非零槽压入待办堆、取最小者写回，结束后清空待办，再按需要重建最大堆。
它不把新位置加入活动 BIT，而只在最终 carry 非零时给“被删位置”加一。
每问初值为区间长度，再减掉左端以后被删的数量，正是事件公式的离线形式。
查询挂 q[right]，空区间的预填长度为 0，所以 r=0 不会卡住别的查询。
cin/cout 关闭同步；语义与前两份同族，堆分配、批次与读写有所不同。

对这些堆分块实现，完整块约 N/B 个，每个真正替换需堆操作，首块展开也
可能花 O(B log B)，不能把所有堆工作直接写成 O(B)。固定容量/有效标签
版本可用 `O(N(B+N/B)log(B+1)+Q log N)` 作为保守上界，取根号块长得到
带堆对数因子的根号算法。分离待办堆版还需按其实际待办规模计堆操作和空间。
它们实际常因块最大值不超过 carry 而快速跳过；快照时间不是最坏复杂度证明。

### #382253 / #346156：把事件表转置后做在线计数

两份 main 真正构造 StaticRangeLIS，再逐条 query，不预读查询。
其 seaweed 合并用迭代倍长块、reca/recb、ida/idb 和辅助布尔数组实现
同类最小加法边界合并；没有调用分块堆。生成的数组 C 按新右端位置索引：
若该位置逐出了 e，记 C=e+1；无逐出记 0。即前面 E 的转置并加一。
于是查询公式变成

```text
LIS(l,r) = count(j<r 且 C[j]<l+1) - l。
```

示例 C=`[0,1,0,3,0]`。问 `[1,4)`，前四项中小于 2 的有三个，减 1
得到 2。这个公式与上游 E 的矩形计数等价，但端点和哨兵不同，不能混用。
波列矩阵固定 17 位，足够表示 N≤100000 的 C；一次查询 17 层 rank。

外层按值域合并有 log N 层，每次内部 seaweed_prod 又按子段长度倍增，
每内部层线性扫描，因此从实际嵌套循环得到 O(N log²N) 构造界。
#382253 文件注释中的 O(N log N) 不能直接覆盖整套双层合并。
两份主内核同形，#382253 使用 fread 读取、string 收集输出，#346156
由其模板包装标准 cin/cout。模板中的额外泛型工具不算每问执行成本。
