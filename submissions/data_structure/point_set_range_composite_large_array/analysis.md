# 十亿长度数组上的区间复合：稀疏在线树与离线坐标压缩

## 1. 与普通版的关键区别

操作仍是单点替换f[p](x)=cx+d，以及按顺序执行[l,r)的全部函数。
但[本题](../../../upstream/data_structure/point_set_range_composite_large_array/task.md)
初始每个位置都是恒等函数f[i](x)=x，且
[N最大为10⁹、Q最大为500000](../../../upstream/data_structure/point_set_range_composite_large_array/info.toml)。
输入没有N行初值。若按N开普通线段树，时间与内存都会浪费在永远不变的位置上。

例如N=10⁹，只将位置2设为f(x)=2x+1、位置9设为g(x)=3x+4：

| 查询，x=5 | 真正改变x的函数 | 答案 |
|---|---|---:|
| [0,5) | f | 11 |
| [3,100) | g | 19 |
| [0,100) | f后g | 37 |
| [3,9) | 无 | 5 |

中间哪怕隔了几亿个恒等函数，也可以直接跳过。
函数合并方向及普通线段树基础见
[单点替换区间复合教程](../point_set_range_composite/analysis.md)。

## 2. 第一种思路：只为真正出现的坐标存节点

假设已经写入过U个不同位置。它们之外永远是单位元，
所以可以维护稀疏搜索结构，每个节点存一个坐标和函数，
并缓存按坐标排序后的子树总复合。查询忽略空节点，
完整覆盖一个子树时直接使用其聚合。

常见的动态线段树沿[0,N)不断二分，只创建需要的路径，
但这种最直接版本可能每次新增O(log N)个节点。
上游使用了更紧凑的变体，不能把它的空间误写成必然O(U log N)。

## 3. 上游 correct.cpp：每个新坐标只创建一个节点

[实际源码](../../../upstream/data_structure/point_set_range_composite_large_array/sol/correct.cpp)
实例化Dynamic_SegTree_Sparse<Monoid_Affine,false>，
预留Q个Node，根最初为nullptr。
每个Node保存idx、该位置函数x、左右孩子、子树聚合prod。
空子树表示所有位置为恒等函数。

插入时仍携带当前坐标区间[l,r)，以mid二分：

- 遇空节点，直接把当前坐标和函数放进去，不再一路创建到单位区间。
- 坐标与节点idx相同，只替换函数。
- 目标在左半且比当前idx大时，交换目标与节点内容，把较小坐标继续插入左边。
- 目标在右半且比当前idx小时，对称地交换，把较大坐标继续插入右边。

这些交换让节点及左右子树保持键的有序关系，同时每深入一级都将
**坐标域**减半。重新计算prod时，先左子树、再节点自身、再右子树，
因此复合顺序与原数组相同。

例如域[0,16)先存坐标2，再插坐标6。两者都在左半，
节点保留较大的6，把2下降到[0,8)的左结构；
随后插入9进入右半，顺序仍为2、6、9。
节点位置不等于固定的mid，但它携带的域边界仍限制递归深度。

每个新坐标恰创建一个Node，已有坐标只替换，所以节点数≤U≤Q；
本题PERSISTENT=false，copy_node直接返回原指针，没有版本复制。
高度至多O(log N)，更新和区间查询O(log N)，空间O(Q)。
查询会按“左、节点、右”有序收集完整覆盖块。

上游因此已经利用稀疏性。它保留在线处理能力，代价是指针访问、
较多字段和依赖原坐标域的树高。当前前五则都预读操作，改用压缩后的连续数组树。

## 4. 离线压缩：只让可能被修改的位置占一个叶子

把所有设置操作的位置收集、排序、去重，得到S。
不在S中的函数一直是单位元，因此可以删掉这些位置，
而不改变任何区间的复合。注意“删掉间隔”不改变函数先后关系。

S=[2,9]时，位置2映射到0，位置9映射到1；
区间边界t映射为lower_bound(S,t)，即S中严格小于t的元素个数。

| 原区间 | 压缩区间 | 含义 |
|---|---|---|
| [0,5) | [0,1) | 只含位置2 |
| [3,100) | [1,2) | 只含位置9 |
| [3,9) | [1,1) | 空，返回x |
| [9,10) | [1,2) | 左端等于9，应该包含9 |

左右边界都必须用lower_bound；右端r本来不包含，不能误用upper_bound。
即使原题保证l<r，压缩后也可能为空。
压缩树初始全部为恒等函数，然后仍按原始时间顺序回放操作：
预先知道未来会修改位置9，不表示它在真正那次更新之前就不再是单位元。

这种做法需要完整操作流，额外存储O(Q)，
树大小由N变成U。普通比较排序预处理O(Q log Q)，
之后每次操作O(log U)，不再为十亿坐标域分配空间。

## 5. 不对每个端点二分：将更新与边界放进同一有序事件流

前三份C++快解把事件打包成64位：
低32位是坐标，高位包含原操作编号与“设置/左边界/右边界”标记。
按坐标排序后，从小到大扫描，m表示已经遇到的不同设置位置数，
lst保存最后一个设置坐标。

遇设置事件时，仅在坐标不同于lst时增加m，并赋压缩下标m−1。
遇查询边界x时，赋：

~~~text
lower_bound_index = m − (x == lst)
~~~

若已有设置事件恰在x，m已经把它算进去，减一得到严格小于x的数量；
若同坐标设置事件还未出现，m本来就没算它。
因此同坐标的事件不管谁先遇到，都能得到正确边界。
这里排序的是坐标映射元信息，真正的函数更新仍按原操作编号回放。

### 5.1 两轮基数排序为何够用

坐标不超过10⁹<2³⁰，所以可把键分成高、低两个15位块。
先按低15位计数排序，再稳定地按高15位排序，即得到完整坐标顺序。
稳定性使第二轮相同高块保留低块顺序。
每轮桶数32768，总代价O(Q+2¹⁵)，每个事件只有固定次数搬运。

小事件数下清零大桶不划算，源码会转std::stable_sort；
阈值是实现选择。某些函数虽然命名radix_sort_u32，
当前N=15实例化只容纳30位键，安全性来自本题坐标范围，
不能把同一实例直接套到任意32位整数。

### #361521 / #390915：映射元信息与操作流分开

qry保存原顺序的操作，aux保存带回指标签的坐标事件。
排序扫描时直接修改qry中的压缩位置，
之后每条操作无需再做坐标二分。
SegTree初始化为恒等元，查询调用evaluate(a,b,x,eval)，
按有序覆盖节点直接更新x，避免先构造完整复合函数。
文件里一般prod接口未被这条查询路径调用。

两份规范化换行后相同。代码在排序小输入时用
n<Mask/8判断是否切换比较排序；当前15位桶配合30位坐标是明确约束。
FastIO同时参与94/96ms端到端时间。

### #393916：相同压缩原则，空区间显式返回

main把操作记录为自有Operation，事件同样低位坐标、高位标签，
调用radix_sort_u32<30,15>明确键只有30位。
一次扫描只为不同设置位置增加compressed_size，
查询边界使用同一个“是否等于previous”的修正。

回放时，若压缩后left==right，直接输出原x；
否则AffineSegmentTree::apply利用边界位差按顺序访问节点。
这是个人提交的实际入口，不能因文件打包其他仿射结构就误标为动态指针树。

### #405490：排序更少的键，再批量搜索所有端点

Rust只收集设置位置values，radix_sort后dedup，
构建StaticSearch::from_sorted。
再把全部更新位置和查询边界排入endpoints，
通过lower_bound_batch一次批量求出positions，供按序回放使用。

32位键对应StaticSearchTree<u32,16>，每层宽节点用标量或
运行时选择的AVX2/AVX512后端找第一个不小于目标的槽；
批量接口交错多条独立搜索，以隐藏加载延迟。
这仍是每端点的分层搜索，不能写成一次线性归并。
它减少被排序的事件数量，换来搜索索引和批量lower_bound成本。
回放查询用seg.fold得到函数(a,b)，再算a*x+b，
与前三份的直接节点求值不同。

### #400994：同一主流程，但不能声称整个文件相同

同样缓存qry/aux、两轮15位排序、扫描映射、再调用树的evaluate。
I/O类型包装、缓冲政策和小输入排序判断有所修改；
其Mask/n>8表达式与第一名的n<Mask/8也不完全等同。
本题Q≥1，每条操作至少提供一个坐标事件，所以该入口的n不为0；
不能将泛用函数可能的空数组边界误当成本题已触发问题。

## 7. 在线与离线的实际取舍

| 方案 | 预读所有操作 | 主存储 | 主要成本 |
|---|---|---|---|
| 上游稀疏动态树 | 不需要 | O(U)节点，池按Q预留 | O(log N)指针路径与有序聚合 |
| 事件压缩+连续树 | 需要 | O(Q)操作/事件+O(U)树 | 固定轮数排序及O(log U)回放 |
| 更新坐标+批量搜索 | 需要 | O(Q)操作/端点+O(U)索引/树 | 排序U个键、批量搜索、树查询 |

当前前五都离线收集坐标，不说明在线路线在所有工作负载下都较差，
也不说明其他在线快提交已被排除。若后续输入依赖先前输出，
这些离线预处理就不能原样使用。

验证重点是无设置操作、同位置多次覆盖、查询边界等于设置坐标、
端点位于巨大空隙、压缩后空区间和未来更新尚未生效的历史状态。
本仓库的[本地教程](../../../problems/data_structure/point_set_range_composite_large_array/tutorial.md)
保存既有实现与实验；本页核对小例、坐标扫描不变量和五份源码，
没有新增性能benchmark。
