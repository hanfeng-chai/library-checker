# 动态加点、矩形求和：预登记坐标的二维结构与时间分治

## 1. 静态矩形题增加了“何时出现”

最初有N个带权点，之后可新增一个点，或查询[l,r)×[d,u)内当前点的权重和。
同坐标新增仍算另一点，权重相加，见
[题面](../../../upstream/data_structure/point_add_rectangle_sum/task.md)。
N,Q各至多100000，坐标和权重≤10⁹。

初始有(1,1,2)、(4,2,7)：

| 操作 | [0,3)×[0,3)内的点权重 | 输出 |
|---|---|---:|
| 查询该矩形 | 2 | 2 |
| 加点(2,2,5) | 2+5 | |
| 再查询 | 2+5 | 7 |
| 加点(1,1,3) | 2+5+3 | |
| 再查询 | 2+5+3 | 10 |

第一问不能看到未来的5和3，也不能把最后一次同坐标的3当成覆盖旧值2。
朴素地在每次查询检查此前所有点，最坏O((N+Q)Q)。
静态题的x扫描可参考[矩形求和教程](../rectangle_sum/analysis.md)；
这里还需要保证时间条件。

## 2. 上游：外层按x的线段树，每个节点再维护y

[correct.cpp](../../../upstream/data_structure/point_add_rectangle_sum/sol/correct.cpp)
先读完整操作流，将初始点和未来加点的x全部收集排序。
外层线段树按压缩x建立。对于每个可能加点(x,y)，
沿外层叶到根，把y登记到这些节点自己的列表中。
每个节点随后排序自己的y列表，再建立内层线段树。

真正新增权重时：

~~~text
找到该点的外层x叶
沿叶到根，每层在该节点的y树中给对应位置加w
~~~

矩形查询将x范围拆为O(log K)个外层节点，
分别在其y树中求[d,u)的和，K为总登记点数的量级。
每次更新/查询O(log²K)，登记与主存储O(K log K)。
上游先批量灌初值到内层叶子，再自底向上建立内层和，避免对初值重复做完整更新。

重要的是：**上游也预读未来加点坐标**，不是完全不知未来的动态空间树。
预登记只提供存储位置，未来点的权重尚未生效；
之后仍按时间顺序回放操作。当前实现还保留了排序列表中的重复坐标，
lower_bound把重复项映射到第一个位置，正确但可能留下一些不用的槽。

## 3. 带可修改权重的波列矩阵：让两维关系保持在连续数组里

先将所有可能出现的点按x排序。一个矩形的x条件就变成一个连续位置区间[L,R)；
每个位置带一个y值和一个可修改权重。
问题变为：“在[L,R)中，y位于[d,u)的权重和”。

### 3.1 稳定分流使子区间仍可表示为两个端点

把y压缩为整数，按最高位将所有位置稳定分成0区和1区，
同时保留这一层原顺序的位图。若rank1(t)表示前t位中1的个数，
区间[L,R)的0元素在重排后位于

~~~text
[L-rank1(L), R-rank1(R))
~~~

1元素则位于

~~~text
[zero_count+rank1(L), zero_count+rank1(R))
~~~

稳定性保证同一类元素的相对次序不变，所以无需存每个查询命中的位置列表。
继续处理更低位，便得到波列矩阵。

例如按x排好后的y为[2,0,1,2]、权重为[2,5,7,4]，
最高位的0/1为[1,0,0,1]，
稳定重排得到y=[0,1|2,2]、权重=[5,7|2,4]。
原区间[1,4)中y<2的元素全部在0区间[0,2)，权重为5+7=12。

### 3.2 为什么需要每层Fenwick，而不再是静态前缀和

若权重永不改变，每层存普通前缀和即可。
本题会激活新权重，所以把每层所需权重序列交给Fenwick。
一个点的y路径固定，新增权重时按rank映射找到它在各层的位置并更新；
查询值上界时，遇到上界位为1，就加入当前全部0分支的权重，
再去1分支继续，位为0则只去0分支。

层数H约为log D，D为y等级数；每层Fenwick操作O(log K)，
总操作O(H log K)，空间O(KH)。
相比树套树，它减少了许多小树、指针和每个内层坐标的重新二分，
但不是把所有动态矩形查询变成了常数时间。

第一名进一步只给每层0分支存Fenwick，
因为“求小于上界”的分解只会整块加入0分支。
点落在1分支时只更新下标映射，跳过该层的权重更新。
每个层的实际节省取决于位分布，不能无条件说恰好少一半空间。

## 4. 另一条路线：按时间分治，只计算左边加点对右边查询的贡献

把初始点视为最早的一批加点事件，再接上全部操作。
时间分治（常称CDQ）将事件序列分成左右两半：

- 左半内部的贡献递归处理；
- 右半内部的贡献递归处理；
- 跨两半只可能是“左半加点影响右半查询”。

跨半贡献已不需要再判断时间，可以用静态矩形扫描：
把左半点和右半矩形的两个x事件排序，
用y-Fenwick累计，然后撤销刚加入的权重。
每个合法“点→后来查询”对，在两者第一次被时间划分分开的节点恰好计算一次，
因此不会漏算或重复。

例如时间序列[加A、问1、加B、问2]：
顶层只算A对问2；左递归算A对问1，右递归算B对问2。
未来的B永远不进入问1。

如果每个递归节点重新排序事件并进行Fenwick扫描，
总计可界为O(T log²T)，T=N+Q；
复用事件缓冲与一条Fenwick，可用O(T)级工作空间。
这是完全离线计算答案的方案，而不是预建坐标后逐条即时求值。

### #401818：未来加点占位置，但初始权重为0

solve读完xyw和queries，为每个未来Add追加一个(x,y,0)记录，
按x基数排序，并记录原点编号到新位置的positions。
同坐标的多个加入记录仍分别保留，时序由各自的权重激活控制。
随后WaveletMatrix::new压缩y，
build_point_add从各层重排后的**0分支**权重构造Fenwick。

回放Add时按原加点编号取positions并加w；
Sum先用xs的两个partition_point确定x区间，再fold_range(d..u,L..R)。
fold_range先沿y上下界共同的高位路径下降，再处理分叉两边，
避免无条件把两条完整前缀都重复走一遍。

y压缩去重，bit_length使用bit_width(D)，
在D恰为二次幂时保留一层全0位，以便正确表示值上界D。
文件同时构造/定义了二位索引等其他API，
但动态权重update/fold实际逐位访问bit_vectors，不能误标为四路权重查询。
构造的稳定分流有CPU分派，端到端时间还包含压缩与快I/O。

### #206958 / #404520：按每条点记录保留y秩

main把未来加点用权重0登记到PARSC2D::Table<…,true>，
prepare排序y并给每条记录分配顺序编号，然后按x排序。
m_ys保留重复y，所以即使同值也可有不同内部秩；
lower_bound/upper_bound会把同值的所有记录都包括进来。
这与第一名按不同y值压缩的层数/布局条件不同。

HasModify=true选择SimpleBIT作为每层权重表，
add_point_value通过原始point_id→x排序位置映射更新相应路径。
query接口采用闭区间，main传入r−1、u−1来对应题目半开边界。
两份执行代码相同，151/155ms不能解释为算法差异。
名称PARSC2D并不代表本题权重只能静态不变，需看实际模板参数。

### #401366：真正的时间分治

PointAddRectangleSum::solve先压缩点和查询边界的y，
dfs分左右事件，取左半Add与右半Query建立临时扫描序列。
点的第二排序字段用I=2³⁰作为哨兵，
查询使用小得多的压缩y下界，因此同x时查询先于加点，
保证矩形的右边界不包含。

每问生成左减/右加两个事件，扫描后将本轮加入的所有点以−w撤销，
让复用的Fenwick回到进入递归前的状态。
若某侧没有可能贡献的加点/查询，会跳过相关扫描或递归。
它不使用动态波列矩阵；文件里其他数据结构不是这条main的算法。
输入宏读取、BufWriter输出也不同于前两份的I/O路径。

### #272598：封装并没有改变核心为CDQ

OFFLINEPARSM2D::Solver内部仍是PARSC2D::Table<…,true>。
第一次查询出现前，add_point直接把真实权重放进初始表；
第一次查询后，再新增的点登记零权并另记Add事件。
prepare完成后逐条回放，这样省去一部分可以提前并入初值的更新。

这个优化合法，是因为更早根本没有查询需要观察这些加点前的状态。
它的OFFLINE命名不能用于推断采用了CDQ；实际求值路径仍是动态权重波列矩阵。

## 6. 比较时要把预处理也算进去

| 方案 | 未来坐标是否预知 | 操作时序 | 典型时间/空间 |
|---|---|---|---|
| 上游树套树 | 是 | 建表后按原序更新/查 | O(log²K)/操作，O(KlogK)存储 |
| 动态权重波列矩阵 | 是 | 建表后按原序激活权重/查 | O(logD logK)/操作，O(KlogD) |
| 当前CDQ | 全事件预知 | 分治计算贡献、最后还原顺序 | O(Tlog²T)总时间，O(T)级工作区 |

这些源码都先读完操作；不能直接把它们当成可接收未知新坐标的在线容器。
它们省掉的工作各不相同：连续层布局、少存0/1一侧权重、
共同前缀路径复用，或用时间分治避免维护完整动态二维结构。

验证应覆盖重复坐标、未来点在过去查询中不能生效、
第一问前大量加点、没有查询、边界点、零权与同x事件次序。
小数据可以逐条维护完整点列表直接求矩形和。
本页核对上述例子、时间分治配对不变量和五份源码哈希，
没有新增性能benchmark，也未排除前五之外的其他算法家族。
