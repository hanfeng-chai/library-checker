# 带值上界的区间计数与求和：归并排序树、值域扫描与打包前缀

## 1. 题目同时要两个答案

静态数组A的每问(l,r,x)，要求输出[l,r)内所有≤x的元素的
**个数和总和**。[题面](../../../upstream/data_structure/static_range_sum_with_upper_bound/task.md)
允许空区间；[参数](../../../upstream/data_structure/static_range_sum_with_upper_bound/info.toml)
为N,Q≤500000，值和阈值≤10⁹。

取A=[5,1,4,2,3]：

| 查询 | 保留下来的元素 | 个数 | 和 |
|---|---|---:|---:|
| [1,5)，x=2 | 1、2 | 2 | 3 |
| [0,3)，x=4 | 1、4 | 2 | 5 |
| [0,5)，x=10 | 全部 | 5 | 15 |
| [2,2)，任意x | 无 | 0 | 0 |

逐问扫描区间是O(NQ)。普通前缀和只按下标过滤，
无法同时处理不同查询给出的不同值上界，需要再利用值的次序。

## 2. 上游归并排序树：每个下标块都有自己的有序值表

将数组下标二分成线段树。每个节点保存它覆盖区间内的值，按数值排序；
同时保存这条排序数组的前缀和。
叶子只有一个值，父节点用merge合并两个孩子的排序表，
所以整棵树建立O(N log N)，存储也为O(N log N)。

例如覆盖A[0…4)的节点含[5,1,4,2]，
排序后为[1,2,4,5]，前缀和为[0,1,3,7,12]。
阈值x=2时，第一个>x的元素下标为2，
因此这个完整块贡献个数2、总和prefix[2]=3。

一个任意区间可分成O(log N)个节点，
每个节点二分找出≤x的前缀，累加数量与和，
查询O(log²N)。

[correct.cpp](../../../upstream/data_structure/static_range_sum_with_upper_bound/sol/correct.cpp)
实际分别调用lower_cnt和lower_sum，
它们都转换成对x+1做lower_bound。
也就是说，上游对数量和总和各跑一遍树查询，
同一个完整块内的边界搜索会重复。
这里x≤10⁹，x+1没有溢出问题；不能将这个写法无条件用于类型最大值。

## 3. 离线按阈值扫描：只把已经合格的位置激活

数组不修改，而且所有查询可预读。
将原元素按值排序，将查询按x排序。
维护一个按原下标索引的结构，初始所有位置为(0,0)，
扫描到阈值x时，依次把所有A[i]≤x的位置加入(1,A[i])。

不变量是：结构里恰好激活当前阈值允许的元素。
于是查询只剩普通区间和，返回两个分量即可。

小例中元素顺序为
(1,位置1)、(2,位置3)、(3,位置4)、(4,位置2)、(5,位置0)。
到x=2时：

~~~text
计数数组：[0,1,0,1,0]
数值数组：[0,1,0,2,0]
~~~

查询[1,5)直接得到(2,3)。
到x=4时继续激活位置4和2，
查询[0,3)只算位置1、2，得到(2,5)。

相等值必须先激活再回答同阈值查询，才能实现≤而不是<。
答案按原查询编号保存，最终按输入顺序输出。
这条方法减少了每问的一层二分搜索，但需要预读查询并延迟输出。

## 4. 用一个聚合结构维护两个分量

一个Fenwick单元可以存(count,sum)，加法按分量进行，
区间结果也按分量做两个前缀的差。
每个元素只插入一次，每问O(log N)，
排序外的总时间O((N+Q)log N)，空间O(N+Q)。

普通比较排序还需O((N+Q)log(N+Q))。
因为值与阈值小于2³⁰，前几份源码用两轮15位基数排序，
桶大小32768，固定整数域内可将这部分降为O(N+Q+2¹⁵)。
排序机制与[大数组区间复合教程](../point_set_range_composite_large_array/analysis.md)
中的事件排序相同；这里排序的是值和阈值。

## 5. 第一名如何把count和sum打包到一次64位加法里

若写编码 E=count·2ᵏ+sum，
两个编码相加能同时累加count和sum，前提是低k位的sum不会进位到count。
例如k=8，编码(1,5)=261、(1,7)=263，
相加524=2×256+12，恰好还原(2,12)。

但本题全局和可达5×10¹⁴，需要49位，
全局count还需19位，不能直接塞进一个64位字。
#402379将数组分成最多65536位置的块：
一个块的和至多65536×10⁹<2⁴⁶，
于是用低46位放和，高位放数量，最大编码仍在64位内。
每个位置只插入一次，是这个容量证明的关键条件。

每个大块内部再用16路前缀结构维护打包值，
最多四层覆盖16⁴=65536个位置。
块之间的累计和与数量分开保存为完整宽度的两个数组，
避免全局结果超过打包容量。
查询先解码块内结果，再加之前完整块的普通count/sum。

叶层存包含该位置的前缀，因此prefix(end)访问end−1，
end=0直接返回(0,0)；较高层存孩子之前的前缀。
这与其他宽树的末端哨兵布局有所不同，不能只按类名照搬下标。

插入位置i时，把编码(1,A[i])加到相关row的后缀，
AVX2同时更新四个64位槽。它减少了两分量独立访存和加法，
也付出了宽树布局、位宽限制和粗细两级组合的复杂性。
这个类不是可无限重复点加的通用树：破坏“一位置仅激活一次”，位宽界便不再成立。

### #402379：打包的前提来自这道题的扫描模式

main读取items与queries，分别radix_sort_u32<30,15>，
按bound递增将尚未激活的位置insert一次。
bounded_prefix_count_sum的MaxValue为10⁹，
局部sum_bits由MaxValue×chunk_size计算，当前为46。
coarse_sums与coarse_counts分别承担跨65536块的前缀，
fold返回(sum,count)，输出时显式改为题目要求的count、sum顺序。

I/O按成对元素和三字段查询批量解析，并使用成对输出。
文件里其他wide模板不是本题配置，
不能把所有通用range接口的功能都算进运行路径。

### #393944：用最直接的双分量Fenwick表达不变量

Aggregate包含u64 sum和int count，operator+=逐项相加，
operator−逐项相减。main将items和queries分别按数值/阈值基数排序，
插入{value,1}，再tree.sum(l,r)。
它没有压缩两个分量到一个机器字，也没有宽树；
相对上游的主要算法收益来自离线扫描和去掉查询里的每节点二分。

### #404965：同一数学流程，泛型接口封装

RangeFoldWithUpperBound<u32,(AdditiveOperation<i64>,AdditiveOperation<i64>)>
把每个值变成键a与权重(1,a)。
execute排序元素与查询索引，激活条件同样为key≤bound，
使用BinaryIndexedTree维护二元可交换群并恢复原查询顺序。
Rust的pair克隆与泛型调用可以被优化，但不能仅凭模板名称断言消失了所有开销；
143ms仍包含解析、分配、排序和输出。

### #400956：数量只需要0/1，可以另用位图

把元素事件标为(a[i],~i)，查询事件标为(x,query_id)，
std::sort按pair排序。同值时负标记先于非负查询，保证≤的包含关系。
每激活一个位置，BinaryIndexedTree01将该位设1，
并在每64位块的计数Fenwick里增加该块的popcount变化；
查询的边缘块用popcount，完整块用计数树。
总和则用另一条long long Fenwick。

这利用了每位置只有未激活/已激活两种状态，
减少数量结构的空间，但维护两个不同结构和比较排序也有成本。

### #365955：同样按值事件排序，区间查询跳过公共部分

事件同样以负的~i保证元素先于同阈值查询。
Fenwick单元直接是(count,sum)，add每次同时加(1,a[i])。
prod(l,r)先从较大的右端累加块，再从左端减块，
两条前缀链相遇时停止，公共部分相消，不必全部各自走到0。
I/O在main前已通过宏映射到fio路径，不能因更早模板里有iostream就误分类。
