# 静态区间不同数个数：最后一次出现、前一次出现与下一次出现

## 1. 先明确“不同数”怎样计数

数组A不变，查询[l,r)里有多少种不同的值，同一个值出现多次只算一次。
例如A=[1,2,1,3,2,1]：

| 区间 | 元素 | 不同值 | 答案 |
|---|---|---|---:|
| [2,6) | [1,3,2,1] | {1,2,3} | 3 |
| [3,5) | [3,2] | {2,3} | 2 |
| [0,6) | 整个数组 | {1,2,3} | 3 |
| [4,4) | 空 | 空 | 0 |

[题面](../../../upstream/data_structure/static_range_count_distinct/task.md)
允许空区间，[参数](../../../upstream/data_structure/static_range_count_distinct/info.toml)
也允许空数组/零查询；N,Q上限500000，值可达10⁹。
逐问扫描并放入集合，最坏需要O(NQ)个元素处理。

与[区间频率](../static_range_frequency/analysis.md)不同，
这里没有一个指定x可以只查它的位置表，必须同时处理所有值。
解决方法是为每种值只选择一个“代表出现位置”。

## 2. 上游：扫描右端点，每个值只保留最后一次出现

当扫描到前缀[0,r)时，将每个值在该前缀中的最后出现位置标1，
其他位置标0。则区间[l,r)的不同数个数，就是标记在[l,r)的和。

为什么？如果某值在区间中出现，它在整个前缀的最后位置一定也落在区间；
反之，落在区间中的一个1就代表该值确实出现。每种值恰好一个1，
所以不重不漏。

小例扫描完整前缀r=6后，标记在位置3（值3）、4（值2）、5（值1）；
查询[2,6)得到3。
每加入一个A[i]，先把它之前的最后位置清零，再把i设为1。

[上游 correct.cpp](../../../upstream/data_structure/static_range_count_distinct/sol/correct.cpp)
预读查询，按r−1挂到vector桶里；
使用std::map维护每个值的最后位置，用加法线段树保存0/1。
扫到i后完成两次set（首次出现只需一次），再回答右端点为i+1的查询。
空区间提前保留答案0。

因此上游已经是离线算法，时间O((N+Q)log N)，空间O(N+Q)。
前五并非首次发现右端点扫描，主要改进是让每次出现只需一次树状数组更新，
部分路线也把两次前缀查询减成一次。

## 3. 前一次出现：把“代表”换成一张二维点图

定义prev[i]为A[i]在i之前最后出现的下标，不存在记−1。
在[l,r)中，一个出现位置i是其值在区间中的第一次，当且仅当prev[i]<l。
所以不同值数等于

~~~text
满足 l≤i<r 且 prev[i]<l 的位置数
~~~

为了用非负下标，存P[i]=prev[i]+1；条件变成P[i]≤l。
小例：

| i | A[i] | prev[i] | P[i] |
|---:|---:|---:|---:|
| 0 | 1 | −1 | 0 |
| 1 | 2 | −1 | 0 |
| 2 | 1 | 0 | 1 |
| 3 | 3 | −1 | 0 |
| 4 | 2 | 1 | 2 |
| 5 | 1 | 2 | 3 |

将每个位置看成点(i,P[i])，查询就是一个二维计数区域。
扫描i<r的点，树状数组按P这个坐标统计数量，
便能查出其中P≤l的个数。

### 为什么最后只减l，而不再做一遍区间查询

刚才的统计包括了所有i<l的点。对这l个位置，
prev[i]<i<l，所以它们全部满足P[i]≤l，恰好多算l个。
因此：

~~~text
distinct(l,r) = count(i<r 且 P[i]≤l) − l
~~~

本例[2,6)中，前6个P为[0,0,1,0,2,3]，
≤2的有5个，减去l=2得到3。
关键是这里树状数组维护**前驱位置的频率**，
不是维护“当前哪个数组位置标了1”；它与上游的树有不同含义。

每扫描一个原元素，只在坐标P[i]加1，永远不删除；
每问查一次prefix(l+1)再减l。
相比上游的清旧代表/设新代表和区间和，这项代数改写确实删掉了操作。

## 4. 下一次出现：从左往右移动查询左端

另一条路线预先求next[i]，即同值下一次出现位置，不存在记N。
初始仅把每种值的第一次出现位置标1。
将查询按l排序，左端越过位置i时，给next[i]再加1。

旧位置i的1没有清掉，为什么还正确？
因为以后所有查询的左端都大于i，它已经在查询范围外。
区间[l,N)中仍只有每种值的第一个有效出现位置被标1；
所以查询[l,r)的标记和就是不同值数。

本例初始标0、1、3。
左端从0移到2时，越过0激活next[0]=2，
越过1激活next[1]=4。现在标0、1、2、3、4，
但查询[2,6)只看到2、3、4，答案仍为3。
旧标记没有被撤销，数学正确性来自所有未来查询都把它们排除。

此法同样每次只做一次树状数组加法，
但一般需要区间和，即两次前缀查询。
next=N的哨兵可放在额外槽中，不会被r≤N的合法区间包括。

### #363615 / #401532：事件顺序和物理下标都值得核对

读A时用exchange(mp[value],i)取得前一个1起点位置，
首次出现为0。查询答案先设−l，端点事件存(l+1)，
之后再加树状数组的前缀统计。
aux将元素事件与查询按右端分桶，先倒填查询，再倒填元素，
因此同一个r桶里“加入第r项”先于“回答前r项”的查询。
这与频率题的边界前后顺序不同，不能机械复制。

Fenwick逻辑索引仍按lowbit移动，实际存储用
hole(i)=i+(i>>10)，每1024个槽插一个间隙。
这是改变二次幂步长访问在缓存中的映射，尝试减少冲突；
它不改变计数公式，也不保证在每种CPU上都更快。
构造时只建立空树，其他从数组建立的模板重载不在主路径。
两份执行逻辑相同，49/51ms不对应一项新算法。

### #393937：同一公式的显式CSR扫描

main先建立previous_plus_one，再按right建立CsrBuckets。
扫描position后previous_counts.add(P[position],1)，
对right=position+1的查询返回prefix_sum(left+1)−left。
每个答案保留原编号，最后按输入顺序打印。
right=0只能是空区间，答案数组初始零即可。

main实际只用计数Fenwick和哈希前驱，
文件里包含的前驱集合、层级位图等其他结构没有参与。
这是需要看入口才能避免的误分类。

### #259922：一次哈希离散化，然后只访问稠密last数组

先用HashMap将原值映射到0…D−1，再倒序扫描得到next，
同时获得每种值最左位置，建立初始标记。
查询通过按l的计数分桶排序，不做比较排序；
左端推进时BIT.add(next[i],1)，查询BIT.sum(l,r)。
哈希容量由随机素数决定，双重散列处理碰撞，
不能把平均访问成本写成任意输入下的最坏保证。

### #365804：相同左端不变量，容器组织不同

unordered_discreate::build实际使用哈希为新值分配编号，
不是把数值排序后压缩。
range_dist计算nx和首次标记，bit_t从初始标记线性建立，
查询按左端桶顺序执行。
虽然函数名multiply看似乘法，此处幺半群是加法，
所以bit.multiply(nx[i],1)的含义仍是加一个标记。
已有旧位置的1一直保留，正确性由第四节证明。

## 6. 复杂度与应做的对照

| 方法 | 每次扫描元素的树更新 | 每问树操作 | 需要预读查询 |
|---|---|---|---|
| 上游最后出现 | 清旧1、设新1 | 区间和 | 是 |
| 前驱位置计数 | 在P[i]加1 | 一次前缀−l | 是 |
| 下一位置激活 | 在next[i]加1 | 区间和 | 是 |

三者总体仍为O((N+Q)log N)，哈希/压缩和分桶另有线性或期望线性部分，
空间O(N+Q)。当前前五并未采用Mo排序或在线波列结构，
不能据此声称那些家族没有更深的快提交。

正确性可对每个小区间直接构造集合，
特别覆盖空数组、空区间、全相同、全不同和交替重复。
性能则固定I/O比较三种代表不变量，再分别替换hash/map、CSR和Fenwick填充。
