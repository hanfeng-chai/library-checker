# Static Range Inversions Query：从逐对比较到分块与延迟扫描

## 题意与完整小例子

区间 `[l,r)` 的逆序对是满足 `l≤i<j<r` 且 `A[i]>A[j]` 的下标对。
相等不算，左右位置顺序不能交换。数组不修改，`N,Q≤100000`、
`0≤A[i]≤10^9`，见
[`task.md`](../../../upstream/data_structure/static_range_inversions_query/task.md)、
[`info.toml`](../../../upstream/data_structure/static_range_inversions_query/info.toml)。

```text
输入                 输出
6 5                  6
3 1 4 2 1 5          3
0 6                  1
1 5                  1
0 3                  0
3 5
1 2
```

全数组六对为 `(0,1),(0,3),(0,4),(2,3),(2,4),(3,4)`。
`[1,5)` 是 `[1,4,2,1]`，只剩后面三对；两个值 1 不构成逆序。
最长区间最多有 `N(N-1)/2=4999950000` 对，超过 32 位有符号整数。
答案与事件的累计贡献都应使用 64 位，不能只把最终输出类型改大。

## 朴素扫描与普通 Mo 的基线

每问枚举两下标是 O((r-l)²)。若从左向右处理区间，维护已经出现值的
频数，加入 x 时统计此前大于 x 的数量，就可用 Fenwick 把单问降到
O((r-l)log N)，但不同查询仍重复扫描相同位置。

Mo 算法先把查询重排成相邻区间尽量接近的顺序，只维护当前 `[L,R)`。
每次移动一格时的变化为：

| 移动 | 新增/移除的点 | 逆序数变化 |
|---|---|---|
| 右端扩张 | p=R | 加上当前区间中大于 A[p] 的数目 |
| 左端扩张 | p=L-1 | 加上当前区间中小于 A[p] 的数目 |
| 右端缩短 | p=R-1 | 减去此前与它配对的更大元素数 |
| 左端缩短 | p=L | 减去此前与它配对的更小元素数 |

按左端块分组、块内右端交替升降排序，位置块宽 B 时总移动量常规界为
`C=O(QB+N²/B)`。每步若仍做 Fenwick 更新/计数，就有额外 log N，
总计 `O(C log N+Q log Q)`。这帮助理解快解要省什么，但上游实际并未
使用 Mo，先看它的在线分块结构。

## 上游先把相等值按原位置展开为不同排名

[`correct.cpp`](../../../upstream/data_structure/static_range_inversions_query/sol/correct.cpp)
对下标按原值 stable_sort，再给排序后的每个位置分配独一排名 0…N-1。
相等值的较早下标排名更小，因此对任何 i<j，原来的严格逆序关系保持不变。
示例 `[3,1,4,2,1,5]` 变成 `[3,0,4,2,1,5]`。

这与“相等值压成同一排名”不同。它把数组变成排列，使任意两个不同位置
都有严格的大小关系，后面的补集计数和组合数修正不用再专门扣除相等对。
若排序时随意打乱相等值，较早的相等项可能反而获得大排名，制造伪逆序。

## 上游的实际分块摘要

块长 `B=floor(sqrt(N))+1`，每个 bucket 保存：

| 成员 | 含义 |
|---|---|
| rank | 该位置块中的排名，保留原位置顺序 |
| sorted_ind | 该块按排名排序的局部下标 |
| prefix_inv[t] | 该块前 t 个元素内部的逆序数 |
| block_inv[L] | 从完整块 L 起，到当前块起点之前的总逆序数 |
| freq[x] | 当前块之前的所有元素中，排名严格小于 x 的数量 |

prefix_inv 在每个小块内部两两比较构造；不同整块之间的逆序对用两条
sorted_ind 双指针统计，再累积进 block_inv。
freq 对每个块边界都保存一条长度 N+1 的排名前缀计数。
所以它并非只存 O((N/B)²) 个块答案，**频数表还有 O(N²/B) 空间**。

建表主要工作为 `O(NB+N²/B+N log B)`，取根号块长约为 O(N√N)；
查询 O(B)，可边读边答。N=100000 时仅按块边界保存的 size_t 频数表
就有约三千多万项，是数百 MB 量级，明显不同于后面的线性空间离线方案。

### 为什么跨块公式需要几个看似奇怪的修正项

设 U 为“左端所在块的块首，到右端所在块的块首”的整块区间；
D 是 U 前面被查询排除的短前缀；R 是右边块实际需要的短前缀。
目标为 `(U 去掉 D) + R`。

先从预存 I(U) 中去掉 D。对 D 中每个值 x，统计 U 中比它小的值数。
这个总数包含 `Cross(D,U\D)`，还包含 D 内所有大小方向的配对，总计
`|D|(|D|-1)/2`；D 内真正应从逆序数扣掉的却是 I(D)。于是

```text
I(U\D) = I(U) - sum(x∈D) count_U(value<x)
                 + |D|(|D|-1)/2 - I(D)
```

再加 I(R) 与跨段配对：

```text
Cross(U,R) = |U|*|R| - sum(y∈R) count_U(value<y)
I(目标) = I(U\D)+I(R)+Cross(U,R)-Cross(D,R)
```

排名唯一、U 与 R 不相交，所以“不是小于”在这里恰好就是大于。
各 count_U 由两个块边界 freq 相减得到；Cross(D,R) 用两个边缘块的
排序下标双指针计算，边缘至多 B 项，所以整问 O(B)。

示例 N=6 时源码 B=3，问 `[1,5)`：U 是 `[0,3)` 的 `[3,0,4]`，
D 是位置 0 的 `[3]`，R 是 `[3,5)` 的 `[2,1]`。
I(U)=1，D 中的 3 在 U 内有一个更小值，故 I(U\D)=0。
I(R)=1，Cross(U,R)=`3*2-(1+1)=4`，Cross(D,R)=2，
最终 `0+1+4-2=3`，对应原数组 `[1,4,2,1]`。

若两端同块，`prefix_inv[r]-prefix_inv[l]` 还包含“查询前缀与目标区间”
的跨对，用本块 sorted_ind 扫一次减掉即可。右端正好在 N 或块边界时，
额外桶/末端 prefix 项负责支持半开端点，不能随意删掉占位桶。

## 前五怎样用第二次扫描省掉每步 Fenwick

前五主要采用“先按 Mo 顺序记录移动，再离线求这些移动的贡献”。
排序仍控制总移动量 C，但并不真的在记录阶段维护当前值频数。
要理解这一点，先把一次查询拆成方便的前缀基值与修正量。

以下暂用闭区间 `[L,R]`，与源码把 r 减一的写法一致。定义：

```text
P[t] = 原数组前缀 [0,t] 的逆序数，P[-1]=0
g(t,x) = #{j≤t : rank[j]≥rank[x]}
D(L,R) = I(L,R) - (P[R]-P[L-1])
```

P[R]-P[L-1] 除区间内部逆序外，还包含位置在 `[0,L)`、值更大的左外部
元素与区间元素的配对，所以 D 是这些跨对的负数。
记录相邻 Mo 查询之间 D 的变化，最后再加回各自前缀基值即可。

### 四种移动的公式从哪里来

右边加入位置 p 时，P 的变化已包含所有 p 之前比它大的元素，
真正区间只应包含 L 之后的那部分，因此 D 需再减 `g(L-1,p)`。
右边删除则加回来。

左边加入位置 p 时，真实新增的是 p 之后、截至 R 比它小的元素。
前缀基值同时增加了 p 之前比它大的元素数；二者相减可以整理为
`R-p+1-g(R,p)`。这里 g 包含 p 自身，+1 正好抵消它，不能随意删去。
左边删除取相反号。因此可以记录如下事件：

| 移动一段位置 p | 扫描时刻 t | 对 D 的贡献 |
|---|---:|---|
| 扩张右端 | L-1 | `-sum g(t,p)` |
| 缩短右端 | L-1 | `+sum g(t,p)` |
| 扩张左端 | R | `+sum(t-p+1-g(t,p))` |
| 缩短左端 | R | `-sum(t-p+1-g(t,p))` |

每种端点移动可覆盖一整段 p，先只存 `(t,移动段,符号,是否加长度,查询ID)`，
每个查询最多四条记录，不把每个移动位置都单独存成事件。

例如示例从 `[1,3]` 扩张到 `[1,4]`：新位置 4 的排名为 1，
`g(0,4)=1`，所以 D 减 1。前缀逆序基值增加 3，真实区间逆序只增加
`3-1=2`，正是原窗口内 4、2 与新 1 的两对。
反过来把 `[1,4]` 左扩到 `[0,4]`，`g(4,0)=2`，D 增
`4-0+1-2=3`，抵消了此前左外部点 0 造成的三对修正。

### 固定扫描时刻后，g 的一次读取只有常数成本

从 t=0 到 N-1 扫一遍。看到排名 y，就给所有排名 x≤y 的计数加一，
这样在时刻 t 读取计数 x，恰好得到 g(t,x)。
用值域分块维护“前缀加、单点读”：每块有 lazy，块内每点有 direct，
读取只需 `direct[x]+lazy[block(x)]`。更新一个排名前缀时，对完整块
只改 lazy，对最后的半块逐项改 direct。

值域块宽 Cb 时，每次插入 `O(N/Cb+Cb)`，但全局只有 N 次；
所有事件在各自时刻读取 g，每个被移动的位置只花 O(1)，总计仍为 C。
并且在插入当前排名之前读 g，得到当前点与更早点产生的逆序数，可顺便
累加构造 P。事件要在插入之后求值，才符合包含 `j=t` 的定义。

总时间为
`O(N(N/Cb+Cb) + QB+N²/B + Q log Q)` 加排名排序；
两块宽都近根号时约为 `O((N+Q)√N+Q log Q)`，空间 O(N+Q)。
这用一次较贵的全局值域扫描更新，替代每个 Mo 移动都做对数频数操作；
查询必须预读并重排，不能继承上游任意新查询到来即可回答的接口。

### #393939 / #181308：同一差分公式，不同排序与读写

#393939 的 main 调 `static_range_inversion_counts`。值按 30 位两轮
15 位稳定基数排序，小数组退回 stable_sort，然后按原位置赋唯一排名。
查询左端块固定为 512、值域更新块固定为 256，不能把这两个块当成同一
空间的分块。events[t] 保存区间差分记录，delta 按原查询 ID 累计；
最后按 Mo 顺序做 running_delta 的前缀和，再加 P 基值，还原每问答案。
计数 direct/lazy 用 int，单项至多 N；累计 prefix_inversions/delta
则用 int64，答案用 uint64。I/O 采用映射输入和缓冲输出。

#181308 同样把查询右端减一、Mo 左块 512、计数块 256，事件字段和四个
转移顺序相同。排名用 `(value,index)` 比较排序，因此相等值仍按下标有序。
pinv、qans、delta 为 long long；最后 ql=0 时减 pinv[0]，而首项逆序
必为 0，与减 P[-1] 等价。它使用关闭同步的 cin/cout。
两者主算法相同，前者主要减少排名排序及读写成本，不能把整段差距说成
首次发明了延迟扫描。

### #36979：相同值保留相同排名，改用严格大于/小于

它用 lower_bound 给相等原值相同排名，所以查询较大值时用
`get(rank+1)`，较小值用 `get(1)-get(rank)`，不能把它替换成前文
唯一排名下的 ≥ 公式。位置排序块与计数块都取 350。
to_add 记录交叉项，val1/val2 预存每个位置在前缀中对应的大/小计数，
随后沿 Mo 端点移动再补这些前缀项，等价地恢复各问逆序数。

它的关键正确性边界在 process：每条事件把整个移动段贡献先加到
局部 **int add**，之后才写入 long long ans。一个段的和可能超过 2^31。
本地以未修改源码、`g++ -std=c++23 -O2` 做一次输出核对：
N=100000、Q=1，前 50000 项为 1，后 50000 项为 0，唯一查询
`50000 100000`。查询全是 0，正确答案为 0；实际输出 **4294967296**。
事件聚合需要累加 `50000*50000=2500000000`，32 位中间量溢出。
这不是性能测量；复用需把事件局部累计一并改为 64 位并重新验证。

### #200198 / #200135：前后两次扫描，把 g 表换成位图计数

两份先按 `(value,index)` 排名，借普通 `FenwickTree_01` 构造前缀
逆序 pre 与后缀逆序 suf；这一步的值只出现一次，可用位图表示是否已插入。
Mo 只取 get_order，没有调用模板中的即时 add/remove 查询流程。
根据四类移动，将跨左边界项放 QL、跨右边界项放 QR，并先把 pre/suf
的差加入当前查询的 delta。

随后从左到右扫描计算 QL，从右到左扫描计算 QR，最后按 Mo 顺序累加
答案差分。扫描结构是 `SqrtFenwickTree_01`：底层每 64 个排名一字，
字内用 popcount，完整字计数由根号分块前缀表给出。单次频数读可由
两个块前缀与至多两个字内计数得到，避免每个移动再做 log N 查询。
这里只需要单向插入，模板中的删除、kth、前驱等接口未调用。

Mo 块宽按 N、Q 计算，随后用相邻查询的曼哈顿移动距离做局部交换，
尝试减少实际移动数；它不改变转移公式，也不是新的逆序对定义。
#200135 与 #200198 的主过程相同，主要把若干块容量从“多留一块”改成
向上取整，并补根号表的尾哨兵。位图的 prod 仍可能在整字右端读取
`dat[n/64]` 后与零掩码相与；N 恰为 64 倍数时，紧分配版本应额外留
哨兵或显式跳过该读取，不能把零掩码当成越界访问合法的理由。
两份使用自定义缓冲/映射 I/O，同为 108 ms 不足以确认容量微调有稳定收益。

## 选择与验证边界

上游以 `O(N√N)` 预处理及较大频数表换在线 O(√N) 查询；
延迟 Mo 以 O(N+Q) 存储和整批重排换掉移动上的对数因子。
本地 [`delta_sweep.cpp`](../../../problems/data_structure/static_range_inversions_query/delta_sweep.cpp)
与 [`fenwick_mo.cpp`](../../../problems/data_structure/static_range_inversions_query/fenwick_mo.cpp)
分别保留延迟与即时计数，说明见
[`tutorial.md`](../../../problems/data_structure/static_range_inversions_query/tutorial.md)。

验证应包含全相等、严格递增/递减、相等值交错、单元素、全区间、跨块
边界及超过 32 位的总/局部贡献。小规模用二重循环独立核对，检查最终
按原查询顺序输出。性能对照应固定 I/O，分别记录排序、移动量、事件条数、
扫描更新与贡献读取；本篇没有新的性能 benchmark，历史 tutorial 的
测量不当作当前五份之间的纯算法比较。
