# 静态区间频率：从位置表二分到离线端点扫描

## 1. 题目与手算

数组不修改，每个查询(l,r,x)询问x在半开区间[l,r)出现多少次。
[题面](../../../upstream/data_structure/static_range_frequency/task.md)允许空区间，
[参数](../../../upstream/data_structure/static_range_frequency/info.toml)还允许N=0、Q=0，
上限均为500000，值域为[0,10⁹]。

取A=[5,2,5,5,2,7]：

| 查询 | 符合条件的位置 | 答案 |
|---|---|---:|
| [1,5)，x=5 | 2、3 | 2 |
| [0,6)，x=2 | 1、4 | 2 |
| [0,6)，x=9 | 无 | 0 |
| [3,3)，x=5 | 空区间 | 0 |

每次扫描整个区间，最坏O(NQ)。数组静态，可以先整理每个值出现在哪里，
也可以预读所有查询并共享前缀计数。当前前五选择的是后一条路线。

## 2. 上游：每个值一条有序位置表

[correct.cpp](../../../upstream/data_structure/static_range_frequency/sol/correct.cpp)
从左到右读A，向map[A[i]]的vector追加i。
因此每条位置表自然有序，无需再排序。
例如值5的位置表为[0,2,3]。

区间[l,r)的出现次数等于

~~~text
lower_bound(位置表,r) − lower_bound(位置表,l)
~~~

lower_bound返回第一个不小于目标的位置。
[1,5)中，r=5对应表末下标3，l=1对应表下标1，
所以3−1=2。两边都用lower_bound，才能保持右端r不包含的语义。

上游用std::map找到位置表，查询又用了map[x]；
缺失x会插入一条空表，仍正确返回0，但产生额外树节点。
建立需O(N log D)，查询O(log D+log freq(x))，
D为map中不同键数（也可能包括只被查询的缺失值）。
这是能按查询到达顺序立即回答的在线方案。

## 3. 将每问拆成两个“到某位置为止出现几次”

定义C_x(t)=x在A[0…t)中的出现次数，
那么freq(l,r,x)=C_x(r)−C_x(l)。
这不是为每个值开N长前缀数组；我们只在扫描时维护当前的计数表。

小例中C_5(t)，t=0…6，依次为
[0,1,1,2,3,3,3]。查询[1,5)为3−1=2。
把该查询记成两个事件：

~~~text
到位置1时，答案减去当前count[5]
到位置5时，答案加上当前count[5]
~~~

从位置0扫描到N：

~~~text
先处理挂在position的所有查询端点
若position<N，再执行count[A[position]]++
~~~

处理端点时，计数恰好只包含position之前的元素，
所以不变量是count[x]=C_x(position)。
若把递增放在前面，右端元素就会被错误计入。
例如查询[1,5)、x=7应为0，不能把A[5]=7提前加入。

所有答案先存数组，最后按原查询编号输出，
因此内部事件重排不会改变用户看到的输出顺序。
这需要预读查询；它与上游即时回答的接口条件不同。

## 4. 端点在[0,N]中，可以计数分桶，不必比较排序

最多有2Q个端点，每个挂在一个整数位置。
先统计每个位置的事件数，对计数做前缀和得到offset，
再把事件写进一条连续数组，对应位置的区间就是
[offset[t],offset[t+1])。
这类布局常叫CSR：用偏移数组表示许多变长列表，
避免每个位置各自创建、扩容一个vector。

构造和扫描O(N+Q)，空间O(N+Q)。
每个端点只查一次当前频率，每个原元素只将频率加一，
不再为每问单独二分位置表。
若计数表使用分布良好的哈希，期望总工作线性；
固定乘法哈希没有任意输入的最坏线性保证，详见
[关联数组教程](../associative_array/analysis.md)。

### #362490 / #401531：把扫描本身也编成一个事件流

aux总长N+2Q，元素事件用id=UINT32_MAX区分，
查询左/右端点用2i、2i+1编码。
cnt初始为1，给每个位置预留一个元素事件槽，
再加入查询端点数量并做前缀和；N处没有A[N]，所以移除最后的多余预留。

先倒填元素事件到对应桶的末端，再倒填查询端点到它前面。
因此顺序遍历aux时，位置t的查询事件一定先于“加入A[t]”，
正好实现第三节的不变量，而不是任意混排。

FastHashMap容量2¹⁹，只为实际A值插入槽，
查询缺失值用get返回0，不占新槽。
无符号ans在左端减计数时允许模2³²回绕，
右端加回来后的真实答案在[0,N]，因此最终位值正确。
两份事件算法相同，但I/O模板不同，不声称全文逐字节同一份。

### #393938：端点单独存，外层扫描更直观

queries保留l/r/value，offsets按位置统计两个端点，
endpoints存查询编号、值及是否右端。
扫描position=0…N，先完成端点加减，再将当前位置值加入U64HashMap。
answers用有符号int，可以暂存−C_x(l)。

空数组时原输入可能有空白行，main专门在n==0且有查询时跳过空白，
不能将正常单分隔符的快速读取契约不加处理地套到该边界。
本题主路径只需计数哈希，附带的其他整数I/O接口未必使用。

### #382978：为什么没有左/右标记也能算

两端事件都只存(i,x)，按位置从小到大处理时，
对答案反复执行ans[i]=count[x]−ans[i]。
第一次到l，ans由0变成C_x(l)；
第二次到r，变成C_x(r)−C_x(l)。
若l=r，两次同一计数相减，仍得0。

这个技巧依赖每问恰好两个有序端点，
不能任意推广到更多带符号事件。
CSRArray将事件连续存放，计数用HashMap<u32,u32,FxHasher>；
Hasher对u32做固定乘法和旋转，并非默认字符串哈希。
它减少了事件字段，但不改变扫描需要O(N+Q)个事件的事实。

### #258498：先加入元素，再处理挂在该元素后的事件

它把右事件挂在r−1，左事件挂在l−1，
l=0时不建左事件，空区间直接保持答案0。
扫描i先把A[i]计数加一，再处理桶i，
于是当前计数是C_x(i+1)，与前几份“端点前处理”的坐标约定等价。
负的左事件用~query_id编码，与非负右事件区分。

HashMap随机选约4N/3的素数容量，
首槽k mod p，步长k mod(p−1)+1。
因p为素数、步长介于1与p−1，探测能遍历全部槽；
这保证有空位时可找到它，不等于保证每次探测都是常数步。
构造时找素数实际会调用素数判定，
但源码里完整质因数分解等其他工具不在本题热路径。

## 6. 对照结论与验证

上游预建位置表，逐问做键查找与两次二分；
当前快解将所有查询改写为端点事件，用一次扫描共享计数，
省掉逐问的搜索路径，同时付出O(Q)事件/答案存储与延迟输出。
CSR进一步省掉很多小容器分配，哈希替换有序map，
整数I/O又单独影响最终毫秒数。

验证应包含N=0、Q=0、l=r、x从未出现、所有值相同、
每个值都不同、端点0/N，以及端点处恰好等于x的元素。
性能对照则固定I/O比较位置表二分与离线扫描，
再分别比较计数表和事件布局。
