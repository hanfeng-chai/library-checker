# Power of Formal Power Series：先处理前导零，再选择指数内核

本题求 `f(x)^M mod x^N`，`1≤N≤500000`、`0≤M≤10^18`，
模数为 `p=998244353`。输入常数项可以为零，指数也可以为零。
真正困难的部分不仅是快速多项式计算，还包括把平移次数、常数幂、
正规化级数的指数三种量正确分开。

## 1. 从乘法定义开始

整数幂就是把 `f` 连乘 `M` 次。所有数组都是普通多项式系数，
乘法按卷积求和；截断只丢弃次数至少为 `N` 的项。
例如 `f=1+x`、`M=3`、`N=4` 时，答案为 `[1,3,3,1]`。

指数为 0 时，空乘积定义为 1，所以即使输入全零，也输出
`[1,0,…,0]`。指数为 1 时可以直接复制输入；正指数下全零输入
仍然全零。这些分支应在求逆、求对数之前处理。

最容易写的通用参照是多项式二进制快速幂：

```text
answer = 1
base = f
while M > 0:
    if M 为奇数: answer = answer * base mod x^N
    M /= 2
    if M > 0: base = base * base mod x^N
```

若一次卷积费用为 `C(N)=O(N log N)`，总计约
`O(C(N) log M)`。它适合短输入或某些小指数，但最大指数需要
多轮长卷积。后面的算法将主要多项式工作与 `log M` 解耦。

## 2. 前导零与三个互不相同的指数

### 2.1 把最前面的非零项提出去

正指数时，设 `s` 是首个非零下标，`c=f_s≠0`，写成

$$
f(x)=x^s c H(x),\qquad H(0)=1.
$$

于是

$$
f(x)^M=x^{sM}c^M H(x)^M.
$$

如果 `sM≥N`，答案全部落在截断范围之外，直接输出零。
否则只需计算 `H^M` 的前 `K=N−sM` 项，乘 `c^M` 后右移 `sM`。

例如 `f=2x²+2x³=2x²(1+x)`，`M=2`、`N=7`，得到
`4x⁴(1+2x+x²)`，答案是 `[0,0,0,0,4,8,4]`。
若 `N=4`，同一输入的平方模 `x⁴` 全零。

### 2.2 先判断范围，再做乘法

最大 `sM` 可能远超 64 位整数。安全判断是

```text
if s>0 and M > (N-1)/s: 返回全零
否则 shift=s*M，此时已知 shift<=N-1
```

不要先把 `s*M` 溢出以后再和 `N` 比较。全零输入应单独返回，
不能访问不存在的 `f_s`。

### 2.3 为什么三处取模不能混用

| 用途 | 需要怎样的指数 | 理由 |
|---|---|---|
| 平移 `x^{sM}` | 原整数 `M`，或足以判定超界的饱和值 | 次数比较发生在普通整数中 |
| 非零常数 `c^M` | 可以使用 `M mod (p−1)` | 有限域非零元素满足 `c^{p−1}=1` |
| `H^M` 的正规化级数运算 | 在 `N<p` 时使用 `M mod p` | 导数方程/对数中的系数乘法属于模域 |

例如 `f=x`、`M=p`，低于 `p` 次的答案全零；若先把次数使用的
指数模 `p`，就会错当成零指数并返回 1。
常数 `2` 的 `p` 次幂则为 2，而不是把指数模 `p` 后得到的 1。
但 `(1+x)^p=1+x^p`，在本题 `N<p` 的截断下确实等于 1。

最后一个等式也说明 `M mod p` 的适用范围：它依赖当前只看次数
小于 `p` 的正规化单位级数，不能不加条件推广到更长精度。

## 3. 两条快速路线共享同一微分方程

### 3.1 对数后取指数

对于 `H(0)=1`，形式对数满足 `log(H^M)=M log H`，于是

$$
H^M=\exp(M\log H)\pmod{x^K}.
$$

`log H` 的常数项为 0，所以可以送入指数函数；所需的整数除数
小于模数，均可逆。
完整算法为：

```text
先处理 M=0、全零输入和 shift>=N
H[i] = f[s+i] / c，只保留 K=N-shift 项
L = log(H) mod x^K
G = exp((M mod p) * L) mod x^K
answer = x^shift * (c^(M mod (p-1))) * G
```

多项式部分为 `O(K log K)`，标量常数幂为 `O(log M)` 或
取模后 `O(log p)`，总工作不再是做 `log M` 次全长卷积。

### 3.2 直接从 `H·DG=M(DH)G` 解系数

令 `G=H^M`、`D=x·d/dx`，有

$$
H\,DG=M(DH)G.
$$

由于 `H_0=G_0=1`，第 `j` 项给出

$$
g_j=\frac1j\sum_{i=1}^{j}\big((M+1)i-j\big)h_i g_{j-i}.
$$

例如 `H=1+x`、`M=3`：
`g_1=3`、`g_2=((4−2)·3)/2=3`、
`g_3=((4−3)·3)/3=1`。
这个递推在稠密输入上为二次时间；如果 `H` 只有 `t` 个非零
非常数项，则只需 `O(Kt)` 工作。小规模和稀疏输入可直接用它。

它也是大输入直接分块求幂的基础。无需显式构造全长 `log H`
再取一次全长指数，就能联合求解这条微分方程。

## 4. 直接分块求幂怎样解当前块

为避免下标混淆，本节用 `B` 表示块宽，`r` 表示块编号。
首块先求 `G_0=H^M mod x^B`，保留首块 `H_0`，并准备
`T=(H_0G_0)^{-1} mod x^B`。

假设旧答案只包含已经完成的块，记作 `G_old`。
它在第 `r` 块造成的两种乘积贡献是

$$
\Psi=[\text{第 }r\text{ 块}](HG_{old}),\qquad
\Phi=[\text{第 }r\text{ 块}]((DH)G_{old}).
$$

因为 `D(HG)=DH·G+H·DG`，当前微分方程残差可写成

$$
\rho=(M+1)\Phi-(D+rB)\Psi.
$$

这就是代码中每项使用 `(M+1)*phi[i]−(rB+i)*psi[i]` 的原因。
设未知块 `G_r=G_0U`，利用首块已满足同一微分关系，可以消去
`DG_0`，剩下

$$
H_0G_0(D+rB)U=\rho\pmod{x^B}.
$$

所以先乘 `T`，逐项除以 `rB+i`，最后乘 `G_0`：

```text
U = rho * T mod x^B
U[i] /= r*B+i
G_r = U * G0 mod x^B
```

旧块贡献可缓存 NTT，在频域合并低半段与跨块高半段。块数选在
`O(log K)` 量级时，块对频点累加为 `O(K log K)`，变换亦为
`O(K log K)`。首块递归继续缩小，工作数组保持线性量级。

这条路线省去分开执行的全长对数和指数，但多了两类块贡献与较复杂
残差。是否更快仍取决于输入规模、后端和实现常数。

## 5. 上游实际是规范化后的对数指数法

[题面](../../../upstream/polynomial/pow_of_formal_power_series/task.md)、
[配置](../../../upstream/polynomial/pow_of_formal_power_series/info.toml)
和[上游 correct.cpp](../../../upstream/polynomial/pow_of_formal_power_series/sol/correct.cpp)
中，入口为 `main→pow(a,m)`。
它先处理 `M=0`、全零数组，用除法形式判断首项次数乘指数是否超界；
然后左移去掉前导零、除以首项、求 `log`、乘 `M mod p`、求 `exp`，
乘首项的幂并右移回来。

这里的上游 `exp` 与另一批 FPS 题的参考代码不同：它**实际调用**
`log(trim(b,2*len))`，而该 `log` 又调用通用求逆、卷积和积分。
不能套用指数题参考解的“内置导数残差”调用图。

`mul` 总是使用整数 NTT，并返回整个补齐后的变换数组；`log`
没有把这个数组立即裁回原有效长度，所以后续 `exp` 可能处理多余
缓冲项。`pow` 最终仍只使用能影响前 `N` 项的部分，数学结果正确，
但有额外变换与扫描。积分逐项通过快速幂求逆，同样有可省的标量
开销。源码还保留 `pow_exact` 和随机 `verify`，`main` 没有调用它们。

### 5.1 #405973 / #382181：同一正文的直接分块微分方程

两文件原始字节不同，正规化换行后正文逐字相同。
入口 `safe_pow` 先处理零指数，再扫描首项，使用
`k>(n−1)/lead` 避免次数乘法溢出。它除以首项、只保留移动后需要
的长度，标量首项幂单独计算。

主体 `pow_18e_block` 实现第 4 节直接求幂。首块递归求幂，
`(H_0G_0)^{-1}` 使用该库的四倍精度求逆；缓存 `H`、`DH` 与
答案块两类卷积，再用残差求下一块。块数约为 `log₂K`，不是
指数题中固定约 16 块的规则。长度不超过 16 时用小规模
`ln_n2→乘指数→exp_n2`。

`main` 先补到 8 的倍数并做 Montgomery 转换，输出只取原 `N`
项。移动后的缓冲还留有向量尾部空间。主体直接使用 AVX2 指令，
没有运行时 CPU 特性回退保证；读写使用自定义缓冲。

### 5.2 #403367：按指数与稀疏度选择内核

`main` 把指数作为十进制字符串传给 `Poly::pow`。解析时同时保存
`mod_p`、`mod_phi`、封顶到 `N` 的 `capped` 以及是否真正为零，
正好对应第 2 节三种用途。零指数不需要读取剩余系数就能确定答案。

去掉前导零并正规化之后，真实分支顺序包括：

- 剩余长度 1 或 `M mod p=0`：只保留常数幂。
- `M mod p=1`：复制正规化级数后缩放。
- 非常数非零项至多 24 个，或长度不超过 32：使用第 3 节稀疏递推。
- 稠密情况下，指数余数为 `p−1,p−2,2,3,4`：分别用求逆、逆的
  平方、平方、立方或两次平方。
- 其余大输入长度至少 512：直接分块求幂；较短情况用 `log→exp`。

这些捷径都建立在正规化后 `H(0)=1`、精度小于 `p` 的条件上。
例如 `H^{p−1}=H^{-1} mod x^K`，不是任意带前导零的原输入都可
直接改成求逆。

该文件有 `__builtin_cpu_supports("avx2")` 的运行时检查及标量
后备，与直接声明 AVX2 的其他实现不同。大分块仍使用第 4 节同一
残差，I/O 是 64 KiB 缓冲与数字转换；其他多项式接口不自动进入
本题路径。

### 5.3 #285067：对数导数自动消去常数因子

`solve→sf_pow→pow_c1` 采用对数指数路线。`sf_pow` 处理 `0/1`
指数、前导零和次数超界，求首项标量幂；`pow_c1` 调用
`ln→乘 M mod p→exp`。这两个大内核使用分块求商与分块指数。

代码没有总是显式把整个输入除以首项。原因是其 `ln` 通过
`(Df)/f` 计算，再设对数常数项为 0：若 `f=cH`，则
`(Df)/f=(DH)/H`，得到的正是 `log H`。常数因子最后由 `c^M`
补回，代数上等价于显式正规化。

主程序指数类型是 `size_t`，在该 64 位运行环境中覆盖 `10^18`。
库支持的负指数分支不属于本题入口。全零扫描返回无符号哨兵，
正指数会通过超界判断返回零；零指数在使用首项前单独返回 1。
AVX2、模尺度、映射输入和缓冲输出仍需配套。

### 5.4 #146030：字符串指数的 `Safe_Pow` 与复用边界

入口调用 `Safe_Pow(F,N−1,M,G)`，精度参数为最高下标。
它扫描前导零，按字符串长度或实际乘积判断平移是否超界，然后
分别解析 `M mod p` 和 `M mod (p−1)`。`Pow` 对非常数单位级数
调用 `Ln→Exp`；两者均使用前述分块内核。指数余数 0 和 1 有
直接分支，非单位首项则显式缩放。

这份包装的边界需按实际内存组织理解：超界时返回 `empty_poly`
而不写输出，主函数忽略返回值；本次单例的 `G` 来自初始为零的
静态内存区，因此能输出零，但这个接口不能直接当成“对任意旧
输出缓冲都会清零”的通用函数。

另外，零指数且有前导零时，它仍先复制移位后的 `N` 项，可能
越过逻辑输入末尾、进入相邻工作区；规范写法应在任何平移复制前
直接处理 `M=0`。字符串位数捷径也依赖通常的规范十进制表示。
这些是源码复用条件，不能因快照 AC 就省略。NTT 与 I/O 延续
QedDust 的 AVX2、内存区和缓冲实现。

## 6. 检查边界比只跑稠密随机数据更重要

| 输入特征 | 期望行为 |
|---|---|
| 任意 `f`，`M=0` | 常数 1，包括 `f=0` |
| 全零 `f`，`M>0` | 全零 |
| `sM=N−1` | 最多剩一个非零常数缩放项 |
| `sM=N` | 全零 |
| 常数 `c` | 只有 `c^M` 非零 |
| `H=1+x` | 小指数可用二项式系数校验 |
| `M=p,p−1,p+1` | 分别验证三种指数语义 |
| 极大 `M` 且 `s>0` | 不溢出，先判断为零 |

已核对五份源码哈希与配置，并检查了前两份正规化后的正文相同性。
本地对长度 `1..12`、含前导零的 216 组输入验证普通快速幂、
正规化后的微分递推和块宽为 3 的直接分块公式。指数包含
`0,1,2,3,4,p−1,p,p+1,10^18`，全部系数一致。没有新增候选编译、
OJ 请求或性能测试。

性能实验应分开看常数、多项式稀疏、稠密、小指数和大指数；固定
相同 NTT 与 I/O 后，再比较对数指数路线和直接分块路线。
只用一个大稠密输入，无法代表 #403367 的多分支设计；只看 52–61 ms
总时间，也不能判断某个通用幂内核的净收益。
