# Sparse FPS Exponential：用至多十个固定偏移生成整个指数级数

要求 `G=exp(F) mod x^N`，输入仅给 `K≤10` 个非零系数，
`N≤1000000`。与稠密指数不同，本题不必维护 Newton 的指数与逆
前缀：微分关系直接给出每项最多十个来源的递推。上游和前五实际
主路径均利用这一点，代码里的大块 NTT 库不是本题执行内容。

## 1. `K=0` 合法，常数项不会出现在输入中

第一行是 `N K`，后面 `K` 行 `(d,a_d)`；所有下标严格递增且
**大于 0**，所以 `F_0=0` 隐含在输入格式里。未给出的系数为 0。
`0≤K≤10`，模数 `p=998244353`，输出始终有 `N` 项。

`K=0` 表示整个 `F` 为零，答案为 `1` 后接 `N−1` 个零。
特别地，`N=1` 时只能有 `K=0`，输出 `[1]`。

形式指数为 `1+F+F²/2!+…`；`F_0=0` 使次数小于 `N` 的结果
只依赖有限项。模分数按逆元处理，不对系数逐项调用实数 `exp`。

例如 `N=8,K=2`，输入 `(2,2),(5,1)`，即 `F=2x²+x⁵`。
利用 `exp(2x²)exp(x⁵)` 或直接展开，可得

$$
G=1+2x^2+2x^4+x^5+\tfrac43x^6+2x^7\pmod{x^8}.
$$

答案为 `[1,0,2,0,2,1,4/3,2]`。它比输入拥有更多非零项，数组
必须按 `N` 分配；无需给答案再乘阶乘。

## 2. 把 `G'=F'G` 展开后，零输入项自动消失

比较第 `n−1` 项：

$$
g_0=1,\qquad
n g_n=\sum_{\substack{d\le n\\a_d\ne0}}d a_d g_{n-d}.
$$

预先令 `w_d=d a_d mod p`，则每轮只做固定权重的短点积，
最后乘 `n^{-1}`：

```text
weights = [(d, d*a_d mod p) for 输入的每一项]
g[0] = 1
for n = 1 .. N-1:
    sum = 0
    for (d,w) in weights:
        if d>n: break
        sum += w*g[n-d]
    g[n] = sum / n
```

所有偏移为正，右侧只引用更低下标；输入按下标排序，允许及时
`break`。`N<p`，因此所用下标均有逆元。

### 2.1 按递推重新算例子

`F=2x²+x⁵` 的两个固定权重是 `(2,4),(5,5)`：

| 下标 | 求和分子 | 答案 |
|---:|---|---|
| 2 | `4g0=4` | `2` |
| 4 | `4g2=8` | `2` |
| 5 | `4g3+5g0=5` | `1` |
| 6 | `4g4+5g1=8` | `4/3` |
| 7 | `4g5+5g2=14` | `2` |

下标 1、3 的分子为零，所以答案为零。若最小偏移很大，其前面
除常数项以外的系数都可直接保留为零，循环可从最小偏移开始。

### 2.2 这不是对输出做“稀疏乘法”

`g` 可以稠密；节省的是求和时只访问输入的 `K` 个固定偏移。
乘积数量为 `Σ_d(N−d)`，至多 `NK`。加上逆元表、初始化与输出，
时间 `O(NK+N)`，空间 `O(N+K)`。

对 `K=0`、只有一个很高偏移等输入，正确的早退或起始位置能减少
递推工作，但写出完整答案仍需 `O(N)`。
若扩展到稠密输入，才需要考虑 `O(N log N)` 的 NTT 指数或在线
卷积；本题上限下不能凭模板里出现 `exp_ntt` 就推断它被调用。

### 2.3 延迟取模的前提是先把权重归约

若累加的每个因子都在 `[0,p)`，至多 16 个乘积满足
`16(p−1)²<2^64`，可以使用 `uint64_t` 合并成一次取模。
本题最多 10 项，所以 cp-algo 的这个分支适用。

这里的乘积必须是 `(d*a_d mod p)*g[...]`。若直接把三个未经
归约的整数 `d*a_d*g[...]` 填进 64 位累加器，上述界便不成立。
十个接近最大值的乘积还可能超过有符号 64 位范围，不能随意把
`uint64_t` 改成 `int64_t`。

## 3. 上游已预先计算导数权重

[题面](../../../upstream/polynomial/exp_of_formal_power_series_sparse/task.md)、
[配置](../../../upstream/polynomial/exp_of_formal_power_series_sparse/info.toml)
和[上游 correct.cpp](../../../upstream/polynomial/exp_of_formal_power_series_sparse/sol/correct.cpp)
中的 `main` 保存稀疏输入，建立稀疏导数 `(d−1,d*a_d)`。
第 `n` 项使用 `F[n−1−(d−1)]`，正好就是 `g[n−d]`。

导数项有序，上游已在偏移太大时 `break`，并且已经把 `d*a_d`
预乘一次。逆元表按需线性扩展，不是每项做一次快速幂。
因此这些不是前五独有的算法突破。

可见剩余成本主要是每项模乘和加法归约、逆元表组织、数组清零、
以及 `printf` 输出。常量 `%p` 的机器指令由编译器决定，不能
把源码取模次数直接换算成硬件除法次数。

### #400459：预乘权重，短点积一次归约

入口明确调用 `exp_sparse`。它从稠密容器提取非零项，预先乘
下标，然后每项调用 `sparse_dot`，最后乘 `small_inv(i)`。
最多 10 项、模数小于 `2^30`，因此实际走无符号 64 位延迟取模。

`small_inv` 第一次调用时通过一次总乘积求逆和前后扫描，固定
准备到 `2^20−1`，覆盖题目上界。小输入也可能支付这段固定准备。
`K=0,N>1` 时该函数仍逐项调用 `small_inv`，没有专门跳过整个
逆元缓存；相反，某些其他实现会直接返回常数数组。

打包的浮点 FFT 不执行，`blazingio` 负责实际读写。编译目标上的
SIMD 支持不能直接等同于这条短递推做了向量卷积。

### #307818 与 #405987：通用 FPS 接口选中稀疏分支

两份都通过 `Yosupo_exp_of_sparse_formal_power_series→exp(a)`
进入 `FPS::exp`。非零项阈值为 50，而本题 `K≤10`，所以调用
`exp_sparse`，不会落入通用 Newton 或 NTT 分支。

`exp_sparse` 提取 `(d−1,d*a_d)`，然后按上游同一递推求值。
它通过 `BiCoef(deg)` 准备整数逆元，额外同时建立阶乘、逆阶乘
数组；本题的递推不需要这两张表，因此存在额外线性初始化和内存。
入口先分配长度 `N` 的输入，`K=0` 也仍是非空容器，会经过稀疏
分支的表准备和答案循环。

两份打包源码并非逐字相同，不能当成同一提交文本；但本题入口
与上述 `exp_sparse` 数学路径一致。实际 I/O 为 `FastRead/FastWrite`，
39/42 ms 混合了库版本、编译和整程序成本，不能只按用户名解释。

### #402929：Nim 直接稀疏类型，跳过零前缀

源码外壳约 20 行，内嵌压缩库已按其中的解包算法在本地展开核查。
入口类型是 `SparseFPS[modint998244353_barrett]`，实际执行
`SparseFPS.exp`，不是普通稠密序列的 `exp`。

它准备 `(d,d*a_d)`，无项时立刻返回常数 1 数组，否则从最小
非零下标开始递推。只准备当前精度的线性逆元表，乘法使用 Barrett
类型；最后用 `join(" ")` 生成完整输出文本。
大库中的 NTT、松弛卷积、矩阵幂投影都不进入该路径。
打包模板声明 `-mavx2`，移植时仍须检查构建目标。

### #375638：保持稀疏输入，导数下标在内层相乘

Rust 入口直接把 `K` 个对收进 `SparsePolynomial`，调用
`f.exp(n)`。空表时直接返回 `1` 补零到 `N` 项；否则线性建立
逆元表，逐项计算 `f_d*g[n−d]*d`，再乘 `1/n`。

与其他几份预乘权重的写法相比，它在每个有效求和项中再乘一次
`d`。这增加了内层模乘，但减少一个权重转换步骤；源码事实不能
自动等同于整程序速度差，因为模表示、缓冲和编译也不同。
函数使用 `take_while` 排除未来偏移，输出缓冲打印所有 `N` 项。

## 5. 边界与可解释的实验

| 检查点 | 原因 |
|---|---|
| `K=0` | 合法且答案常数为 1 |
| 所有输入下标都大于 0 | 确保形式指数定义和三角依赖 |
| 下标乘权重先取模 | 延迟归约的乘积范围依据 |
| 每轮最后除以全局 `n` | 分母不是偏移 `d` |
| 最小偏移很大 | 前面可以跳过计算，但不能漏输出零 |
| 单项式 `cx^d` | 只有 `kd` 位置可非零，值为 `c^k/k!` |

五份文件的 SHA-256 已与配置匹配；Nim 实现来自原文件的本地
解包内容。本地对 128 组长度 `1..32`、包含 `K=0` 的随机输入，
比较稀疏递推与直接按 `ΣF^k/k!` 展开的结果，全部系数一致。没有新增候选编译、OJ/API 请求或性能测试。

如果比较模约减优化，保持相同权重和逆元表，只切换逐项归约与
整段累加，并保留溢出界检查。比较输出时应打印相同完整数组，
因为输入至多十行，输出却最多一百万个整数。若只测计算内核，
应明确结果不包含整程序的重要输出成本。
