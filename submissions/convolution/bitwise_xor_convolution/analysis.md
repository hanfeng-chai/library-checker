# XOR 卷积：为什么一组加减蝶形就能代替枚举所有数对

## 1. 先把题意算一遍

[题目](../../../upstream/convolution/bitwise_xor_convolution/task.md)给定两条
长度 L=2^N 的数组 A、B，求 C[k]=Σ A[i]B[j]，求和条件为 i XOR j=k，
答案对 998244353 取模。[参数](../../../upstream/convolution/bitwise_xor_convolution/info.toml)
规定 0≤N≤20。XOR 的每位规则是“相同得 0、不同得 1”。

例如 N=2，A=[1,2,3,4]、B=[5,6,7,8]：

| k | 所有满足 i XOR j=k 的乘积 | C[k] |
|---:|---|---:|
| 0 | 1×5 + 2×6 + 3×7 + 4×8 | 70 |
| 1 | 1×6 + 2×5 + 3×8 + 4×7 | 68 |
| 2 | 1×7 + 2×8 + 3×5 + 4×6 | 62 |
| 3 | 1×8 + 2×7 + 3×6 + 4×5 | 60 |

输出 [70,68,62,60]。每个 i 与 k 唯一决定 j=i XOR k，
但对每个 k 都枚举 L 个 i，仍需 O(L²)=O(4^N) 工作。
最大 L=2²⁰ 时约有 1.10×10¹² 对数。不同 k 之间必须共享计算，
才能达到题目所需规模。

普通卷积以 i+j 为目的下标，[AND 卷积](../bitwise_and_convolution/analysis.md)
以 i AND j 为下标；本题规则不同，不能只改最后一个运算符就复用原变换。
下面从一位下标推导专用于 XOR 的变换。

## 2. 两个元素时，答案的“和与差”反而更容易算

设 A=[a0,a1]，B=[b0,b1]，按定义：

~~~text
c0 = a0·b0 + a1·b1
c1 = a0·b1 + a1·b0
~~~

两个式子分别看要四次乘法，但加起来和减开后：

~~~text
c0+c1 = (a0+a1)(b0+b1)
c0−c1 = (a0−a1)(b0−b1)
~~~

把 [a0,a1] 表示成 [a0+a1,a0−a1]，B 也一样，
只需对应两项各乘一次，就得到答案的和与差。再由
c0=(和+差)/2、c1=(和−差)/2 恢复。

变换 T(u,v)=(u+v,u−v) 再做一次，得到 (2u,2v)，
所以逆变换就是同一个操作后除以 2。所有除法在模意义下乘逆元；
模数是奇数，2 的逆元存在。本题 2⁻¹=(998244353+1)/2。

这个两输入、两输出的加减操作也叫蝶形。它不含 NTT 的旋转因子，
没有浮点复数，更不需要搜索高阶单位根。

## 3. 多个 bit：分别变换每一位

XOR 在每一位独立进行。因此对数组中只差第 b 位的每对下标做上述蝶形，
依次处理全部 N 位，即得到 Walsh–Hadamard 变换，常缩写为 FWT/FWHT。

~~~text
for w = 1,2,4,…,L/2:
    for 每个长度2w的连续块:
        for i = 0 .. w-1:
            u = block[i]
            v = block[i+w]
            block[i]   = u+v
            block[i+w] = u−v
~~~

原地实现必须先保存 u、v。若覆盖前半后用更新过的值去计算后半，
就不再是同一个蝶形。每层有 L/2 对，共 N 层，时间 O(NL)，额外工作区可为 O(1)。

### 3.1 四元素的全过程

前面的 A、B 可以先在普通整数中手算，最后再理解模运算：

~~~text
A: [1,2,3,4] -> [3,-1,7,-1] -> [10,-2,-4,0]
B: [5,6,7,8] -> [11,-1,15,-1] -> [26,-2,-4,0]
逐项相乘：                      [260,4,16,0]
再做相同FWT：                   [280,272,248,240]
每项除以4：                     [70,68,62,60]
~~~

负数在真实程序里存为相应的模余数，例如 −2 存成 p−2。
这个手算例与第一节直接枚举完全一致。

### 3.2 为什么变换后可以逐点相乘

对每个变换下标 s，给输入下标 i 一个符号：
若 s AND i 的置位数为偶数，取 +1；为奇数，取 −1。
记这个符号为 χs(i)。例如 s=01 时，四个下标的符号是 [+1,−1,+1,−1]。
FWT 的第 s 项就是 Σχs(i)A[i]。

XOR 会把各位的奇偶性相加，所以 χs(i XOR j)=χs(i)χs(j)。
于是答案的变换为：

~~~text
Σ χs(k)C[k]
 = Σ_i Σ_j χs(i XOR j)A[i]B[j]
 = (Σ_i χs(i)A[i]) (Σ_j χs(j)B[j])
~~~

这就是逐点乘法成立的原因。它与 NTT 都有“先换表示再相乘”的共同思路，
但这里的权重只取 ±1，来自 XOR 的位奇偶性。

### 3.3 为什么最后除以 L，而不是只除以 2

每处理一位，两次相同蝶形都带来一个因子 2。
N 位一起做两次，整个数组放大 2^N=L 倍，因此第三次 FWT 后乘 L⁻¹。
也可在逆过程每层都除以 2，代数上等价，但会改变运算次数和实现方式。
下面第三名源码虽定义了逐层除二的函数，实际入口没有调用它。

FWT 只要求这个 L 可逆；对 2 的幂 L，任何奇数模数都满足。
它不要求 L 整除 p−1。上游使用的特殊逆元表达式另依赖本题模数，
不能把那个快捷式的条件误当成 FWT 本身的条件。

## 4. 上游 correct.cpp 的真实流程

[上游源码](../../../upstream/convolution/bitwise_xor_convolution/sol/correct.cpp)
用三条 vector<modint> a、b、c，关闭 iostream 同步后：

~~~text
读a -> walsh_hadamard(a)
读b -> walsh_hadamard(b)
c[i] = a[i]*b[i]
walsh_hadamard(c)
输出 c[i]*inv
~~~

walsh_hadamard 正是上一节的 w/块/偏移三层循环。
加减立即规范到 [0,p)，乘法用 64 位乘积后 %p。
总时间 O(NL)，三个变换共 3NL/2 个蝶形；
每个蝶形有一次加、一次减，另有 L 次点乘及 L 次缩放。
三条主数组约 12L 字节，未计输入输出缓冲。

上游将 inv 写成 p−(p−1)/L。因为本题 L 是至多 2²⁰ 的二次幂，
且 p−1=119×2²³，所以这里整数除法恰好整除，
L·(p−(p−1)/L)=(L−1)p+1≡1。一般模数若不满足整除，
应另求 L 的逆元，而不能照抄这个表达式。

## 5. 快解可以怎样减少同一变换的工作

### 5.1 结果覆盖 a，避免第三条数组

点乘后不再需要原来的变换值 a[i]，因此写回 a，
第三次变换继续原地进行。两条主数组约 8L 字节，
少于上游三数组的 12L。固定上限静态数组与按实际 L 分配的向量
还会产生不同的虚拟空间、触页和分配行为；OJ RSS 不等于这两个数字。

### 5.2 合并两层蝶形，让中间值留在寄存器

对四个值 x0,x1,x2,x3，先算
s0=x0+x1、d0=x0−x1、s1=x2+x3、d1=x2−x3，
再输出 [s0+s1,d0+d1,s0−s1,d0−d1]。
这恰好完成两位的变换，中间 s、d 可以不写回数组。
四分递归把这种内核应用到连续小块，二分递归每次只合并一位；
它们都实现相同的符号求和，区别在访问次序、循环和编译展开。

### 5.3 SIMD 要分别处理“槽内邻居”和“远距离邻居”

八个 32 位数放进一个 AVX2 寄存器。前几位的配对距离为 1、2、4，
配对元素都在这个寄存器内，需要 shuffle/permute 搬到对应槽，
再依据目标位置选择加或减。更高位的距离超过八项时，
则从两个不同数组片段各加载一条向量，对应槽直接做蝶形。
这解释了 #170283 为什么先有特殊的十六元素内核，再进入较大步长循环。

模乘仍需 64 位中间积，不能把一次 256 位加载等同于八路完整模乘指令。
同时取偶、奇槽的乘积、再合并约减结果，也有实际指令成本。

### 5.4 缩放放在哪里，必须跟踪表示

因为 FWT 线性，乘 L⁻¹ 可以放在最后，也可以提前乘进点值乘积。
若同时使用 Montgomery 约减，还要补偿它的 R⁻¹ 因子。
只把末尾缩放循环删掉而不补因子，会得到放大或错误编码的答案。
#170283 将缩放和 Montgomery 因子一起放入点乘阶段，
后面的第三次 FWT 直接产生普通余数。
Montgomery 的完整手算可参阅 [模卷积教程](../convolution_mod/analysis.md)。

### #400553 / #405716：四分递归

实际链为 solve→xor_convolution_inplace→xor_transform。
with_bit_floor 把运行时长度分派到编译期模板；长度 1 直接返回，
长度 2 做一个蝶形，其他情况递归四个子块，再合并两层。
两份源码统一换行后逐字节相同，不能用 25/26 ms 差距解释成算法改动。

点乘和第三次变换都覆盖 a，之后另遍历乘 base(L).inv()。
I/O 使用手写读取和输出缓冲，虽然 main 还设置了 iostream 同步，
实际 solve 用 read/println。源码还记录 stderr 阶段计时；
那与 OJ 汇总的完整程序时间不是同一测量口径。

### #357194：二分递归，未调用逐层除二的逆函数

solve_main 对两个 uint32 数组调用 fwt_xor，逐点乘写回 a，
再调用一次 **fwt_xor**。随后快速幂求 L^(p−2)，统一乘回并输出。
模板里的 ifwt_xor 在每层模意义除以 2，但这条接口未被 main 调用；
不能据文件中出现该函数就把逐层除二计入真实热路径。
模加减通过无符号 min 形式规范化，点乘及缩放用 64 位 %p。
输入映射、输出缓冲来自 FastIO，而不是上游的 iostream 格式化路径。

### #170283：SIMD 与缩放因子真正融合的位置

main 申请对齐的两个 uint32 数组，直接以普通余数读入，
调用 Cum::convolve_xor。fwht 对 L≤8 用标量循环；
更大输入先用 shuffle、blend、半区交换完成寄存器内三层，
再合并两个八元素寄存器完成第四层。更高层尽量两层一次处理，
末尾若只剩一层则走单层分支。

convolve_xor 做两次 fwht 后，构造普通数值 f=R²/L mod p。
内部两次 Montgomery 乘法为 REDC(f·REDC(a·b))，
总的 R⁻² 恰好抵消 f 的 R²，因此点乘结果为 ab/L 的普通表示。
第三次 fwht 后便直接输出，不再额外乘逆元。
这需要实际跟踪因子；不能因出现 Montgomery 类，就说输入数组全程是 xR 编码。
I/O 采用映射文件和约 256 KiB 输出缓冲。

### #243969：传统三层循环与 Montgomery 模数类

main 把读入系数构造成 MontgomeryModInt，逐位循环做两次 fwt_xor，
点乘覆盖 a，再调用 ifwt_xor：后者先做 fwt_xor，
然后乘 MI(L).inv()。输出 val() 才还原普通余数。
两条最大长度 2²⁰ 的全局数组保存数据，变换加减允许惰性 [0,2p) 表示。
数学流程与上游相同，主要变化在模数表示、两数组内存和自定义 I/O。

## 7. 对照实验与阅读边界

五个用户只有四份不同执行源码，数学路线均是 FWT→点乘→FWT→归一化，
第四名显式 SIMD 也没有保证比更短的递归实现快。
要解释差距，应固定 I/O 后对照逐位、二分递归、四分递归、SIMD 内核，
再单独对照普通与 Montgomery 约减、缩放前移与末尾缩放。

先用小 N 枚举全部 i,j 验证，覆盖 N=0、只有一个非零项、
所有值接近 p−1 和随机输入；再测大 N 的缓存、吞吐与内存。
常量 %p 可能被编译器转成乘法/移位，不能只从源码记号数硬件除法。
本页验证了手算变换、缩放公式、五份源码哈希及相同文本关系，
没有新增性能结论；全站其他提交和各家族绝对最快仍需更广候选池审阅。
