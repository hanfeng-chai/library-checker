# `convolution_mod_1000000007`：从手算卷积到三模 NTT、拆位 FFT 与快解分流

这题要求把两个数组卷积，最后对 `p = 1,000,000,007` 取模。这个模数不支持本题所需的长二进制 NTT。上游在三个其他模数下分别计算，再用 CRT 合并；快解有的把这条精确整数路线做得更省，有的把系数换一种表示后交给浮点 FFT。

本文按“题意 → 朴素算法 → 变换基础 → 上游实现 → 快解具体省掉什么”展开。小例子和标有“教学伪代码”的代码用来说明数学，不是提交源码的逐行转写；作者实现的结论以末尾列出的本地源码与实际入口为准。

## 1. 题目究竟要算什么

[题面](../../../upstream/convolution/convolution_mod_1000000007/task.md)给两个数组 `a`、`b`，长度分别为 `N`、`M`，要求输出 `N+M-1` 项：

\[
c_k=\sum_{i+j=k}a_i b_j\pmod p.
\]

也就是：把所有“下标相加等于 `k`”的乘积累加到 `c[k]`。根据[配置](../../../upstream/convolution/convolution_mod_1000000007/info.toml)，

\[
1\le N,M\le524288=2^{19},\qquad 0\le a_i,b_i<p.
\]

### 1.1 完整手算一次

取 `a=[1,2,3]`、`b=[4,5]`。每对元素给出的贡献是：

| 来自 `a` 的项 | 乘 `b[0]=4` | 乘 `b[1]=5` |
| --- | --- | --- |
| `a[0]=1` | `4` 加到 `c[0]` | `5` 加到 `c[1]` |
| `a[1]=2` | `8` 加到 `c[1]` | `10` 加到 `c[2]` |
| `a[2]=3` | `12` 加到 `c[2]` | `15` 加到 `c[3]` |

因此

\[
\begin{aligned}
c_0&=1\cdot4=4,\\
c_1&=1\cdot5+2\cdot4=13,\\
c_2&=2\cdot5+3\cdot4=22,\\
c_3&=3\cdot5=15.
\end{aligned}
\]

输出就是 `[4,13,22,15]`。这些数都小于本题模数，取模后不变。

取模不改变“哪些项应该相加”。例如本题中 `a=[p-1,2]`、`b=[3,4]`，可以临时把 `p-1` 看成 `-1`，得到 `[-3,2,8]`，再把负数规范到 `[0,p)`，输出 `[p-3,2,8]`。第 8 节会利用这种较小的整数代表少用 NTT 模数。

### 1.2 为什么卷积就是多项式乘法

把下标写成幂次：

\[
A(x)=1+2x+3x^2,\qquad B(x)=4+5x.
\]

展开乘积：

\[
\begin{aligned}
A(x)B(x)
&=4+5x+8x+10x^2+12x^2+15x^3\\
&=4+13x+22x^2+15x^3.
\end{aligned}
\]

`a[i]x^i` 和 `b[j]x^j` 相乘后幂次是 `i+j`，所以 `x^k` 的系数正好是 `c[k]`。后面说“卷积数组”和“多项式系数”是在描述同一件事。

| 记号 | 含义 |
| --- | --- |
| `p` | 目标模数 `1,000,000,007` |
| `N,M` | 输入长度 |
| `S=N+M-1` | 实际输出长度 |
| `L=bit_ceil(S)` | 不小于 `S` 的最小二次幂，常规完整变换长度 |
| `q`、`q1,q2,q3` | 为 NTT 另选的素数，区别于目标模数 |
| `B` | 某种整数代表下，单个卷积系数的绝对值上界 |

最大 `S=2^20-1`，因此本题最大 `L=2^20`。

## 2. 朴素算法：把每个乘积送到正确位置

下面是可以直接核对题意的教学伪代码：

```text
c = 长度 N+M-1 的全零数组
for i = 0 .. N-1:
    for j = 0 .. M-1:
        c[i+j] = (c[i+j] + 64位整数(a[i]) * b[j]) mod p
return c
```

它进行 `NM` 次乘加，时间为 `O(NM)`，输出之外的辅助空间为 `O(1)`。最大输入下有 `2^38=274,877,906,944` 对元素，远超过这里应有的计算量。

单次 `a[i]*b[j]` 接近 `10^18`，32 位装不下；若每次都把 `c[i+j]` 约减到 `[0,p)`，一次更新可以放进 64 位整数。把最多 `524288` 项乘积全部累积后才取模，则可能达到约 `5.24×10^23`，64 位也装不下。

朴素算法仍适合短输入。`M=1` 时只需把 `a` 每项乘一个数，是线性工作；若为它准备三组变换，数组、单位根和内存准备成本反而很高。快解里的 `min(N,M)≤16`、`≤96` 等阈值都在处理这种情况，阈值属于具体实现的性能选择。

## 3. 变换为什么能把两重循环变小

### 3.1 从“系数”换到“在一些点上的值”

若 `C(x)=A(x)B(x)`，则对任意点 `t` 都有 `C(t)=A(t)B(t)`。如果知道 `A`、`B` 在 `L` 个合适点上的值，就只需 `L` 次逐点相乘，再从 `C` 的这些值恢复系数。FFT/NTT 提供快速转换方式：

```text
系数 a ──正变换──> A 在 L 个点上的值 ─┐
                                     ├─逐点相乘─> C 的值 ─逆变换─> c
系数 b ──正变换──> B 在 L 个点上的值 ─┘
```

FFT 通常在复数中计算，NTT 在模素数的整数中计算。它们采用相似的递归结构，但前者需要分析舍入误差，后者的模运算可以保持精确。

### 3.2 单位根与蝶形的最小背景

长度 `L` 的变换使用一个**阶恰好为 `L`** 的单位根 `ω`：`ω^L=1`，而提前走不到 `1`。求值点为 `1,ω,ω²,…,ω^(L-1)`。

把多项式的偶数幂和奇数幂分开：

\[
A(t)=A_{\rm even}(t^2)+tA_{\rm odd}(t^2).
\]

在 `t` 和 `-t` 上求值时，两个子问题使用同一个 `t²`，结果分别为 `E+tO` 和 `E-tO`。这对加减就是一个“蝶形”。不断把长度减半，有 `log₂L` 层，每层处理 `O(L)` 个数，得到 `O(L log L)` 的正、逆变换。

在模素数 `q` 下，逆变换可写成

\[
c_j=L^{-1}\sum_{k=0}^{L-1}\widehat c_k\omega^{-jk}\pmod q.
\]

这里 `L⁻¹` 是模 `q` 的乘法逆元；“逆变换最后除以 `L`”就是乘这个逆元。

### 3.3 用模 17 的四点变换走一遍

仍用 `[1,2,3]` 与 `[4,5]`，补成 `[1,2,3,0]`、`[4,5,0,0]`。为便于手算，**本小例暂时使用 `q=17`**，取 `ω=4`，因为 `4²≡-1`、`4⁴≡1 (mod 17)`。

| 求值点 | `A(t) mod 17` | `B(t) mod 17` | 相乘 `C(t) mod 17` |
| --- | ---: | ---: | ---: |
| `1` | `6` | `9` | `3` |
| `4` | `6` | `7` | `8` |
| `16=-1` | `2` | `16` | `15` |
| `13=-4` | `7` | `1` | `7` |

例如 `A(4)=1+2×4+3×16=57≡6`。逆变换得到 `[4,13,5,15]`，正是 `[4,13,22,15]` 对 `17` 取模。第零项为

\[
c_0=(3+8+15+7)\cdot4^{-1}\equiv33\cdot13\equiv4\pmod{17}.
\]

这次变换只给出**模 17 的答案**，已经丢失了 `5` 原本可能是 `22` 的信息。第 4 节要补回的就是这些信息。

### 3.4 为什么必须补到 `N+M-1`

在 `L` 次单位根上求值，无法区分 `x^L` 与 `1`，因此长度 `L` 的变换自然计算模 `x^L-1` 的循环卷积。只要真实乘积次数小于 `L`，没有项绕回去，就得到普通卷积。

把 `[4,13,22,15]` 强行压进长度 `2`，会变成 `[4+22,13+15]=[26,28]`。`L≥S` 的补零是为了避免这种重叠。第 9 节会有意识地制造两种重叠，再把它们解开；那需要额外的代数步骤。

## 4. 为什么不能直接模 `1e9+7` 做长 NTT，CRT 怎样补救

### 4.1 缺的是足够长的单位根

模素数 `p` 的非零元素形成大小为 `p-1` 的乘法群，元素的阶必须整除 `p-1`。长度 `2^k` 的标准 NTT 因而要求 `2^k | p-1`。本题

\[
p-1=1,000,000,006=2\cdot500,000,003,
\]

只含一个因子 `2`。标准二进制 NTT 最多直接用到长度 `2`，无法取得本题需要的 `2^20` 次单位根。把其他素数下的 NTT 模板常量改成 `1e9+7`，数学前提就不成立。

上游选择在另外三个适合 NTT 的素数下计算。随后的问题是：知道一个整数的几个余数，怎样得到它对 `p` 的余数？

### 4.2 小模数 CRT：把余数 `3,4,2` 还原成 `123`

取互素的 `5,7,11`。设整数 `T` 满足

\[
T\equiv3\pmod5,\quad T\equiv4\pmod7,\quad T\equiv2\pmod{11}.
\]

逐个满足这些条件：

1. 第一式说明 `T=3+5u`。
2. 代入第二式，有 `5u≡1 (mod 7)`。因为 `5⁻¹≡3`，所以 `u≡3 (mod 7)`，进而 `T=18+35v`。
3. 代入第三式，有 `7+2v≡2 (mod 11)`，即 `2v≡6`，所以 `v≡3 (mod 11)`。

因此

\[
T=3+5\cdot3+5\cdot7\cdot3=123\pmod{385}.
\]

CRT 保证在 `[0,385)` 内答案唯一。`123+385`、`123+2×385` 也有相同余数，因而 CRT 本身没有恢复一个无限大的未知整数。

如果事先知道 `0≤T<385`，就能确定 `T=123`，再求任意目标模数下的余数，例如 `123 mod 17=4`。只用 `5,7` 时恢复的是 `18 (mod 35)`；`18` 与 `123` 模 `17` 分别为 `1` 和 `4`。所以“最后反正要模 `p`，CRT 模数乘积不够大也没关系”不成立。

### 4.3 本题为什么三个模数足够

先把输入当作 `[0,p)` 中的非负整数，暂时不取目标模数。每个系数最多有 `min(N,M)` 项，因此

\[
0\le T_k\le B_{\max}=\min(N,M)(p-1)^2.
\]

全题最大的上界为

\[
524288(1,000,000,006)^2=524,288,006,291,456,018,874,368.
\]

上游选择的三个素数如下：

| 素数 | `q-1` 的分解 | 最大二次幂 NTT 长度 |
| --- | --- | ---: |
| `q1=1,004,535,809` | `479×2^21` | `2^21` |
| `q2=998,244,353` | `119×2^23` | `2^23` |
| `q3=985,661,441` | `235×2^22` | `2^22` |

它们互不相同，都是素数，且都支持 `L≤2^20`。乘积为

\[
Q=q_1q_2q_3=988,393,890,385,622,438,779,027,457>B_{\max}.
\]

每个真实非负系数都落在 `[0,Q)`，三份余数唯一确定它；再模 `p` 就是题目答案。这条正确性论证不依赖浮点精度。

### 4.4 Garner：不用真的存储那个巨大整数

`Q` 超过 64 位，但上游没有构造整个整数 `T`，而是使用混合进制：

\[
T=t_0+q_1t_1+q_1q_2t_2,
\]

其中 `0≤t0<q1`、`0≤t1<q2`、`0≤t2<q3`。三位的计算是

\[
\begin{aligned}
t_0&=r_1,\\
t_1&=(r_2-t_0)q_1^{-1}\pmod{q_2},\\
t_2&=\big((r_3-t_0)q_1^{-1}-t_1\big)q_2^{-1}\pmod{q_3}.
\end{aligned}
\]

最后在目标模数中计算

\[
c_k=t_0+(q_1\bmod p)t_1+(q_1q_2\bmod p)t_2\pmod p.
\]

局部乘法只涉及约 30 位的数，使用 64 位中间乘积即可。`123` 的手算就是混合进制数字 `(3,3,3)` 的例子。Garner 节省了大整数表示与运算，但仍需要 `Q>B` 来证明它恢复的正是原来的非负卷积。

## 5. 上游 `correct.cpp`：真实数据流与开销

[上游源码](../../../upstream/convolution/convolution_mod_1000000007/sol/correct.cpp)的调用链是：

```text
main
  └─ ntt_convolution<1000000007>
       ├─ ntt_convolution<1004535809>
       ├─ ntt_convolution<998244353>
       ├─ ntt_convolution<985661441>
       └─ 对每个输出调用 garner_algorithm_template
```

### 5.1 每个阶段持有什么数据

| 阶段 | 输入 | 输出 | 具体工作 |
| --- | --- | --- | --- |
| 读入 | 文本 | `a[N],b[M]` | `scanf` 逐项读入 |
| 投影 | `a,b` | `x0,x1,x2,y0,y1,y2` | 每个输入系数转换到三个素数下 |
| 第一模卷积 | `x0,y0` | `z0[S]` | 复制、补到 `L`、两次正 NTT、点乘、一次逆 NTT |
| 第二、第三模卷积 | 各自的两份投影 | `z1[S],z2[S]` | 同样的流程，使用不同模数和根 |
| 合并 | 每个位置的三个余数 | `c[S]` | Garner 数字及目标模数下的组合 |
| 输出 | `c` | 文本 | `printf` 逐项输出 |

单模过程的教学伪代码为：

```text
convolution_under_q(a, b, q):
    A = a mod q，补零到 L
    B = b mod q，补零到 L
    A = NTT_q(A)
    B = NTT_q(B)
    for k = 0 .. L-1:
        A[k] = A[k] * B[k] mod q
    A = inverse_NTT_q(A)
    return A 的前 S 项
```

`z0,z1,z2` 是**同一组整数卷积系数的不同余数**。每个模数负责全部输出下标，不是三个模数各负责三分之一的系数。

### 5.2 `ntt_inplace` 的具体成本

函数内部每次调用分配一条长度为 `L` 的工作数组 `b`。每一层从当前数组读取蝶形输入，将结果写到工作数组，再交换两个向量。缓冲在同一次变换中逐层复用，源码没有在每层重新分配它。

每次变换还建立正、逆单位根数组 `ep,iep`。逆变换最后扫描 `L` 项，逐项乘 `L⁻¹`。模乘在源码里是 64 位乘积再 `% PRIME`；模板常量可能让编译器把 `%` 改写为乘法与移位，没有查看汇编时不能把每个 `%` 都记成一次硬件除法。

大输入的一般路径共做 **6 次正 NTT、3 次逆 NTT**，以及三次逐点乘法。若只数二进制蝶形，合计约为

\[
9\cdot\frac L2\log_2L.
\]

整体时间 `O(3L log L)`，额外空间 `O(L)`。空间的大 `O` 隐藏了六条原长投影、保留的三条结果、每模的复制补零数组与变换缓冲，不能理解成只占“一条数组大小”的内存。

### 5.3 源码的小输入分支没有提前返回

两个 `ntt_convolution` 重载都写了 `size≤32` 时的朴素循环，但 `return c;` 被注释掉。局部 `c` 因而不是返回结果，程序仍向下进入 NTT 路径，不能把这段代码描述为已生效的小输入加速。

这影响汇总时间的解释：其他提交在短输入上可能直接完成几十次乘加后返回，上游仍然准备三模变换。小测试拉开的差距不能全归因于大 NTT 内核速度。

## 6. 浮点路线的基础：为什么把一个系数拆成两部分

复数中总能找到任意长度的单位根，所以 FFT 避开了目标模数缺少单位根的问题。但把约 `10^9` 的系数直接送进双精度 FFT，会遇到精度问题：真实整数卷积系数可达 `10^23` 量级，双精度无法逐个精确区分那么大的相邻整数。

拆位方案先减小每次浮点卷积的输入幅度。

### 6.1 用十进制拆位完整计算一个例子

为手算取基数 `s=10`，实际提交会用 `2^15` 或约 `√p`。设

\[
A=[23,14]=A_0+10A_1,\qquad B=[12,35]=B_0+10B_1,
\]

其中

\[
A_0=[3,4],\ A_1=[2,1],\ B_0=[2,5],\ B_1=[1,3].
\]

展开多项式乘法：

\[
AB=\underbrace{A_0B_0}_{C_{00}}
+10\underbrace{(A_0B_1+A_1B_0)}_{C_{01}}
+100\underbrace{A_1B_1}_{C_{11}}.
\]

每个小卷积都能手算：

| 小卷积 | 结果 |
| --- | --- |
| 低位 × 低位：`A0*B0` | `[6,23,20]` |
| 低位 × 高位：`A0*B1` | `[3,13,12]` |
| 高位 × 低位：`A1*B0` | `[4,12,5]` |
| 两个交叉项相加：`C01` | `[7,25,17]` |
| 高位 × 高位：`A1*B1` | `[2,7,3]` |

于是

\[
\begin{aligned}
c_0&=6+10\cdot7+100\cdot2=276,\\
c_1&=23+10\cdot25+100\cdot7=973,\\
c_2&=20+10\cdot17+100\cdot3=490.
\end{aligned}
\]

直接算也得到 `23×12=276`、`23×35+14×12=973`、`14×35=490`。真实程序最后再模 `p`，不需要把这些“数字”做进位；拆位只是代数恒等式。

### 6.2 为什么是四份正变换、三份逆变换

教学上可以先把 `A0,A1,B0,B1` 分别变换。每个频点构造

```text
F00 = FA0 * FB0
F01 = FA0 * FB1 + FA1 * FB0
F11 = FA1 * FB1
```

再把三份结果逆变换，得到低低、交叉、高高三个卷积。两个交叉项可以在频域相加，所以不用为它们分别做逆变换。

这是数据依赖的解释。提交中的 SIMD FFT 把系数打包进复数的实部、虚部与向量通道，并把部分最底层蝶形融进乘法内核。“四正三逆”描述四条输入谱和三条输出谱的调用关系，不能直接当作七次普通、完整长度 `L` 的教科书复数 FFT 来比较耗时。

### 6.3 拆位改善精度，舍入仍需要条件

以 `s=2^15` 为例，低位小于 `32768`，高位也只有约 15 位。长度上限下，低低项的粗上界约为 `2^49`，两个交叉项合起来约为 `2^50`，远小于原先的 `10^23`。

理想的逆变换结果应为整数，实际可能是 `22.00000003`。只有误差绝对值小于 `0.5`，四舍五入才保证得到 `22`。即使最终整数小于双精度能逐个表示整数的界 `2^53`，中途的根近似、复数乘法和加减仍会产生误差；数值大小条件不是完整的误差证明。

还应先舍入各个小卷积，再以整数或经过控制的模运算组合。若 `C01` 舍入错了 `1`，最终答案可能相差 `s`，最后取模不会自动修复它。

## 7. #368722：15 位拆分，加一层可逆的随机缩放

[源码](../../selected/convolution_mod_1000000007/368722.cpp)的真实入口是 `main → work → conv`。它主要沿第 6 节的路线计算，但还做了一步代数预处理。

### 7.1 随机缩放为什么不改变答案

`work` 随机选择非零 `k`，把输入换成

\[
a'_i=a_i k^{i+1}\pmod p,\qquad b'_j=b_j k^{j+1}\pmod p.
\]

固定输出下标 `t=i+j` 后，所有乘积都多出相同因子：

\[
c'_t=\sum_{i+j=t}a_i b_j k^{i+j+2}=k^{t+2}c_t\pmod p.
\]

输出时乘 `k^{-(t+2)}` 即可恢复。例如取 `k=2`，`[1,2,3]` 与 `[4,5]` 变成 `[2,8,24]` 与 `[8,20]`，卷积为 `[16,104,352,480]`，各项恰是 `[4,13,22,15]` 乘 `[4,8,16,32]`。

它改变了送入 FFT 的数值分布。精确算术中的可逆性可以证明，对舍入误差的帮助需要实验或误差分析，不能由恒等式推出“永远不会浮点出错”。

源码的 `mt19937_64` 种子是常量加系统时钟计数，重复运行可能选到不同 `k`；这里没有调用 `random_device`。复现实验应记录或固定实际种子。

### 7.2 数组怎样走过实际内核

| 函数 / 内核 | 实际动作 | 对应的数学 |
| --- | --- | --- |
| `conv` 短输入分支 | `min(N,M)≤16` 时直接模乘并返回 | 朴素卷积 |
| `to_poi` | `x & 32767` 与 `x >> 15` 放进两条数组 | `x=x0+2^15*x1` |
| 四次 `_vfft` | 处理 `a0,a1,b0,b1` | 四条拆位输入谱 |
| `calc` / `KIL` | 写回 `a0=低低`、`a1=两交叉之和`、`b0=高高` | 三个待逆变换的积 |
| 三次 `_vifft` | 处理 `a0,a1,b0` | 回到三个小卷积 |
| `un_poi` | 取整、SIMD Barrett 约减、加权相加 | `C00+2^15*C01+2^30*C11 mod p` |
| `work` 输出循环 | 乘连续的逆幂 | 撤销 `k^(t+2)` |

`lm=bit_ceil(S)/2`。`to_poi` 把前半与后半的系数放在复数的不同部分，每个 `vcpx` 又包含四个双精度通道。读源码时要区分 `L`、`lm` 与 `vlm=lm/4`，不能把 SIMD 容器元素数误认成多项式长度。

文件里还有 `_vdot` 与演示测试代码，但 `conv` 的主路径使用展开后的 `calc/KIL` 内核。只搜索一个叫“点乘”的函数，可能会找到没有执行的代码。

### 7.3 相对上游省了什么，又多了什么

它消去了三模整数投影、三模 NTT 和 Garner，改为双精度 AVX2/FMA 运算及拆位组合；交叉项在频域合并，共用三份逆结果。代价包括拆分、舍入、随机缩放及撤销缩放，还有多条双精度缓冲，快照内存约 `43.0 MB`。

输入输出是手写缓冲，较大数组分配还调用 `mmap/madvise`；主路径向标准错误写阶段计时，这些成本也进入 OJ 汇总时间。文件用 `#pragma GCC target("avx2","fma")` 指定目标特性，这个入口没有先检测 CPU 再选标量版本。

## 8. #403507：在精确 CRT 路线上少做整组 NTT

[源码](../../selected/convolution_mod_1000000007/403507.cpp)的入口是 `main → convolution_io → compute`。先看如何减少变换组数，再看怎样缩小或优化每一组。

### 8.1 居中代表：`p-1` 可以当作 `-1`

目标答案只关心模 `p`，所以可以把系数换成

\[
\widetilde a_i=\begin{cases}
a_i,&a_i\le\lfloor p/2\rfloor,\\
a_i-p,&a_i>\lfloor p/2\rfloor.
\end{cases}
\]

`b` 同理。得到的整数卷积可能为负，但最终模 `p` 不变。如果很多输入接近 `p`，幅度会显著减小：`p-1,p-2,p-3` 变成 `-1,-2,-3`。

例如 `a=[p-1,2]`、`b=[3,p-4]`，居中后为 `[-1,2]`、`[3,-4]`，整数卷积只有 `[-3,10,-8]`。没有必要恢复原先非负表示下约 `p²` 的巨大乘积才能得到目标余数。

### 8.2 上界从整个数组计算

定义

\[
S_a=\sum_i|\widetilde a_i|,\quad M_a=\max_i|\widetilde a_i|,
\quad S_b=\sum_j|\widetilde b_j|,\quad M_b=\max_j|\widetilde b_j|.
\]

对任意输出下标，

\[
\left|\sum_{i+j=k}\widetilde a_i\widetilde b_j\right|
\le\min(S_aM_b,S_bM_a)=B.
\]

第一项来自“把所有 `|a_i|` 都累加，把配对的 `|b_j|` 放大到最大值”；交换两者得到另一界，取较小的即可。`bounded_primes` 正是完整扫描数组得到这些量，用 128 位中间值计算 `B`。

前 16 项只作预筛：如果看起来不值得计算更紧的界，就回退三模；通过预筛后仍检查全数组。抽样没有证明其余位置也小，程序不会凭样本直接宣告“一模足够”。

### 8.3 为什么有符号恢复需要 `Q>2B`

真实系数现在在 `[-B,B]`。为避免两个不同整数相差一个 `Q` 却拥有相同余数，这个区间宽度必须小于 `Q`，即 `Q>2B`。

CRT 先给 `[0,Q)` 中的代表 `v`。若 `v>Q/2`，解释为 `v-Q`；否则就是 `v`。例如 `-3 mod 23=20`，在已知 `|T|<23/2` 时，`20` 应还原成 `-3`，最后输出 `p-3`。

上面的例子有 `Sa=3,Ma=2,Sb=7,Mb=4`，故 `B=min(12,14)=12`。教学上选模数 `29>24`，余数 `[26,10,21]` 就能唯一还原 `[-3,10,-8]`。这个小数组在实际提交会先走朴素分支；例子只解释上界逻辑。

实际 `bounded_primes` 的素数顺序和选择为：

| 完整上界条件 | 实际选择 | 省掉的主要工作 |
| --- | --- | --- |
| `B=0` | 直接输出全零 | 所有变换 |
| `2B<897581057` | 一模 | 两个模数卷积和多模合并 |
| 上式不满足，但 `2B<897581057×880803841` | 两模 | 第三个模数卷积 |
| 都不满足，或预筛拒绝 | 三模非负整数方案 | 保留全题范围的正确性界 |

“一模”一般就是两次正 NTT 加一次逆 NTT，平方或其他分流还可以再省。若两边长度均为 `100000`，居中后每项绝对值不超过 `10`，粗界 `B≤10^7` 足以通过一模条件；均匀的大余数通常需要三模。

### 8.4 短尾：为几项数据把变换翻倍很贵

设 `N=M=513`，则 `S=1025`、常规 `L=2048`。把长输入最后一项取出，写成

\[
A(x)=A_{\rm head}(x)+a_{512}x^{512},
\]

于是

\[
AB=A_{\rm head}B+a_{512}x^{512}B.
\]

主体输出长度是 `512+513-1=1024`，可以使用一半长度的变换；尾部只是把 `B` 乘一个数，再平移相加，额外付出 `513` 次乘加。

实际 `compute` 在 `min>96` 且 `bounded_primes` 没有处理完时，检查 `L≥2048` 和 `excess=S-L/2≤8`。从长输入末尾取出 `excess` 项，主体调用 `compute_ntt`，每个尾系数用 `add_scaled` 加回。额外工作为 `O(excess×短输入长度)`。

分流顺序很重要：一模/两模若已成功，就不会再进入短尾优化，不能无条件叠加两者的理论收益。

### 8.5 长短不均衡：overlap-add 如何复用短输入

短数组长度 `M` 很小、`N` 很大时，一次大变换会携带大量短输入的零。把长多项式分块：

\[
A(x)=A_0(x)+x^hA_1(x)+x^{2h}A_2(x)+\cdots,
\]

则

\[
AB=A_0B+x^hA_1B+x^{2h}A_2B+\cdots.
\]

每块单独卷积，再加到对应偏移。相邻块结果有重叠，需要在重叠处相加，所以叫 overlap-add。手算例子如下：

```text
A=[1,2,3,4]，B=[5,6]，A 按两项一块
[1,2]*[5,6] = [5,16,12]       加到位置 0,1,2
[3,4]*[5,6] = [15,38,24]      加到位置 2,3,4
合并结果        [5,16,27,38,24]
```

每块使用同一个 `B`，其正变换可以只做一次。`blocked897/blocked880/blocked754` 在循环外填充、变换短输入；循环内只变换当前长块、相乘、逆变换和叠加。

门槛是非平方，传入 `engine` 的第一输入长度至少为第二个的 `8` 倍，第二个长度至少 `128`。分块变换长度 `z=bit_ceil(4M)`，步长 `h=z-M+1`，保证每块结果不超过 `z`。三模主路径先交换到长输入在前；一、两模的 `bounded_primes` 保留原输入次序，因此能否触发分块也受输入顺序影响。

对 `K` 个长块，每模大致需要一次短输入正变换、`K` 次长块正变换及 `K` 次逆变换，时间为 `O((2K+1)z log z)`，另加叠加成本。它与一次大变换在常数、缓存行为上有取舍，不能只数“变换调用更多了”就判定更慢。

### 8.6 三模保底也优化了每一步

三模 `compute_ntt` 的局部顺序是 `754974721 → 880803841 → 897581057`，与一、两模的顺序不同。三者乘积约 `5.969×10^26`，大于全题非负整数上界；其 `q-1` 分别含 `2^24,2^23,2^23`，也都支持本题长度。

| 源码机制 | 直观含义 | 相比基线减少的工作 |
| --- | --- | --- |
| `small`、`small_scalar`、`small_simd` | `min≤96`，或 `min≤128 && max≥8192` 时直接求和 | 省掉短输入的三模准备与变换 |
| 内容相同的输入走 `sq` | `A*A` 的两份谱相同 | 省一份输入正变换，使用平方叶块 |
| AVX2 Montgomery 内核 | 用适合整数向量指令的表示做模乘 | 多通道同时处理 |
| radix-4 与缓存遍历 | 合并两层二进制结构，优先处理缓存内的小块 | 减少中间往返和调度 |
| 8/16 点 `leaf_products` | 分解到小多项式后直接做叶块积 | 合并最后几层变换与乘法 |
| `arena` 跨模复用 | 三个模数顺序使用工作区 | 减少保留的投影与临时数组 |
| `fixed_mul`、流式 Garner | 预计算固定乘数，成组重建后直接写出 | 减少标量操作和额外结果向量 |

Montgomery 以 `xR mod q` 保存 `x`，其中 `R=2^32`，利用低位乘法、加法和移位约减。奇数 `q` 下 `R` 有逆元，只要输入、根和输出的表示匹配，结果就是精确模运算。代码还混用普通与 Montgomery 表示来融合转换，不能看到 `montgomery_raw` 就假定所有数组始终使用同一种表示。

`fixed_mul` 用 Shoup 式固定乘数约减：预存与常量 `K` 和模数有关的倒数近似，以乘积高位估计商，再修正余数，适合 Garner 中重复乘同一逆元的情况。三模最后一位还写成

\[
t_2=(r_3-r_1)(q_1q_2)^{-1}-t_1q_2^{-1}\pmod{q_3}.
\]

它与第 4 节公式等价，将一条串行依赖改成两次独立常量乘法，便于处理器重叠执行；收益大小仍需测量。

下面是省略底层内核、保留重要顺序的**源码分派摘要**：

```text
compute(a,b):
    if min_length > 96:
        if bounded_primes 用完整界处理成功: return
        if L >= 2048 且 S-L/2 <= 8:
            主体交给 compute_ntt，短尾直接乘加，return
    compute_ntt(a,b)

compute_ntt(a,b):
    if min<=96 或 (min<=128 且 max>=8192): 直接乘，return
    识别内容相同的两输入；将长输入交换到前面
    顺序执行三模 engine，可能在各 engine 中分块或走平方
    用固定常量重建并输出
```

一般时间仍为 `O(3L log L)`，额外空间 `O(L)`，但输入允许时可少用模数或缩小变换。快照内存约 `32.4 MB`。它使用手写 mmap/缓冲 I/O，并编译面向 AVX2、BMI/BMI2、LZCNT、POPCNT 的代码，主入口没有 Rust 那样的运行时标量回退分派。

## 9. #405312 / #405711：把余数变成小整数对，再做两支复数卷积

这两份文件统一换行符后完全相同，下文一起解释。普通大输入路径比常规拆位更难读，可以先忽略格基、相位和 SIMD，先回答：**能否把模 `p` 的数换成较小的复数，而且相乘后仍能恢复原来的模乘结果？**

### 9.1 需要保持的是乘法投影

假设在模 `p` 中找到 `r²≡-d`。用两个整数 `(u,v)` 表示一个余数：

\[
x\equiv u+rv\pmod p.
\]

把这对整数送到复数

\[
z=u+i\sqrt d\,v.
\]

两个复数相乘，对应的整数对为

\[
(u_1,v_1)(u_2,v_2)
=(u_1u_2-dv_1v_2,\ u_1v_2+u_2v_1).
\]

结果按 `u+rv` 投影回模 `p`，因为 `r²≡-d`，恰好得到原来两个余数的积。加法也保持，所以整条卷积可以这样计算。

严格地说，使用的是整数二次环 `Z[t]/(t²+d)` 及其到模 `p` 的投影，再把整数对嵌入复数。由于 `-d` 在 `F_p` 中已有平方根，不能把它含混地称为不可约的 `F_(p²)` 扩域；这里也没有把有限域直接作为子域放进复数。

### 9.2 小例子：模 29 的乘法如何变成小复数乘法

暂取 `p=29,d=1,r=12`，因为 `12²≡-1 (mod 29)`。

余数 `20` 用 `(-2,-3)` 表示，因为 `-2+12×(-3)=-38≡20`；余数 `17` 用 `(0,-1)` 表示，因为 `-12≡17`。对应复数为 `-2-3i` 与 `-i`，于是

\[
(-2-3i)(-i)=-3+2i.
\]

投影回去是 `-3+12×2=21 (mod 29)`，直接算 `20×17=340≡21`，一致。复数输入坐标只有 `0,1,2,3` 量级，小于直接使用 `20,17`。

把 `x` 表示成 `(x,0)` 总是可以，但没有缩小幅度。难点是快速选择较小的那一对整数。

### 9.3 格基是寻找小而等价的整数对的工具

满足 `u+rv≡0 (mod p)` 的整数对，加到任何表示上都不会改变余数。容易写出的两个向量是 `(p,0)` 和 `(-r,1)`；它们的整数线性组合构成二维格子。

模 `29` 的例子里，`(5,2)` 与 `(-2,5)` 都表示零，因为 `5+12×2=29`、`-2+12×5=58`。从 `(20,0)` 出发，

\[
(20,0)-4(5,2)+(-2,5)=(-2,-3),
\]

就缩小了坐标而保持余数不变。

源码 `quadratic::init` 对 `(p,0),(-r,1)` 做二维 Lagrange 约减：反复交换长短基向量，再从长向量减去短向量的近整数倍。长度采用 `u²+d v²`，对应 `u+i√d v` 的长度平方。得到短基以后，每个输入只需少量浮点乘法与取整，就能减去合适的格向量，取得约 `√p` 量级的坐标。

对本题，`least_negated_residue` 选择的最小正 `d` 是 **5**：`-1,-2,-3,-4` 都不是模 `p` 的平方，`-5` 是。所以实际嵌入为 `u+i√5 v`。例如 `474848249` 是 `-5` 的一个平方根；初始化选哪一个根不影响投影逻辑。

### 9.4 两支半长卷积怎样恢复完整结果

常规完整长度为 `L`，实际 `unit2` 令 `n=L/2`，分别计算模 `x^n-1` 和模 `x^n+1` 的乘积。真实乘积长度不超过 `2n`，可写成

\[
C(x)=C_{\rm low}(x)+x^nC_{\rm high}(x),
\]

两部分次数都小于 `n`。两支返回

\[
U=C_{\rm low}+C_{\rm high},\qquad V=C_{\rm low}-C_{\rm high}.
\]

投影回模 `p` 后有

\[
C_{\rm low}=(U+V)/2,\qquad C_{\rm high}=(U-V)/2.
\]

除以 `2` 是模 `p` 乘 `2⁻¹`。代码 `half` 对奇数先加 `p` 再右移，实现同一运算。

用教学长度 `n=2` 看 `[4,13,22,15]`：两支分别得到 `[26,28]` 与 `[-18,-2]`，半和为 `[4,13]`，半差为 `[22,15]`。真实函数为适应向量内核会取至少 `n=8`，这个四项例子只演示重建等式。

第二支的“负循环”指越过第 `n` 项的贡献绕回后取负。`phasevector<4>` 通过带相位的复数求值点实现它，这不要求目标域里存在 `n` 次单位根。

### 9.5 核查实际入口，避免读到另一条实验路线

[源码](../../selected/convolution_mod_1000000007/405312.cpp)的普通大输入调用链是：

```text
main
  └─ cp_algo::math::fft::mul(big_vector<modint<1000000007>>, ...)
       └─ shallow::apply<1000000007>("unit2")
            └─ two<P, false>
                 ├─ branch<P, 0, false>            // alpha=1
                 └─ branch_to<P, 4, false, true>   // alpha=p-1
```

两支的 `negative` 都为 `false`，`Weighted` 也都为 `false`。因此实际普通路径没有使用共轭嵌入或径向加权；文件里的 `scaled2`、`unit4`、`corners4`、`ramp` 等名称属于其他选项或共享设施，不能全部归为这题执行的优化。

每支的源码步骤为：

1. `fill` 先按 `alpha=±1` 折叠超出 `n` 的输入，再把模余数转为小整数对。选格坐标时加入随机流产生的扰动，得到等价的整数代表。
2. 对两个 `phasevector` 分别调用 `forward`。
3. `multiply` 完成叶块相乘及逆变换，末端变换和乘法有融合。
4. 缩放后，`project` 对实部取整、对虚部除以 `√5` 后取整，再按 `u+rv` 还原模余数；第二支产生结果时与第一支合并。

这相当于两支各承担“两份正变换、一份逆变换”的工作，通常是六份长度约 `L/2` 的复数变换。小整数对乘法把低低、交叉、高高的组合折进复数的两个坐标，再通过两支多项式余数恢复全长结果。

### 9.6 本题确实可达的分流

| 条件 | 本题实际行为 |
| --- | --- |
| `min(N,M)<64` | 通用 `mul` 中用 `mul_slow` 朴素乘法 |
| `has_short_tail` | 通用 `quadratic` 路径，直接计算少量高尾并修正绕回 |
| 其余通常输入 | 上述 `shallow::two<P,false>` 两支路线 |
| `large≥2^20` 且满足长短比例条件 | 本题 `large≤2^19`，入口的 overlap-add 分支不可达 |
| `branch_to` 中 `n≥2^20` | 本题两支的 `n≤2^19`，超大缓存分块分支不可达 |

`has_short_tail` 检查 `S-n≤32` 且两输入长度都不超过 `n`，其中 `n=bit_ceil(S)/2`，另有最小内核长度。对本题 `d=5`，通用路径选 `mul_single`：先在整数对坐标中直接求少量高次项，用短 FFT 算带绕回的主体，再扣除绕回贡献并补回高尾。

这与 #403507“剥去一个输入的几项，再与整个另一输入相乘”的短尾实现不同。这里靠末端只有很少对元素会落到高尾来直接求这些项，不能把两者说成同一段代码。

### 9.7 省下的成本与正确性边界

相对上游，它用两支短 SIMD 复数卷积代替三组整数模卷积及 Garner。小坐标转换、投影与半和半差都是线性工作，工作区跨分支复用，快照内存约 `24 MB`。

整数对乘法与两支重建都是精确的代数恒等式，但实际 FFT 仍是浮点。只有两个输出坐标都正确取整，代数证明才能连接到程序结果。格基缩小幅度，随机扰动改变表示，通用源码还有经验性的可用范围检查；这些不能单独替代全输入误差证明。`shallow` 普通两支路径也不能直接套用通用 `quadratic::usable` 的所有分流结论。

两份源码使用相同的 mmap 输入、缓冲输出及面向 AVX2/FMA 等指令的编译目标。29 ms 与 37 ms 的快照差异没有对应的算法或主体源码差异，不能解释为其中一份减少了某组变换。

## 10. #402147：Rust 根据长度与 CPU 特性选择路线

[Rust 源码](../../selected/convolution_mod_1000000007/402147.rs)只有 64 个物理行，许多模块压缩在一行内。应搜索 `impl ConvolveSteps for Convolve<(M,(N1,N2,N3))>` 与 `convolve_mint_avx2`，不能只看类型别名。

入口是 `solve → MIntConvolve<Modulo1000000007>::convolve`。`MIntConvolve` 的别名含有 `167772161,469762049,754974721` 三个 NTT 素数，但覆写的 `convolve` 先进行其他分派。

### 10.1 小输入为什么使用 Karatsuba

写成 `A=A0+x^h A1`、`B=B0+x^h B1` 后，利用

\[
A_0B_1+A_1B_0=(A_0+A_1)(B_0+B_1)-A_0B_0-A_1B_1
\]

就能用三次半规模乘法代替四次。平衡时递归时间约 `O(n^(log₂3))`，到很小的规模再用朴素法。Karatsuba 不需要单位根和 FFT 缓冲，适合某些中小规模。

这份代码的 `convolve_karatsuba` 在短边 `≤30` 时落到朴素法，极不均衡时还会拆长输入。外层是否调用它，由 CPU 特性和长度共同决定。

### 10.2 源码中的分派条件

`@dispatch_avx2_fma` 在 `x86_64` 上同时运行时检查 `avx2` 和 `fma`，否则走另一分支。

| 条件 | 外层选择 |
| --- | --- |
| AVX2/FMA 可用，且 `max≤30` 或 `min≤10` | Karatsuba，随后可能落到朴素法 |
| 无上述特性，且 `max≤384` 或 `min≤128` | Karatsuba |
| 一次待算卷积 `fft_len≤256` 且 `N*M≤8*fft_len` | 局部再次选择 Karatsuba |
| AVX2/FMA 可用，且 `fft_len≤fft_limit` | `convolve_mint_avx2` 浮点路径 |
| 其余 | `convolve_mint_crt` 精确三模路径 |

AVX2/FMA 可用时，源码计算

\[
\text{fft\_limit}=2^{\min(\lfloor\log_2(\lfloor2^{50}/p\rfloor)\rfloor,20)}=2^{20};
\]

不可用时设为 `0`。本题完整卷积长度都在这个浮点长度界内；具备上述特性且未被小输入分流的大输入会进入 FFT。**快照没有记录那次 OJ 的 CPU 分支，不能仅凭 0.051 s 或类型名断言实际走了 FFT 还是 CRT。**

### 10.3 浮点拆分与 #368722 的区别

`split_coefficients` 先将余数居中，再取

\[
s=\lfloor\sqrt p\rfloor+1=31623,\quad
x_1=\operatorname{round}(\widetilde x/s),\quad
x_0=\widetilde x-sx_1.
\]

低位也可以是负数，幅度大致压到 `s/2`，区别于取非负低 15 位。四条拆位输入经过 `fft_soa`，`dot_soa` 生成低低、交叉、高高，三条 `ifft_soa` 恢复并取整，然后组合

\[
C_{00}+sC_{01}+s^2C_{11}\pmod p.
\]

代码预先使用 `s² mod p=14122`，配合 AVX2/FMA 浮点约减。这里也用 `n=L/2` 的实部/虚部打包与四通道双精度布局，正确性仍需要最终舍入无误。该入口没有 #368722 的随机幂缩放。

### 10.4 不平衡分块与 CRT 回退

外层根据短边选择长块大小，基础公式为 `bit_ceil(min_len)*8-min_len+1`，使用 FFT 时还限制每块变换不超过 `fft_limit`。过长的输入按块计算，再按偏移相加。

这条循环对每块调用 `convolve(a_block,b.clone())`，会重新处理短输入。源码此处没有像 #403507 的 `blocked*` 那样显式缓存短输入谱，所以两者虽然都采用重叠相加，省掉的工作并不相同。

CRT 回退把输入投影到三个素数下分别卷积，再精确重建。三者乘积约 `5.950×10^25`，足够覆盖本题的最坏非负整数系数界。通用库还为超出 CRT 容量准备分块，但本题不会因为这个整数容量条件而必须分块。

复杂度随分支而变：小输入 Karatsuba/朴素，中大输入浮点 `O(L log L)`，或精确 CRT `O(3L log L)`，再加可能的分块。Rust 快输入、缓冲输出、分配与运行时 CPU 检测同样进入汇总时间。

## 11. 对照上游：最快一批到底减少了哪些计算

| 方向 | 基线本来要做什么 | 快解如何减少 | 成本或条件 |
| --- | --- | --- | --- |
| 短输入直接乘 | 准备并执行三模变换 | 只做少量乘加 | 规模大后 `NM` 增长很快 |
| 一模/两模 | 不看输入幅度，总做三模 | 完整上界允许时省一、两组卷积 | 需要严格界与有符号恢复 |
| 平方 | 对相同输入做两次正变换 | 复用同一份谱 | 识别相同输入，内核支持 |
| 短尾 | 输出刚过二次幂时长度翻倍 | 小量直接计算换半长变换 | 高尾足够短，正确补回贡献 |
| overlap-add | 大长度上处理短输入的很多零 | 长输入分块；#403507 还复用短谱 | 多次小变换与重叠相加 |
| 拆位 FFT | 三模整数变换加 Garner | 小系数 SIMD 浮点变换、三项组合 | 拆位、双精度缓冲与舍入条件 |
| 二次环整数对 | 三模或三个拆位卷积输出 | 复数乘法携带两个坐标，两支短乘积重建 | 格坐标转换、投影与舍入条件 |
| SIMD、叶块、缓冲复用 | 通用标量蝶形和数组交换 | 减少指令与数据搬运，改善缓存使用 | 复杂的表示与机器特性要求 |

主要大规模路线仍围绕 `O(L log L)`。差距来自长度、组数、数据表示、内存访问和分流，不只是大 `O` 的类别变化。

“九次 NTT”“七条 FFT 谱”“六份半长复数变换”不能直接按数字比快慢。整数模运算与复数的单元素成本不同，打包、叶块融合、逆变换缩放方式也不同。实际收益需要在统一环境和输入上测量。

## 12. 常见误区与可复现的实验

### 12.1 容易误解的地方

| 容易得出的错误结论 | 应检查的事实 |
| --- | --- |
| `p` 是素数，任何二次幂长度都能 NTT | 所需长度必须整除 `p-1` |
| 最后取模，CRT 模数乘积多大无所谓 | 非负恢复要 `Q>B`，有符号恢复要 `Q>2B` |
| 拆位后结果小于 `2^53`，已有浮点正确性证明 | 还要界定整个变换链的误差 |
| 随机缩放或格坐标扰动能保证正确 | 代数可逆不等于误差一定小于 `0.5` |
| 前 16 项小就能只用一模 | #403507 仍扫描全数组给严格上界 |
| Rust 类型名有三个素数，那次一定跑 CRT | 外层按 AVX2/FMA 与长度选择浮点或整数路线 |
| 文件里有分块/共轭/加权，就算这题的优化 | 要从 `main` 跟到实际模板及可达条件 |
| `ntt_inplace` 不用辅助数组 | 上游每次变换有一条长度 `L` 的缓冲 |
| 每个常量 `%` 都是硬件除法 | 要检查所用编译器产生的汇编 |
| 不同用户代表独立实现 | #405312 与 #405711 统一换行后字节相同 |

### 12.2 实验应一次回答一个具体问题

以下是后续实验设计，**不是本文已经测得的性能结论**。应在同一机器、相同编译参数与输入上比较，先保证正确，再看计时。

| 想验证的问题 | 输入或改动 | 应记录什么 |
| --- | --- | --- |
| 一、两模的界是否按预期触发 | 固定长度，用全零、小整数、`p-小整数`、均匀大余数 | 完整界 `B`、预筛结果、实际模数数目 |
| 抽样有没有被误当成证明 | 前 16 项全零，后面放接近 `p/2` 的数 | 完整扫描应拒绝不足的一、两模容量 |
| 短尾节省了什么 | `S=2^k-1,2^k,2^k+1,2^k+8,2^k+9`，短边高于门槛 | 实际变换长度、尾部工作和阶段耗时 |

| 平方省几次变换 | 内容相同但分别存储，与只改一个系数的输入 | 平方分支、正变换次数 |
| 浮点数值边界在哪里 | 全同值、交替大小值、稀疏尖峰、接近 `p/2`、题库针对数据 | 与精确 CRT 的错项，调试副本中的舍入残差 |

| Rust 实际走哪条路 | 记录 CPU 特性，调试副本记录分派 | FFT/CRT/Karatsuba 次数 |
| SIMD 与内存策略各有多少作用 | 副本里一次关闭一种可独立开关的优化 | 内核时间、分配次数、峰值内存；必要时检查汇编与硬件计数器 |

小数组与 `O(NM)` 的整数模卷积逐项比较，大数组用已核验的精确 CRT 作参照。还可检查 `sum(c)≡sum(a)sum(b) (mod p)` 这种廉价不变量，但它只能捕获部分错误，不能替代逐项核对。
