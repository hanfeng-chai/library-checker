# K-th Root (Integer)：从二分到分段估计与整数校正

## 题目实际上要求一个整数不等式

每问给出 `0≤A<2^64` 和 `1≤K≤64`，求最大的非负整数 r，使
`r^K≤A`。这就是 `floor(A^(1/K))`；floor 表示向下取整。
答案还必须满足 `(r+1)^K>A`，两边一起检查才能确认没有少取或多取 1。
最多 `T=500000` 问，见 [`task.md`](../../../upstream/number_theory/kth_root_integer/task.md)
和 [`info.toml`](../../../upstream/number_theory/kth_root_integer/info.toml)。

```text
输入
8
0 5
1 64
63 3
64 3
80 3
81 4
18446744073709551615 2
18446744073709551615 32

输出
0
1
3
4
4
3
4294967295
3
```

`3³=27≤63<64=4³`，所以第三问输出 3；64 是完全立方数，第四问输出 4。
`4³=64≤80<125=5³`；`3⁴=81`。最大输入 `2^64-1` 的平方根向下取整
是 `2^32-1`，因为 `(2^32)²=2^64` 已超出输入；32 次根至多是 3，
因为 `4^32=2^64`。`K=1` 时直接输出 A，`A=0` 时任何合法 K 都输出 0。

## 先做一个完全整数的基线

从 r=0 开始逐个试 `r^K` 很直观，但 K=2 时答案可能接近 43 亿，
逐个枚举仍太慢。注意判定 `ok(x): x^K≤A` 对 x 单调：小的合法，大的
一旦不合法，后面都不合法。于是可以二分“最后一个合法值”。

保持 `low^K≤A<high^K`，取中点 mid；合法则 `low=mid`，否则
`high=mid`。区间每轮减半，直到 `high=low+1`，low 就满足答案的两边
不等式。这里 high 是明确不合法的哨兵，不要求它本身属于输入值域。

但判定不能先把 `x^K` 算溢出，再与 A 比较。最简单的安全写法是逐乘，
每次乘之前检查除法界：

```text
power_leq(x,K,A):
    if x==0: return true
    value=1
    repeat K 次:
        if value>A/x: return false
        value*=x
    return true
```

其中检查一旦失败，后续乘法只会更大，立即拒绝即可。额外空间 `O(1)`，
单次判定 `O(K)`，二分总计 `O(K log high)`。这是“只判断是否超过限制”，
并不需要在超过范围后继续计算那个巨大幂。

## 上游 `correct.cpp` 的真实二分与溢出界

上游 [`correct.cpp`](../../../upstream/number_theory/kth_root_integer/sol/correct.cpp)
首先处理 `K=1`；其他情况固定 `low=0、high=2^40`，调用 `mypow(mid,K)`
判定。因为 `K≥2` 且 `A<2^64`，`(2^40)^K≥2^80>A`，初始上界一定
不合法。这个很宽的区间使每问固定进行约 40 轮二分，即使 K 很大、答案只有 1。

`mypow` 使用有符号 `__int128_t result`，每次乘 mid 后若
`result>>64` 非零就停止。它不把大结果饱和成某个哨兵，而是保留这次乘法
得到的、已大于所有合法 A 的 128 位值，供 `<=A` 判断。
为什么连这个 128 位结果也不会溢出？进入乘法前未触发停止，故
`result<2^64`；二分中 `mid<2^40`，下一次乘积小于 `2^104`，远小于
有符号 128 位上限。这是由**实际二分上界与逐乘停止位置**共同保证的，
不能把这个函数直接当作任意 128 位底数的安全幂函数。

手走 `A=80、K=3`：早期二分不断缩小过大的上界，最后到达 `[0,8]`。
中点 4 的立方为 64，移 low 到 4；中点 6 的立方为 216，移 high 到 6；
中点 5 的立方为 125，移 high 到 5。此时相邻，输出 4。
若某次 mid 已是 `2^39`，`mypow` 第二次乘法就超过 64 位，不必真的做完
全部 K 次。时间上界 `O(40K)`，实际受这些提前停止影响；空间 `O(1)`。
在五十万问上，40 轮意味着约两千万次幂判定，是快解集中消除的重复工作。

一个仍保持纯整数的方法是缩紧上界。若 A>0，令 b 为其二进制位数，
则 `A<2^b`，所以 `high=2^ceil(b/K)` 已满足 `high^K>A`。
K≥2 时指数至多 32，可安全在 `u64` 中构造。它能缩短二分，但下面的
公开前五主要采用更激进的数值估计和指数分段，不能把这个改良二分
误标为它们的实际算法。

## 第一项优化：大指数的答案只有几个候选

输入固定小于 `2^64`，因此 `r<2^(64/K)`。K 越大，可能的 r 越少。
非零输入下，先有候选 1；再逐个判断 2、3 是否达到阈值即可：

| 指数范围 | 能出现的答案 | 为什么 |
|---|---|---|
| `K=64` | 1 | `2^64>A` |
| `41≤K≤63` | 1 或 2 | `3^41=36472996377170786403>2^64-1` |
| `32≤K≤40` | 1、2 或 3 | `4^32=2^64` |
| `12≤K≤31` | 至多 40 | `40^12=16777216000000000000` 可容纳，而 `41^12` 已超界 |

例如 K=32 时，先看 `A≥2^32`；再看 `A≥3^32=1853020188851841`，
就决定输出 1、2 或 3。没有必要调用浮点幂，更没有必要做 40 轮二分。
若预存所有可容纳的 `j^K`，一般形式就是
`r=1+满足 j^K≤A 的 j≥2 的个数`；阈值随 j 严格递增，因此数过几个
正好就是最后一个合法候选。超出 `u64` 的阈值必须省略或单独表示，不能
让它绕回小整数再比较。

## 第二项优化：浮点只负责定位，整数负责确认

`pow(double(A),1.0/K)` 很快给出实数根的近似，但向下取整对误差敏感。
比如真实答案对应完全幂 `A=1000、K=3`，近似若为 `9.999999999`，
直接转整数会错成 9；若在完全幂前一项得到略偏大的估计，也可能多取 1。
double 不能精确表示全部 64 位整数，输入转换本身也会引入误差。

可先得到估计 r，再检验 `(r+1)^K≤A`，成立就加一；检验 `r^K>A`，
成立就减一。若两边都用无溢出的整数比较并循环到稳定，最终答案由整数
不等式确定，而不是由浮点舍入决定。多数输入只修正零到一次，但“只有一次
修正就一定够”需要额外的误差界，不能由使用了 long double 自动推得。

快解常把 `1.0/K` 调成朝 0 的相邻浮点数 `nextafter(1.0/K,0)`，使指数
略偏小，从而倾向把近似放在真根下侧。`nextafter` 不是减去一个随意的
十进制 epsilon，而是选浮点格式中恰好相邻的可表示值。
不过 `pow` 自身和 A 转换仍有误差；只向上修一次的实现，依旧依赖
“估计没有过大、也没有小超过一格”的平台数值条件。

## 整数校正怎样做到又快又不溢出

逐乘比较需要 K 次乘法；重复平方把指数按二进制处理，只需 `O(log K)`。
以 `x^13` 为例，`13=8+4+1`，保存 `x,x²,x⁴,x⁸`，选相应项相乘。
每次结果相乘或底数平方前后，使用溢出检测；只要未来仍要用到的幂已经
超过 `u64`，就知道不可能小于等于合法 A，立即返回 false。

```text
value=1
while K!=0:
    if K 的最低位为 1:
        若 value*x 的无符号乘法溢出: return false
        value*=x
    K >>= 1
    if K==0: break
    若 x*x 的无符号乘法溢出: return false
    x*=x
return value<=A
```

没有剩余指数位时跳过最后一次平方，避免把已经不再需要的幂的溢出误判成
当前答案溢出。若还有指数位，至少一个未来二进制幂确实会乘入结果，
所以此时平方溢出可以安全拒绝。
边界 `A=2^64-1` 不能用 u64 的 `A+1` 作为大数哨兵，必须用独立状态、
更宽类型或像这里一样直接返回真假。

### #229185：按编译期指数分流，三个数值内核

实际调用链是 `main→Main→KthRoot→KthRootImpl::calc2→calc<K>`。
`calc2` 先处理 n=0，再用 switch 把 K=1…63 分派成编译期常量，K=64
走默认返回 1。文件中的模平方根、整除分块等大量模板没有调用。
常量 K 使不适用的分支在编译时被移除，但代价是更大的生成代码。

**K=2。** `IntSqrt64` 的运行期分支先取
`s=floor(sqrt(double(n)))`，令 `tmp=s-1`，返回
`tmp + (tmp*(tmp+2)<n)`。因为 `tmp*(tmp+2)=s²-1`，比较等价于
“s²≤n 则保留 s，否则减一”。这种写法还让 s=2^32 时的乘积成为
`2^64-1`，不会直接计算装不下的 s²。
它依赖浮点 s 落在正确整数根及其后一项之中；源码给该函数指定
`no-fast-math`。函数中另一段 `is_constant_evaluated()` 下的二分只用于
编译期求值，运行期输入不会执行，不能把它算进每问 18 ms 的路径。

**K=3。** 这份没有调用 `cbrt` 或普通 `pow`，而是估计倒立方根
`x≈n^(-1/3)`。先用 `t=bit_width(n)-1` 定位 `2^t≤n<2^(t+1)`，
从 `rt3[t]` 表取约 `2^(-t/3)` 的初值。定义误差 `h=1-nx³`，理想的
新 x 与旧 x 的比值满足

```text
x_ideal/x = (1-h)^(-1/3)
          ≈ 1+h/3+2h²/9+14h³/81+35h⁴/243+91h⁵/729
```

源码把这个展开式按嵌套乘法计算，重复三轮，最后取 `r=floor(1/x)`，
用 r³ 和 `(r+1)³` 作一次下/上修正。以 n=27 为例，t=4，初值约
0.396850263；第一轮 h=-0.6875，x 变为约 0.330460681；第二轮约
0.333333333323；第三轮约 1/3，取倒数得到 3。
这解释了多项式系数承担的工作，而不是仅贴“Newton 优化”标签。

`lim[3]=2642245` 是 u64 最大输入的整数立方根；代码先用它保护即将
计算的立方，防止越界候选的乘积绕回。三轮误差是否对整个输入域都满足
单步修正条件，还依赖浮点实现和初值表；本篇未穷尽证明该数值界。

**K=4…11。** `iv[K]` 是略小于 1/K 的常量，调用 `pow` 得到整数 r，
再以重复平方计算 `(r+1)^K`。若 `r<lim[K]` 且候选幂不超过 n，就加一。
`lim` 保证真正用于比较的候选幂可容纳；某些不再使用的无符号平方值可以
绕回，不能因此把这个循环当作对任意底数都安全的幂函数。
这一分支只向上修一次，同样依赖估计误差方向和大小。

**K≥12。** 不再调用浮点，直接累计所有可能的整数阈值。
例如 K=12，代码可检查 2…40；复合底数的幂由小素数幂表相乘或移位
构成，如 `6^K=3^K*2^K`、`9^K=(3^K)²`。编译期 `if constexpr`
根据 K 去掉超出 u64 的候选。K 越大，保留的比较越少，K≥41 时只剩
2 的幂。最大分支也只有至多 39 个阈值比较，查询无建表过程，静态表固定。

其 `BasicReader/BasicWriter` 为自定义缓冲读写，`main` 逐问处理。
速度变化同时包含特化内核、查表、分派与 I/O，不能归因于某一个函数名。

### #209944：溢出返回 0，统一成一次比较

`main→work→k_rt` 首先处理 A=0 或 K=1。K=2 直接返回 `sqrtl(A)`
转换后的整数，没有调用整数上下校正；这依赖该平台 long double 和
平方根实现的精度，不能泛化成“任意浮点格式均精确”。K=3…31 使用
`nextafter(1.0/K,0)` 的预存倒数，取 `r=floor(pow(A,iv))`。

`sf_qpw` 使用 `__builtin_umulll_overflow` 的重复平方，若溢出返回 0。
校正写成 `sf_qpw(r+1,K)-1 < A`：正常非零结果 v 时等价于 `v≤A`；
若返回 0，则无符号 `0-1` 为 `UINT64_MAX`，对任何合法 A 都不小于 A，
因此拒绝这个溢出候选。由于候选 r+1 为正，真正的整数幂不会是 0，
这个哨兵在此调用中不会与合法结果冲突。

K=32…63 只看 `2^K` 和表中的 `3^K-1`；3 的幂溢出时，该表项也由
0-1 变为最大值，比较自然为假。K=64 提前返回 1，避免 `1ULL<<64`。
相比上游，它以一次浮点定位、一次 `O(log K)` 的整数幂检查替代 40 次
逐乘判定；节省的工作清楚，但单向、单次修正的数值假设也应一并保留。
I/O 使用 `mmap`、每次两位数字解析和缓冲输出。

### #393720：估计后检查两侧，保留明确的整数不变量

`main` 调用源码中实际打包的 `toy::kth_root_floor`。K=1 或 A≤1
直接返回；K=2 以 long double 平方根定位，随后两个 while 分别检查
`(r+1)²≤A` 和 `r²>A`；K=3…31 以偏置 `pow` 定位，也进行同样的双向
校正。检查函数 `power_leq` 就是上文带溢出检测的重复平方。
因此只要估计可转换到整数且循环正常结束，最终 r 的正确性由两侧不等式
确定，不要求估计必定只错一格。

K≥64 返回 1；K≥32 比较 `2^K`，K≤40 时另用 K 次整数乘法构造 `3^K`
再比较。这里并没有使用前两份的 3 次幂静态表，数十次小乘法也是它的
实际工作。设纠正次数为 E，估计加校正分支的整数工作为
`O((1+E)log K)`；通常 E 很小，但未给出误差界时不能将“通常”写成定理。
辅助空间仍是常数。文件里的其他 `toy::integer` 函数没有在本题调用。

### #246999 / #405762：0.05 是候选调整，不是直接给答案加误差

两份源码字节一致，均走 `main→OY::KthRoot::floor_iroot`。先处理 0、
K≥64、答案小于 2 等条件，再对 K≥32 作阈值比较；Linux 的 K=2 分支
直接把 `sqrt(long double(x))` 转整数。文件中的 `ceil_iroot`、
`floor_log`、`ceil_log` 未调用。

K=3…31 时以 `floor_einv[K-3]` 中偏小的倒数算 double 估计 res。
试验候选是整数转换后的 `res+0.05`，只有它的整数幂满足
`fast_pow(candidate,K)-1 < x`，才给 res 加 0.05，再转成整数输出。
例如 x=1000、K=3，若 res≈9.999999999，候选为 10，`1000-1<1000`
成立，修到 10；x=999 时，候选 10 的判定为 `999<999`，不成立，
保留向下取整的 9。因此 0.05 的角色是跨过可能非常接近的整数边界，
不是把近似值任意四舍五入。

其 `fast_pow` 是普通 u64 重复平方，没有通用溢出检查。它依赖本分支
受限的近邻候选、指数范围和阈值设计；溢出恰好为零时的减一哨兵行为
不能推广成“任何溢出都可这样检测”。若移植或扩大范围，宜使用带检测的
`power_leq` 与明确的双向校正，不能仅照抄常量 0.05。
`cin/cout` 在文件中被宏替换为 `OY::LinuxIO`，实际是映射读入和缓冲输出。

## 可以复用的部分与验证边界

本仓库有 [`binary_search.cpp`](../../../problems/number_theory/kth_root_integer/binary_search.cpp)
和 [`specialized_integer_root.cpp`](../../../problems/number_theory/kth_root_integer/specialized_integer_root.cpp)，
说明见 [`tutorial.md`](../../../problems/number_theory/kth_root_integer/tutorial.md)。
前者保留单调判定和溢出检查的基线，后者采用分段与整数校正；两者都比
“相信 `pow` 后直接截断”更容易给出明确的答案不变量。

| 优化 | 减少什么 | 必须保留的条件 |
|---|---|---|
| 二进制位数缩紧上界 | 减少二分轮次 | 0、K=1 单独处理，移位指数不越界 |
| 重复平方判定 | 从 K 次逐乘变为 `O(log K)` | 每次有关的乘法都检测溢出 |
| 大 K 阈值分段 | 消除二分和浮点幂 | 只比较可容纳的阈值或正确哨兵 |
| 浮点定位 + 校正 | 消除大部分候选搜索 | 最后满足 `r^K≤A<(r+1)^K` |
| 单次单向校正 | 再省循环与部分检查 | 需要估计误差方向及不超过一格的界 |
| 编译期 K 特化与倒立方根内核 | 少调用通用 libm、让分支消失 | 代码体积、静态表与平台数值行为 |

这些方法都按输入顺序在线处理独立查询，没有与 T 成正比的预处理索引。
