# Primality Test：从试除到少底数 Miller–Rabin

## 素数是什么，题目要输出什么

大于 1、正因子只有 1 和自身的整数叫素数；例如 2、3、5、7、11。
1 不是素数，9 因为 `9=3×3` 不是素数。输入至多十万个
`1≤n≤10^18` 的数，每个输出 `Yes` 或 `No`，彼此之间没有状态。
下面是完整可手算例子：

```text
输入             输出
7                No
1                Yes
2                Yes
13               No
21               No
49               No
2047             Yes
97
```

这里 `21=3×7`、`49=7×7`、`2047=23×89`；97 不被不超过其平方根的
素数 2、3、5、7 整除，所以为素数。特意保留 2047，是因为后面一个看起来
很强的“底数 2 检验”仍然会被它骗过。

## 最直观的试除，以及十亿次循环的来源

若 `n=a×b` 且 `1<a≤b`，一定有 `a≤sqrt(n)`；否则两者都大于平方根，
乘积就会大于 `n`。所以只需试除到平方根：

```text
if n<2: return false
for d=2 while d<=n/d:
    if n%d==0: return false
return true
```

条件写 `d≤n/d` 可避免通用实现中 `d*d` 溢出。单数时间 `O(sqrt(n))`、
额外空间 `O(1)`。对接近 `10^18` 的素数，平方根约十亿，没有提前退出，
十万问最坏约 `10^14` 次试除。只试素数能减少常数，但仍要处理极长的除数表。
快算法要改成用少量算术关系**证明它是合数**，而不逐一寻找小因子。

## 模幂：用几十轮乘法代替巨大整数

`x mod n` 表示除以 `n` 的余数。`x≡y (mod n)` 表示二者相差 `n` 的倍数。
乘法后随时取余不影响最后余数，例如
`(a mod n)(b mod n) mod n = ab mod n`，所以不必真的构造 `a^d`。
把指数写成二进制，便得到重复平方：

```text
result=1, power=a%n
while d>0:
    if d 的最低位是 1: result=result*power mod n
    power=power*power mod n
    d >>= 1
return result
```

例如 `3^13` 的 `13=8+4+1`，只需得到 `3,3²,3⁴,3⁸` 四个幂，再选
其中第 1、4、8 次幂相乘。每轮指数减半，总计 `O(log d)` 次模乘。
循环不变量是“已累计的结果乘以尚未处理的幂，仍与原目标模 `n` 相等”。

但乘法本身有一个新问题：`a,b<n≤10^18` 时，`a*b` 可接近 `10^36`，
超出 64 位。先用 64 位乘法溢出，再 `%n` 不能恢复正确余数。
可用 `unsigned __int128` 容纳乘积，再取余；上游则在 Montgomery 内核里
把两个数各拆成高、低 32 位，用四个 32×32 乘积和进位拼出完整乘积。
这属于模乘实现层，和接下来“要做多少次模乘”的算法层应分开理解。

## Miller–Rabin 为何能拒绝合数

### 从素数必须满足的两条性质出发

设 `p` 是奇素数，且底数 `a` 不被 `p` 整除。费马小定理给出
`a^(p-1)≡1 (mod p)`。另一个性质是：如果 `x²≡1 (mod p)`，
那么 `(x-1)(x+1)` 被素数 `p` 整除，故 `x≡1` 或 `x≡-1`。
这里的 `-1` 用余数表示就是 `p-1`。

把候选奇数的 `n-1` 拆成 `d×2^s`，`d` 为奇数。计算序列

```text
x0 = a^d mod n
x1 = x0² mod n
x2 = x1² mod n
...
xs = a^(n-1) mod n
```

如果 `n` 是素数，终点必须是 1。若起点已经为 1，可以通过；否则观察
第一次变成 1 的那一步，前一步不能是另一个普通数，只能是 -1。
因此，一个素数一定满足下面条件之一：`x0=1`，或者
`x0,x1,…,x(s-1)` 中出现 `n-1`。不满足就得到了“n 不可能是素数”的证据，
这个底数称为一个 witness（合数见证）。

```text
test_one_base(n,a):
    if a%n==0: 跳过这个底数
    写 n-1=d*2^s，d 为奇数
    x=pow_mod(a,d,n)
    if x==1 or x==n-1: return 通过
    repeat s-1 次:
        x=x*x mod n
        if x==n-1: return 通过
    return 合数
```

### 两条平方链的完整手算

`n=13` 时 `12=3×2²`，底数 2 给出 `x0=2³ mod 13=8`，
`x1=8² mod 13=12=-1`，所以通过；再平方是 1，符合素数必须有的形状。
`n=21` 时 `20=5×2²`，底数 2 给出 `x0=2⁵ mod 21=11`，
`x1=11² mod 21=16`，既未从 1 开始，也未遇到 20，所以拒绝。
实际上上游会先用 3 试除掉 21，这里单独展示的是 MR 内核的判断过程。

**通过一次并不证明素性。** 对 `2047=23×89`，`n-1=1023×2`，
又因 `2^11=2048≡1 (mod 2047)` 且 `1023=11×93`，得到
`2^1023≡1`。它虽为合数，却通过底数 2；这称为该底数的强伪素数。
要得到确定结论，就要使用对给定整数范围足够的底数组合，不能因为随机
挑了两个底数或测试了几个例子，就声称对所有输入确定正确。

## 上游实际用了哪些步骤

[`correct.cpp`](../../../upstream/number_theory/primality_test/sol/correct.cpp)
每问调用 [`is_prime`](../../../upstream/number_theory/primality_test/lib/prime.hpp)：
先按顺序试除 `2,3,5,7,11,13,17,19`，等于某个小素数立即返回真，
是其倍数立即返回假；其余进入 `miller_rabin`。在那里排除 1 和偶数，
拆出 `d,s`，顺序检查固定七底数
`2,325,9375,28178,450775,9780504,1795265022`。
这是代码采用的有界整数确定性底数集合，不能任意换成“前七个小素数”。

每个底数各自调用 `mg.gen(wt).pow(d)`，失败就提前返回合数；所有底数
通过才返回素数。`wt%n==0` 的底数被跳过，避免把素数等于底数的因子误拒绝。
代码的后续平方循环写为 `c<r`，相较常见 `s-1` 次形式多留了一轮上界；
不要把本篇教学伪代码当作该源码的逐字转写。
同一头文件中的 `PrimeGenerator` 不由本题 `main` 调用，不计入查询开销。

按固定字宽模乘计成本，七个底数每个 `O(log n)` 次模乘，单问仍是
`O(log n)`，额外工作空间 `O(1)`。但常数差异很大：素数要完成全部七条链，
容易识别的合数通常在小素数试除或第一个底数就退出。比较优化时应分别
统计这两类输入，不能只看一个总平均。

## Montgomery 表示：为什么热循环可以省掉取模除法

MR 要对同一个奇数 `n` 做很多模乘。令 `R=2^64`，因为 `n` 为奇数，
它在模 `R` 下有逆元。用 `x̄=xR mod n` 代替普通余数 `x` 存储。
若直接乘两个编码值会多出一个 `R`，所以定义约减 `REDC(T)`，使其等价于
`T/R mod n`。预先求 `n'=-n^(-1) mod R`，则：

```text
q = (T 的低64位 * n') mod R
u = (T + q*n) / R
若 u>=n，再减 n
```

因为 `q*n≡-T (mod R)`，分子低 64 位恰好归零，除 `R` 只需取高半部。
在标准规范范围 `0≤T<nR` 下，结果小于 `2n`，至多减一次 `n`。
`REDC(x̄*ȳ)` 因此得到 `xyR mod n`，仍保持同一种编码，可以连续平方。
进入此域通常用 `REDC(x*(R² mod n))`；退出用 `REDC(x̄)`。

用小参数 `n=13、R=16` 手算原理：`13^(-1) mod 16=5`，故 `n'=11`。
数字 3 编成 `3*16 mod13=9`，数字 5 编成 2；乘积 `T=18`，
`q=18*11 mod16=6`，`u=(18+6*13)/16=6`。这仍是编码值，
解码一次得 `(6+2*13)/16=2`，与 `3*5 mod13=2` 一致。
位宽换回 64 后原理不变。

上游 `MontgomeryGenerator::calc_inv` 用 64 轮位递推求逆，构造编码时
又调用 `modprod`；大模数下 `modprod` 使用逐位倍加。循环中的乘法由
32 位拆分重建高低半部，每次 witness 检查还调用 `val()` 还原余数。
快解常用原生 `u128` 乘积、预计算 `R²` 以及 Newton 迭代
`v←v*(2-n*v)` 求逆。若原逆元已经正确到 `t` 位，这一步使误差平方，
正确位数加倍；少数几轮便覆盖 64 位。快解还直接比较编码后的 `1` 和
`n-1`，不必每次先解码。

不同源码的约减符号和剩余范围有差别：#405740 用负逆元和加法公式，
#264121 用正逆元配减法式高半部约减，并暂留较宽的等价剩余。
比较前必须规范化，不能把两者的逆元或约减函数混用。
本题 `n≤10^18<2^60` 给中间范围留有余量；推广到整个 `uint64_t` 域时，
必须重新核对 128 位相加是否溢出及允许剩余范围。

## 公开快解的两条主要省工路线

第一条是**减少底数数量**。预计算表根据 `n` 的哈希桶选额外底数：先让
固定底数 2 排除大部分合数，再为同一桶中仍会通过的候选选择能拒绝它们
的底数。运行时是常数次哈希和一次数组读取，不是现场搜索合适 witness。
它的确定性依赖整张表针对规定值域的覆盖性质；普通哈希“碰撞少”不能
替代这份性质，哈希桶也不是概率判素本身。

第二条是**交错推进独立链**。同一底数的 `x²→x⁴→x⁸` 必须串行等待，
不同底数的乘法却互不依赖。一个指数位同时更新两条或三条链，可让 CPU
在等待第一条乘法结果时发射另一条。这里主要是指令级并行，不是 AVX2
寄存器里同时做多个 64 位模乘，更不是多线程。模乘总数通常没有因此减少；
遇到第一底数就能拒绝的合数时，预先计算其他链反而可能浪费工作。

下面按真实入口和参数逐份对照。小数位图、底数表、模乘内核和 I/O 分别
节省不同的工作，不能把几个标签相加当成正确性或速度的证明。

## 参考实现及比较基准

[upstream `correct.cpp`](../../../upstream/number_theory/primality_test/sol/correct.cpp) 调用 [`is_prime`](../../../upstream/number_theory/primality_test/lib/prime.hpp)：先试除 `2,3,5,7,11,13,17,19`，再将 `n-1=d·2^s`，依次使用固定七底数 `2,325,9375,28178,450775,9780504,1795265022` 做 Miller–Rabin（MR）。[`MontgomeryGenerator`](../../../upstream/number_theory/primality_test/lib/montgomery.hpp)提供模乘；其 128 位中间乘积由 32 位拆分手工构造，每个 witness 各自调用 `pow`，并把 Montgomery 值转回普通剩余类检查 `1` 和 `n-1`。七底数覆盖 64 位整数是这个通用实现的正确性依据。

本仓库的 [串行版](../../../problems/number_theory/primality_test/serial_miller_rabin.cpp) 与 [并行版](../../../problems/number_theory/primality_test/parallel_miller_rabin.cpp)仍用相同七底数，分别通过 [`toy::is_prime` / `toy::is_prime_parallel`](../../../include/toy/prime.hpp) 处理。并行版将七条模幂链按指数位交错推进，以暴露指令级并行；个人留存的 [#393716](../../selected/primality_test/393716.cpp) `main` 实际调用的是 `toy::is_prime_parallel`，不是其同一源码内的串行函数。该个人提交配置中的 112 ms 与 `is_latest=null` 是旧快照，不能直接据此断言和上表在相同数据、编译环境下的加速比例。

前五的核心变化是**为本题数据范围缩减 witness 数量**：利用预计算表按 `n` 选出能区分相关伪素数的底数。少做模幂通常比再改一个常数级 I/O 细节更有潜力；但预计算表的正确性取决于其构造与覆盖证明。本文核对了运行路径和当前 AC，没有独立重建或形式验证这些大表，因此不把“当前 AC”写成“已经证明覆盖全部 `1…10^18`”。

## #405740 / #365922：两条链与 262144 桶表

两份文件逐行文本相同：#405740 为 CRLF、#365922 为 LF，归一化行尾后源码一致。这是**一个实现、两份提交**，不宜当成两项独立算法发现。两份 `main` 都用 `fastio::scan` 读入 `Q,N`，调用 `nt::prime_test(N)`；`fastio::print` 输出 `"Yes "` / `"No "`，以空白分隔答案。源码里的 `nt::bases[]` 是 262144 个 `u16`，约 512 KiB 静态表，`hashh(n)` 以两次乘法和异或混合后取低 18 位。第二底数是 `bases[hashh(n)]`，第一底数固定为 2；它没有在执行过程中遍历七个通用 witness。

`prime_test` 先特殊处理 `2,3,5,7`，再排除它们的倍数。由于所有小于 121 的合数必有不大于 7 的素因子，`n<121` 可直接返回真（已排除 `1` 和合数）。其余奇数用 `m64`：Newton 迭代求 `-n^{-1} mod 2^64`，`r2 = R² mod n`，`reduce(u128(a)*b)` 实现 Montgomery 乘法。把 `n-1=d·2^z` 后，固定底数 2 与表选底数同时变换到 Montgomery 域；循环把各自的平方和按 `d` 的二进制位交错计算，得到 `a^d mod n`。代码用 `y=a`、`exp=d>>1` 启动，因此初始的最低位 `1` 已计入 `y`。最后两条链分别检查 `1`、`-1` 或后续至多 `z-1` 次平方中的 `-1`；两者都通过才报素数。

相对 upstream，减少了七次模幂到两次、把两条链交错运行，并用原生 `u128` 做 Montgomery 乘法。代价是约 512 KiB witness 表及其来源验证、缓存访问和源码体积；输入分布和编译器会影响收益。源码注释指向 FJ64 262K 表，但本轮只确认了代码如何索引，未复现该表的生成或穷尽验证。

## #340522：按数值范围选择不同测试器

`main` 在 OJ 配置下使用 `gsh::MmapReader`、512 KiB `BasicWriter`，真正的判定入口是 `cppr::IsPrime(x)`。这是打包的 `libcpprime`，不能把文件中所有泛用模板都算成本题开销。实际可达分支如下：

| `n` 范围 | 执行路径 | 有效底数/数据结构 |
| --- | --- | --- |
| `< 2^17` | `IsPrime17` | 1024 个 64 位字、约 8 KiB 的奇数素性位图；直接查表 |
| `2^17…2^32-1` | `TrialDivision32` 后 `IsPrime32` | 小素数筛选；256 槽哈希表选一个 MR 底数。`n<2^21` 时使用特殊乘法路径，其余用 64 位乘积 `%n` |
| `2^32…2^49-1` | `TrialDivision64` 后 `IsPrime49` | 小素数筛选；固定 2 加 `GetBase(n)` 的双链 Montgomery MR |
| `2^49…10^18` | `TrialDivision64` 后 `IsPrime64<false>` | 固定 2、`GetBase(n)`、从第二底数高位索引 8 字节表得到的第三底数 |

`GetBase(n)` 以 `0xad625b89 × low32(n)` 的高 14 位索引 16384 项 `u16` 表（约 32 KiB）。`TrialDivision32/64` 把若干小素数整除判定改写为常量乘法和比较。49 位及更大分支把 2 或 3 条模幂链一起推进；对 `n≡3 (mod 4)`，`n-1` 只有一个因子 2，MR 根本没有后续平方链，因此可立即凭初始结果返回。对 `n≡1 (mod 4)` 才在必要时继续平方。`IsPrime64<true>` 用严格 Montgomery 剩余范围处理更大整数，但题目上限 `10^18 < 2^60 < 2^62`，本题不会进入该分支。

与 #405740 的统一双底数不同，这份实现把小数查询分流到位图或较小哈希表，把大数交给 2/3 底数版本，表大小、初始化和模乘成本均随区间变化。由此可以解释代码设计，但当前 34 ms 不能单独证明“分段”优于双底数方案，因为排名前三同为 34 ms，且 I/O 也不同。

## #264121 / #283661：三底数哈希方案的两个包装

两份实际入口分别是 `main→__yzlf::work→isprime` 与 `main→isprime`，核心结构高度相似：`n<64` 用一个 64 位常量位图，偶数直接否决；`n<2^32` 使用固定 `2,7,61`；较大整数取固定底数 2、一个 16384 项哈希表底数、再用该表值的高三位从 8 项数组 `{15,135,13,60,15,117,65,29}` 取第三底数。两个实现的哈希乘数相同：`0xad625b89 = 2908904329`，索引是对应 32 位乘积的高 14 位。大表在 #283661 里是 Base64 编码后解码为 `u16` 数组，在 #264121 里是直接写出的整数数组；不能把编码压缩误认为判定过程中要在线解码每次查询。

它们先求 `n-1=d·2^k`，将三底数都转入 Montgomery 域，在同一个指数位循环里交错更新三条乘法链。初值 `1` 及 `n-1` 的 Montgomery 表示分别用于判定 `a^d`；后续统一做 `k-1` 轮平方并累积是否遇到 `-1`，已经通过的链也随循环更新，最终三条 witness 都通过才输出 `Yes`。#283661 的 `reduce(u128, inv, n)` 直接构造 Montgomery 商，热循环中允许结果保留非规范表示，然后在比较前减 `n`；#264121 用 `mul` 与 `std::min(r,r-x)` 折叠同类值。这里减法为无符号运算：若 `r<x`，`r-x` 回绕为很大的数，`min` 保留 r；否则取 `r-x`。这种技巧只有在已证明 r 的剩余范围后才可用。两者都以原生 `u128` 替代 upstream 手写的 32 位拆分乘积。#283661 使用自制缓冲读写，#264121 用 `mmap` 输入与两位十进制查表解析、缓冲输出；这些 I/O 差异同样进入 OJ 时间。

它们相对 upstream 的主要改进是把七底数降为最多三底数，再把独立模幂交错；相对本仓库 `toy::is_prime_parallel`，两者都减少了同时推进的链数和模乘次数，但承担约 32 KiB 哈希表的正确性依赖。#340522 在相同大数区间也用 2 加两个表底数，但有额外的数值范围分流和小素数筛选，不能仅按“都是三底数”视为同一个执行路径。

## 可复用结论与待核查点

1. **算法上的差距**：当前前五实质上都是 MR 或小数直接查表，没有发现新型素性判定算法。关键是把通用七 witness 改为按哈希桶预选的 2/3 witness，并在同一指数循环推进多链；这降低每个需要完整测试的大数的模乘工作量。固定数量 witness 时仍是每个数 `O(log n)` 模乘、额外工作空间 `O(1)`；哈希表方案另有固定的 8 KiB、32 KiB 或 512 KiB 静态空间。
2. **正确性上的条件**：MR 本身对任意给定底数只有单向拒绝能力；“通过所选少数底数即可认定素数”须依赖针对所覆盖范围和哈希映射构造的完整表。表索引、表内容或输入上界一旦改变，就不能自动沿用现有结论。OJ 本轮 AC 证明这些提交通过当前测试集，未提供表的穷尽证明。
3. **性能上的边界**：34/36/37 ms 的差别涉及数据构成、I/O、二进制大小、编译选项及 OJ 计时波动。前五排序是 OJ 快照，不是控制变量实验；不应由 3 ms 推断某一种 witness 表或读取器普遍更快。个人 #393716 尚无 `is_latest=true`，比较时须先重测。实验应固定相同读写器，分别替换底数组合、串行/交错调度、模乘内核，并分开测素数、首底数即可拒绝的合数与强伪素数。
4. **样本上的边界**：这里逐份阅读的是当前前五、个人 #393716 以及上述历史重测元信息；没有逐份审阅本题原始榜单前 100 或全部 AC 提交。因此不能断言这些就是所有算法家族，更不能为尚未检查的家族指定最快提交者。原始前 20 的评测收敛和算法审阅范围分别记录，不能互相替代。本次只复核本地源码、元信息和教学算例，没有新增 OJ 请求或同机性能结论。
