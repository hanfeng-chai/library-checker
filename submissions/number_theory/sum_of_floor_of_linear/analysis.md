# 线性函数下取整之和：从逐项相加到欧几里得递推

## 1. 题目与一个贯穿全文的小例子

每组输入 N、M、A、B，求
F(N,M,A,B)=Σ(i=0…N−1) floor((Ai+B)/M)。
[题目](../../../upstream/number_theory/sum_of_floor_of_linear/task.md)
有至多 100000 组，1≤N,M≤10⁹，0≤A,B<M。

取 N=5、M=7、A=3、B=4：

| i | Ai+B | 除以7后向下取整 |
|---:|---:|---:|
| 0 | 4 | 0 |
| 1 | 7 | 1 |
| 2 | 10 | 1 |
| 3 | 13 | 1 |
| 4 | 16 | 2 |

答案为 5。直接循环 N 次很容易验证，但单组就可能十亿项。
我们要利用相邻项来自同一条直线的结构，避免逐个计算。
下文 n,m,a,b 表示递推中的当前参数，可能已不同于初始输入。

## 2. 先剥掉容易算的整数部分

写 a=qa·m+a'、b=qb·m+b'，其中 0≤a',b'<m，则

~~~text
floor((ai+b)/m) = qa·i + qb + floor((a'i+b')/m)
F(n,m,a,b) = qa·n(n−1)/2 + qb·n + F(n,m,a',b')
~~~

因为 i 的和是 n(n−1)/2，前两项立即可算。
输入本来满足 a,b<m，但坐标交换后的递归参数未必满足，所以每轮都需要此步骤。
例如 F(2,3,7,5)：

~~~text
7=2×3+1，5=1×3+2
整数部分贡献 = 2×(0+1)+1×2 = 4
剩下 F(2,3,1,2) = floor(2/3)+floor(3/3)=1
~~~

总和为 5。参数虽然变了，计数值可以保持不变，这为下一步缩小问题做准备。

## 3. 把“按列数高度”改成“按行数宽度”

归一化后 0≤a,b<m。把每个 floor((ai+b)/m) 看成第 i 列包含多少
个整数高度 j≥1：满足 mj≤ai+b 的点都计入答案。
原来逐列相加，也可以逐个高度统计有多少列够高。

若 a=0，各项均为 0，直接结束。否则令
Y=floor((an+b)/m)，r=(an+b) mod m。
Y 使用列右边界 i=n，而不是最后一列 n−1；
多出来的最高一行可能宽度为 0，不影响计数。

对高度 h=1…Y，最小合法列为 ceil((mh−b)/a)，
因此该行的宽度为 n−ceil((mh−b)/a)。
用 j=Y−h 把行倒序，并代入 mY=an+b−r：

~~~text
n − ceil((mh−b)/a)
 = n − ceil((an−r−mj)/a)
 = floor((mj+r)/a)
~~~

所以

~~~text
F(n,m,a,b) = F(Y, a, m, r)
~~~

这条等式说明为什么可以“交换 a 和 m”：它来源于同一批格点换一种数法。
新模数是旧 a，而归一化后 a<m，下一轮再取余，正好构成欧几里得算法的缩小过程。
如果 Y=0，原来所有列都不够高，剩余答案直接为 0。

例子 F(5,7,3,4) 中，an+b=19=2×7+5，
所以转成 F(2,3,7,5)，上一节已算出它等于 5。
原图的第一行覆盖 i=1…4，共4点；第二行仅覆盖 i=4，共1点。
转置后的两项为 floor(5/3)=1、floor(12/3)=4，
正好把这两行反向列出来。

## 4. 先理解最短迭代版，再对照上游的不同写法

以下教学伪代码与几份公开源码的状态更新相同：

~~~text
answer=0
while n>0:
    answer += (a/m)·n(n−1)/2 + (b/m)·n
    a%=m; b%=m
    y=a·n+b
    if y<m: break
    (n,m,a,b) = (y/m, a, m, y%m)
return answer
~~~

同时赋值很重要：右侧必须使用旧参数。以贯穿例子检查每轮：

| 轮次 | 进入时(n,m,a,b) | 剥掉整数部分的贡献 | 累计 | 下一状态 |
|---:|---|---:|---:|---|
| 1 | (5,7,3,4) | 0 | 0 | (2,3,7,5) |
| 2 | (2,3,7,5) | 4 | 4 | (1,1,3,1) |
| 3 | (1,1,3,1) | 1 | 5 | a=b=0，结束 |

### 4.1 上游多拆了一块矩形

[correct.cpp](../../../upstream/number_theory/sum_of_floor_of_linear/sol/correct.cpp)
同样先剥 a/m 与 b/m，但随后计算：

~~~text
Y = (a*n+b)/m
X = Y*m-b
若Y=0，返回
answer += (n-ceil(X/a))*Y
answer += F(Y,a,m,(-X) mod a)
~~~

源码将 ceil(X/a) 写为 (X+a−1)/a，
将最后的规范非负余数写为 (a−X%a)%a。
为什么这样也是第三节的同一个递推？
由 X=an−r 得
n−ceil(X/a)=floor(r/a)，且 (−X) mod a=r mod a。
因此上游只是提前从 F(Y,a,m,r) 中拆出
Y·floor(r/a) 这块矩形，再递归处理剩余的 r mod a。

本例 Y=2、X=10，矩形宽度为 5−ceil(10/3)=1，先贡献2；
再递归 F(2,3,7,2)=3，总计5。
这段变换和简短迭代版代数等价，但多了一些边界/整除表达式。
不能把上游描述成枚举 N 项的朴素解。

### 4.2 复杂度与整数范围

每轮交换并取余，使 (m,a) 沿欧几里得余数链缩小，
所以单组 O(log M) 时间。上游递归占 O(log M) 栈，
迭代版本只保存几个整数，额外空间 O(1)。

在题目约束下 (Ai+B)/M<i+1，因此每项 floor≤i，
答案≤N(N−1)/2<5×10¹⁷，int64足够。
乘积 a*n 必须先用64位，不能先在32位中溢出再赋给64位。
计数过程中的面积与三角形也需要相同的位宽审查。

### #385286 / #405748：去掉上游额外的矩形表示

main 直接调用 floor_sum_u64。它只在 a≥m、b≥m 时剥整数部分，
用 y=a*n+b 判断是否结束，再同时更新四参数。
文件中另有支持负 a、b 的 floor_sum 包装函数，
但 main 没有调用，不能把 signed 修正算作本题的执行工作。
两份规范化换行后的源码完全相同；12/13 ms 不代表执行算法不同。
输入在普通文件上尝试 mmap，否则读入缓冲，输出使用自有缓冲器。

### #364392：用矩形总量减去另一侧格点

这份使用另一条等价公式。归一化后令
k=floor((a(n−1)+b)/m)，即最后一列的真正最高高度，
则返回

~~~text
整数部分 + k*n − F(k,a,m,m+a−b−1)
~~~

推导来自每个高度 h=1…k 的合法列数
n−ceil((mh−b)/a)。将 h 改成 j+1，
ceil((m(j+1)−b)/a)=floor((mj+m+a−b−1)/a)，
就得到上式。它通过矩形补集递归，同样是欧几里得缩小；
这里的减号与偏移都是计数边界所需，不能任意挪动。

floor_div 能处理一般有符号参数，题目 main 读的是非负 u32，
实际以 i64 实例化核心。快速 I/O 的整数解析会批量读八/十六位数字，
还保留映射与其他输入路径。它没有改变渐近复杂度，
但核心表示与上游的先加矩形递归不同。

### #217798：参数保持32位，面积扩为64位

实际 main 调用 LinearFloorSum，而不是文件里大量的素数、模数类、
筛法或其他数论工具。每轮用 p=a/m、q=b/m 剥整数部分，
以 u64 计算 n(n−1)/2 与 a*n，再缩小参数、交换 a/m。
输入参数和递推后的参数适合 u32，面积和答案适合 u64。
它使用 BasicWriter；Reader 是否映射由 EVAL 编译宏决定。

### #316963：简短迭代与块缓冲读取

floor_sum 使用 int64 保存所有参数，每轮无条件计算 a/m、b/m，
取余后按第四节的状态递推。main 真正使用的是 rd.read、wr.writeln，
其底层为 fread/fwrite 缓冲；文件中还有 cin/cout 包装，
但不应误判成主输入路径。与上游相比，递归改成循环并简化转置公式，
I/O 也同时改变，因此快照不能拆出仅消除函数调用的收益。

## 6. 该打磨哪一层

| 层次 | 实际减少的工作 | 需要验证的条件 |
|---|---|---|
| O(N)枚举→欧几里得 | 不再逐列计算 | 格点转置与边界必须推导正确 |
| 上游矩形拆分→简短状态 | 减少中间除法/余数与参数整理 | 保持同一面积不变量 |
| 递归→迭代 | 函数调用、栈与状态传递 | 新旧参数不能交叉覆盖 |
| u32参数/u64面积 | 数据宽度与除法路径选择 | 所有乘积先扩宽 |
| 专用I/O | 通用格式处理 | 输入范围、尾部读取与输出完整性 |

几份公开实现和上游都已是 O(log M)，12–13 ms 的差距不能直接归因于
单一代码技巧。应固定 I/O，对照递归公式与迭代公式，再单独测输入输出。
正确性可穷举小 n,m,a,b 与朴素求和比较，重点覆盖 a=0、m=1、
直线恰好穿过格点、n=1 和接近上界的参数。
