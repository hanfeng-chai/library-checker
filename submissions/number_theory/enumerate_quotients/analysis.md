# 枚举整除商：怎样把一万亿个除数压缩成约两百万个答案

## 1. 题目与手算例子

给定 N，枚举所有不同的 floor(N/x)，其中 1≤x≤N，按升序输出。
floor 表示向下取整。[题面](../../../upstream/number_theory/enumerate_quotients/task.md)
要求先输出不同值的数量，再输出这些值；
[上限](../../../upstream/number_theory/enumerate_quotients/info.toml)为 N≤10¹²。

N=10 时：

| x | 1 | 2 | 3 | 4 | 5 | 6…10 |
|---|---:|---:|---:|---:|---:|---:|
| floor(10/x) | 10 | 5 | 3 | 2 | 2 | 1 |

去重并升序排列，得到 5 个数 [1,2,3,5,10]。
朴素地遍历 x=1…N，然后排序/去重，至少要 N 次除法；
N=10¹² 时不可行。关键是结果有很长的重复段。

## 2. 同一个商覆盖的除数区间，可以直接跳过

若从某个左端 l 算出 q=floor(N/l)，那么直到 r=floor(N/q) 为止，
商都还是 q。因为 q≤N/x<q+1 等价于：

~~~text
floor(N/(q+1))+1 ≤ x ≤ floor(N/q)
~~~

因此可以只走每个重复段的起点：

~~~text
l=1
while l≤N:
    q=N/l
    r=N/q
    记录q
    l=r+1
~~~

N=10 时依次走 [1,1]→商10、[2,2]→5、[3,3]→3、
[4,5]→2、[6,10]→1。得到的是降序值，若要求升序就再反转。
这个方法叫整除分块；分的是“商相同的除数区间”，不是固定长度数组块。

## 3. 为什么不同商只有 O(√N) 个

令 s=floor(√N)。把除数分两类：

- x≤s 时只有 s 个除数，直接列出 N/1,…,N/s；
- x>s 时商不超过 s，所以至多再出现 1,…,s。

两类加起来不超过 2s 个不同值。但要直接生成升序答案，
还需知道小值是否连续、两部分会不会重复。

### 3.1 小商确实是连续的 1…s

当 1≤q<s 时，q(q+1)≤s(s−1)<N，因此
N/q−N/(q+1)>1，必有一个整数除数落在上一节的区间中，
从而商 q 必出现。
对 q=s，若 N<s(s+1)，除数 x=s 就给出商 s；
若 N≥s(s+1)，除数 x=s+1 给出商 s。
所以每个 1…s 都有来源，而不是凭观察补进去。

### 3.2 大商不重复，交界只可能重复一个 s

对 x<s，有 N/[x(x+1)]>1，因此 N/x 与 N/(x+1) 的整数商严格不同。
反向枚举除数 s,s−1,…,1，就得到严格递增的 s 个商。
它的第一项 N/s 至少为 s，所以与小前缀 1…s 最多在 s 处重叠。

- N<s(s+1)：N/s=s，交界重复；总数为 2s−1。
- N≥s(s+1)：N/s>s，不重复；总数为 2s。

因此可先输出 1…m，再输出 N/s,N/(s−1),…,N/1，
其中 m=s−1 或 s，按上述条件选择。
N=10 的 s=3、m=2，输出 [1,2] 再接 [3,5,10]；
N=12 的 s=3、m=3，输出 [1,2,3] 再接 [4,6,12]。

另一种等价边界约定是始终输出 1…s，把第二部分的最大除数改成 m。
源码变量名相同也不保证用同一种约定，阅读时要看真正的两个输出循环。

## 4. 上游已经有 √N 算法，还额外省了一半大整数除法

[correct.cpp](../../../upstream/number_theory/enumerate_quotients/sol/correct.cpp)
并非朴素枚举全部 N 个除数。它先用 f 从 1 递增，直到 f²≥N，
同时把 1…f−1 放进向量。接着枚举 k，条件为 kf≤N，
把 floor(N/k) 追加到向量的后半部，最后只反转这一半。
这样前半升序、后半反转后也升序，两者交界不重复。

特别的地方在于 k 为偶数时：

~~~text
floor(N/(2t)) = floor(floor(N/t)/2)
~~~

N/t 已在此前 k=t 时存入向量，所以读取旧结果再除以 2 即可，
不必再做一次 N 除以变量 k 的运算。例如 N=20，k=2 的商是
已有 N/1=20 除以 2 得 10；k=4 的商是已有 N/2=10 除以 2 得 5。
这是真实代码 res[qp1+k/2−1]/2 的含义。

算法时间 O(√N)，向量空间 O(√N)；
不仅已经利用商集合结构，还复用了偶数除数的结果。
代价是构造向量、可能扩容、反转及后续遍历输出。
当 N=10¹² 时，约两百万个 long long 单元约 16 MB，
即使不算额外容量，也是一块可观的工作区。

### #393721 / #405739：去掉答案向量

main 先用 long double sqrt 估计 root，再以除法比较修正为精确的 floor√N：
只要 root+1≤N/(root+1) 就增加，只要 root>N/root 就减少。
这种比较避免在修正条件中计算可能溢出的平方。
本题 root≤10⁶，所以随后 root²+root 在 uint64 内也安全。

接着计算 m，输出数量 root+m，
直接输出 1…m 和 N/root,…,N/1。算法辅助空间为 O(1)，
另有固定输出缓冲和输入映射；它省掉上游的向量及反转，
但每个大商仍用一次 N/divisor，没有复用上游的偶数商技巧。
所以速度取舍包含少存数据与多做除法，不是所有方面都少工作。

该提交 main 没有调用文件前部的 enumerate_quotients 向量接口，
也没有调用附带的其他数论模板。统一 CRLF/LF 后两份源码完全相同，
12/13 ms 不能归因于可见的算法变化。

### #207554：相同集合划分，不同整数根修正

isqrt 以浮点根为初值，反复使用 (N/x+x)/2 的整数 Newton 更新，
fixpoint 处理先上升再下降的状态，小于 4 单独返回。
main 采用 m 小前缀加 s 个大商的约定，与前两份同样流式输出。
输出 io 使用自定义缓冲，不能因为接口像流插入就当成普通 iostream。
根修正只做一次，输出却可能百万项；不能仅凭根函数写法解释毫秒差距。

### #217996：交换两个分界角色

QuotientsList 保存 sq 与 m，但 main 输出 1…sq，
再从除数 m 递减到 1 输出 N/i。这是第三节的另一种等价约定，
不是把 sq/m 写反了。类的 operator[] 有自己的访问实现，
main 没有用它逐项读取。

IntSqrt 用 double sqrt 的整数估计减一，再以整数比较做一次修正。
其精度设计针对给定整数范围，和前两份的显式修正循环不同。
输入在 EVAL 宏定义时选择 MmapReader，否则选择 BasicReader；
不应只因文件中包含 mmap 就声称所有编译配置必走映射。

### #216285：返回整个商区间的通用迭代器

SqrtDecomposition::begin 从商 1 的区间
[N/2+1,N] 开始。递增迭代器在小商阶段把商加一并更新边界；
进入大商阶段后，区间只含一个除数，便把该除数减一并计算下一个商。
不变量是每一步的 m_quot 都在 [m_left,m_right] 上保持不变，
区间之间相邻而不重叠，因此不会漏值或重复。

main 只输出 m_quot，附带的区间端点对本题不是必需，
但可复用于需要“每段商×段长”的整除求和。
lower_bound、反向迭代等接口没有被本题 main 调用。
cin/cout 在文件顶部被宏替换为 OY::LinuxIO，并非标准流。
size 用平方根与交界条件计算项数，输出同样不保存完整答案向量。

## 6. 哪些结论可以复用

首先应复用的是“商集合只需两段”的结构证明。
若下游算法还要随机访问全部商，向量版是合理接口；
若只打印，则直接生成可以避免存储。若还需要每个商对应多少除数，
整除区间迭代器更方便。三者都有 O(√N) 时间，
单纯打印本身就需要 Ω(√N) 个数，优化空间主要在常数。

[本仓库教程](../../../problems/number_theory/enumerate_quotients/tutorial.md)
与 [direct_enumeration.cpp](../../../problems/number_theory/enumerate_quotients/direct_enumeration.cpp)
记录了流式路线，另有可复用的
[vector_enumeration.cpp](../../../problems/number_theory/enumerate_quotients/vector_enumeration.cpp)。
历史“成为榜首”以当时提交为准，本表才是上述时刻的当前记录。

验证应覆盖 N=1、完全平方数、s²+s 的前后及 (s+1)²−1，
因为所有去重差一错误都集中在交界；小 N 可直接枚举全部除数对照。
对性能则固定同一输出器，比较流式、向量和偶数商复用，
再单独比较 I/O。这里核对了例子、源码路径和哈希，没有新跑性能 benchmark。
