# Bernoulli Number：从分数递推到一次幂级数求逆

伯努利数在本题里由生成函数确定。前几项是
`1, −1/2, 1/6, 0, −1/30, 0, 1/42`；输出时把分数解释为模
`998244353` 下的除法。上游参考解与公开快解的数学目标相同，但
前四名利用了一个很具体的事实：分母的所有系数本来就已知，因此
可以省去上游的一整次通用级数指数计算。第五名进一步把偶数项压缩
到约一半长度处理。

把分母换成模逆元；这些分母在题目范围内都可逆。

## 1. 从定义手算前五项

本题使用的符号约定是

$$
\frac{x}{e^x-1}=\sum_{k\ge0}B_k\frac{x^k}{k!}.
$$

因此 `B_1=-1/2`。有些资料采用 `B_1=+1/2` 的另一种约定，直接
复制那种表会在第一项非零下标上出错。题面与上游代码可确定本题的
约定；`N=0` 则只输出 `B_0=1`。

这里没有在 `x=0` 对两个实数做 `0/0`。把分子分母共同的 `x`
先约掉：

$$
A(x)=\frac{e^x-1}{x}=1+\frac{x}{2!}+\frac{x^2}{3!}
\frac{x^3}{4!}+\cdots.
$$

`A` 的常数项为 1，所以它作为形式幂级数存在唯一的倒数。令
`G(x)=Σ B_k x^k/k!`，关系就是 `A(x)G(x)=1`。
比较 `x^m` 的系数，再乘 `(m+1)!`，对于 `m≥1` 得到

$$
\sum_{j=0}^{m}\binom{m+1}{j}B_j=0,
\qquad
B_m=-\frac1{m+1}\sum_{j=0}^{m-1}\binom{m+1}{j}B_j.
$$

这个递推足以一步步算出表格：

| 要求的数 | 系数方程 | 结果 |
|---|---|---|
| `B_0` | 常数项 `1·B_0=1` | `1` |
| `B_1` | `1+2B_1=0` | `−1/2` |
| `B_2` | `1+3B_1+3B_2=0` | `1/6` |
| `B_3` | `1+4B_1+6B_2+4B_3=0` | `0` |
| `B_4` | `1+5B_1+10B_2+10B_3+5B_4=0` | `−1/30` |

例如第四行中的已知部分是 `1−2+1=0`，所以 `B_3=0`。
第五行的已知部分是 `1−5/2+10/6=1/6`，故 `B_4=−1/30`。

模数为质数，`a/b` 的实现是 `a·b^{-1} mod p`。例如
`−1/2 mod p=499122176`，`1/6 mod p=166374059`。负号也必须
转成合法的非负模代表元，而不能把实数小数四舍五入后输出。

直接实现上述递推需要 `O(N²)` 个求和项，空间 `O(N)`，适合作为
小规模校验程序。`N=500000` 时约有 `1.25×10^11` 个求和项，
因此后面需要批量处理这些系数关系。

## 2. 生成函数只是改变数组中存的数

### 2.1 指数型生成函数的阶乘不能省略

普通系数数组 `[a_0,a_1,…]` 表示 `Σa_i x^i`。
指数型生成函数把第 `i` 个计数或数列值除以 `i!` 后再存进去。
本题要求的数组与中间数组分别是：

| 下标 | 输入给求逆函数的 `A_i=1/(i+1)!` | 求逆所得 `G_i=B_i/i!` | 最终 `B_i` |
|---:|---|---|---|
| 0 | `1` | `1` | `1` |
| 1 | `1/2` | `−1/2` | `−1/2` |
| 2 | `1/6` | `1/12` | `1/6` |
| 3 | `1/24` | `0` | `0` |
| 4 | `1/120` | `−1/720` | `−1/30` |

所以程序要准备到 **`(N+1)!` 的逆**，虽然最终阶乘只乘到 `N!`。
这是常见的差一错误。题目 `N+1<p`，所需阶乘均非零。

前四名的整个数学流程可以写成：

```text
准备 fact[0..N+1] 与 ifact[0..N+1]
A[i] = ifact[i+1]，i=0..N
G = inverse_series(A, N+1)
answer[i] = G[i] * fact[i]
```

### 2.2 一次级数乘法就是卷积

若 `C=AB`，则

$$
c_k=\sum_{i=0}^k a_i b_{k-i}.
$$

例如 `[1,2]` 与 `[3,4]` 对应 `(1+2x)(3+4x)=3+10x+8x²`。
这类求和称为卷积。NTT 先把多项式转换成一组模意义下的函数值，
逐项相乘后再逆变换，能在约 `O(n log n)` 时间内求出长卷积。
模数 `p−1=119·2^23` 为本题长度提供了足够的二次幂单位根。
进一步入门可看[卷积教程](../convolution_mod/analysis.md)。

“求 `A` 的逆级数”是求一个数组 `G` 使 `AG=1 mod x^n`，
不是分别计算 `1/a_i`。乘积中不同下标会互相影响。只要 `a_0≠0`，
由第 `k` 项系数方程就能唯一解出

$$
g_0=a_0^{-1},\qquad
g_k=-a_0^{-1}\sum_{i=1}^{k}a_i g_{k-i}.
$$

这仍是二次递推；它说明解存在且唯一，随后 Newton 方法加快同一
组方程的求解。

## 3. Newton 求逆：误差从 `x^m` 开始，就能一次补 `m` 项

### 3.1 误差平方的证明

假设已经知道 `G=A^{-1} mod x^m`。令 `e=1−AG`，那么 `e` 的
前 `m` 项均为零。定义

$$
G_{new}=G(1+e)=G(2-AG).
$$

相乘后 `AG_new=(1−e)(1+e)=1−e²`。`e²` 至少含有因子
`x^{2m}`，所以新结果正确到 `2m` 项。重复 `1→2→4→8→…`
即可求出所有需要的系数。

### 3.2 用本题的系数手算一次

已知 `G=1−x/2 mod x²`，把 `A` 保留到三次项：

$$
AG=(1+x/2+x^2/6+x^3/24)(1-x/2)
=1-x^2/12-x^3/24\pmod{x^4}.
$$

因此 `e=x²/12+x³/24`，修正后

$$
G_{new}=G+Ge=1-x/2+x^2/12+0x^3\pmod{x^4}.
$$

新的 `x³` 项恰好相消。乘阶乘后得到 `B_2=1/6`、`B_3=0`，
与独立的二次递推一致。

### 3.3 快解只写误差的高半段

把误差写成 `AG=1+x^m E`，则

$$
G_{new}=G-x^m GE\pmod{x^{2m}}.
$$

于是原有低 `m` 项不必覆盖，只需把 `−GE` 的前 `m` 项追加过去。
几份快速求逆代码的共同数据流是：

```text
a = A 的前 2m 项
b = 旧 G，补零到 2m 项
Ahat = NTT(a)
Bhat = NTT(b)
t = INTT(Ahat * Bhat)
把 t 的低 m 项清零
u = INTT(NTT(t) * Bhat)
G[m..2m) = -u[m..2m)
```

这里有 3 次正变换、2 次逆变换，并复用了 `Bhat`。最后一轮只把
真正需要的下标写入答案，或在完成后统一裁剪。

两个数组长度分别为 `2m`、`m`，完整线性卷积最长接近 `3m`，
为什么上面只用长度 `2m`？因为高于 `2m−1` 的项回卷后只落在
下标小于 `m` 的区域，而这部分恰好清零。第二次乘法仍只读取安全
的高半段。这是截断求逆的专门条件；普通乘法若也随意少补零，会
混入高次项。

每轮费用约 `M(2m)`，几何级数相加为 `O(M(n))=O(n log n)`，
同时只需线性数量的工作数组。该复杂度与模表示、AVX2 无关；后两者
进一步改变同一批变换的常数。

## 4. 上游 `correct.cpp` 真正做了什么

参考的是
[`upstream/number_theory/bernoulli_number/sol/correct.cpp`](../../../upstream/number_theory/bernoulli_number/sol/correct.cpp)。
它也使用生成函数，并且已经有 NTT 乘法，不能把它称为二次暴力。

### 4.1 外层的五步

| 代码操作 | 数学结果 | 精度为什么这样取 |
|---|---|---|
| 生成 `fact[0..N]` | 输出转换用的阶乘 | 最后要乘 `i!` |
| `po={0,1}` | 多项式 `x` | 给通用 FPS 指数当输入 |
| `po.exp(N+2)` | `1+x+x²/2!+…` | 下一步会丢掉常数项，故多算一项 |
| `po >>= 1` | `(e^x−1)/x` | 这个右移是“丢掉最低系数并移动下标” |
| `po.inv(N+1)`，再乘阶乘 | `B_0,…,B_N` | 与快解目标相同 |

尤其 `po >>= 1` 并非把未减去 1 的实数函数直接除以 `x`；其数组
操作本来就丢掉了常数项。因此结果确实是 `[1,1/2!,1/3!,…]`。

### 4.2 `exp` 是同步维护逆的倍增，没有调用通用 `log`

令输入级数为 `S`，当前指数近似为 `f`，逆近似为 `g`。源码每轮
在当前精度 `m` 下按顺序进行：

```text
g = (2g - f*g*g) mod x^m
q = S' mod x^(m-1)
w = q + g*(f' - f*q) mod x^(2m-1)
f = f + f*(S - integral(w)) mod x^(2m)
```

其中 `f'−fq` 的低 `m−1` 项已经为零。`g` 只正确到 `m` 项也
足够求出所需的高段；`w` 因而等价于 `f'/f` 到当前所需精度，
积分后就是 `log f`。最后一行实现 `f←f(1+S−log f)` 的 Newton
指数修正。形式导数、积分、指数的详细入门推导也见
[贝尔数教程](../bell_number/analysis.md#newton)。

这里的 `exp` **直接写出导数残差和逆维护**，并没有每轮调用源码
另一个 `log()` 或 `inv()` 接口。不能把通用公式的教学伪代码当成
这份文件的实际调用图。

### 4.3 最后一次 `inv` 也有可见的额外常数

上游的逆迭代直接写为
`res=(2*res-res*res*A.pre(2m)).pre(2m)`。乘法运算符会调用普通
完整卷积，计算完再截断。它不像前述高半段算法那样显式保存旧逆的
频域数组，也没有直接把只需的新半段写出来。

`multiply()` 在较短操作数长度不超过 8 时做二次乘法，否则执行
整数 NTT；变换每一级用临时数组重排，逆变换的长度归一化在乘法
末尾完成。`ModInt` 的模乘写成 64 位乘积再 `%p`。常量余数可能由
编译器化成乘法/移位，不能未经汇编核查就称为硬件除法。

还有一个与本题相关的线性扫描成本：`inte()` 对每项写 `/ (i+1)`，
而该 `ModInt::inv()` 用快速幂，没有逆元表。因此通用指数中的积分
会反复求标量逆元。若把模数也计入参数，额外工作是约 `O(n log p)`；
多项式部分仍为 `O(n log n)`。

直接填 `1/(i+1)!`，会省掉上述整个指数阶段，包括其中所有卷积、
积分和临时数组；这比单纯换一种输入输出方式更有明确的算法依据。
预处理仍需 `O(N)`，最后仍须输出 `N+1` 个数。

## #405758 / #383856：同一 Rust 实现，直接建分母级数

两份源文件逐字节相同。`main` 读 `n` 后建立 `Combination::new(n)`，`(0..=n).map(|i| comb.finv(i+1))` 生成 `A_0,…,A_n`。初始组合数表只含 `0!`、`1!`，后续 `finv(n+1)` 会触发 `precalc(n+1)`，所以 `n=0` 也有合法的 `1!` 倒数；扩展时用线性递推求整数逆元、阶乘、逆阶乘。随后调用 `poly.inv(n+1).unwrap()`，逐项乘 `comb.fact(i)` 并使用 256 KiB 缓冲输出。

真正走到的 `Polynomial::inv` 从常数项的倒数开始，`refine_inv` 每次把精度从 `m` 增到 `2m`：先对 `A` 与当前 `G` 做 NTT 点乘和逆变换，清零乘积的低 `m` 项，再 NTT 此误差并乘旧 `G`，把高半段取负追加到答案。最终截为 `n+1`。模数类型是 `ModInt998244353`，因此这里调用单模数 NTT；文件中通用的三模数 CRT 卷积、`exp`、`log` 等接口**未被此题 `main` 调用**。NTT 在长度至少 8 且运行环境满足其 x86 SIMD 检测时走 AVX2 实现，否则有标量路径；库代码的体积不能直接当作本题执行工作。源码检查的是 `is_x86_feature_detected!("avx")`，随后调用带 `avx2` 目标属性的函数：本次 OJ 运行无碍，但若移植到仅支持 AVX、不支持 AVX2 的 CPU，这个检测条件不足以保证安全。

相对 upstream，它省掉 `exp`，并直接用线性预处理填写每个 `1/(i+1)!`。相对 #17797/#65329，它只预处理到当前输入 `n+1`，对小 `N` 不支付固定 50 多万项的初始化。这两份榜首记录使用同一源码，因此无法从 90,112 B 的内存差或同为 38 ms 的时间推断实现差异；运行波动或环境因素都可能影响读数。

## #17797：同一数学路线，固定组合数表与 AVX2 NTT

`main→solve→BernoulliEGF` 是实际路径。`solve` **先**建立 `Binomial<mint> C(530000)`，即使输入 `N=0` 也预先生成约 53 万项阶乘、逆阶乘和整数逆元；随后读 `N`。`BernoulliEGF(N,C)` 把 `f[i]=C.finv(i+1)` 填到 `N+1` 项，再用 `FormalPowerSeries::inv(N+1)` 得到 `B_i/i!`。最后逐项乘 `C.fac(i)`，通过自制 128 KiB 缓冲读写输出。固定上限高于题目最大 `N=500000`，也覆盖所需的 `N+1` 项。

`FormalPowerSeries::inv` 的每级同样是“两次 NTT 乘法并只写高半段”的 Newton 倍增；其 `NTT<mint>` 路径带 AVX2 目标属性，并使用 32 位 Montgomery 模数表示。这个大文件还含 `TaylorShift`、Stirling 数、通用 `exp/log` 等模块，但 `solve` 没有调用。与 Rust 榜首相比，数学算法和复杂度相同，差别集中在固定预处理、NTT 内核、分配策略与 I/O。54 ms 对 38 ms 的差距无法凭代码静态阅读单独归因于某一个因素。

## #65329：手写 Montgomery/NTT 逆级数，固定预处理尤其影响小 N

`main→Main` 读入 `n` 后调用 `pre_fact(500002)`，无论实际 `n` 是多少都会填约 50 万阶乘、逆阶乘与整数逆元；再在约 2 MiB 的局部数组 `A[500001]` 中放入 `_inv_fact[i+1]`。`fps_inv(A,n+1,n+1)` 从常数项倒数起步，每级用两块预分配的工作区执行 NTT、点乘、逆 NTT、清低半段、再次 NTT/点乘/逆 NTT，将新半段写入结果。代码中的 `min_m32(work0[i],mod)` 名字容易误导：它实际调用 `sub_m32(0,work0[i],mod)`，是**模意义取负**，不是取最小值。最终 `ret[i]·_fact[i]` 转回普通模数值输出。

这份源码的 `m32` 是 32 位 Montgomery 表示，NTT 的模数与根表固定为 998244353，不必走任意模数 CRT。输入/输出使用 `getchar_unlocked`、`putchar_unlocked` 一类无锁 stdio，而不是 #17797 的整块输出缓冲。与 upstream 一样能在 `O(N log N)` 计算倒数，但同样省去了通用 `exp`；与 Rust 版不同，它把预处理规模固定为题目上界附近，所以小 `N` 的执行成本会很不成比例。85 ms 是完整 OJ 时间，单从这个值不能断定其 NTT 内核比其他版本慢多少。

## 5. 奇偶压缩为何正确：先证明零项，再构造半长数组

### 5.1 所有大于 1 的奇数下标项都为零

仍写 `G(x)=x/(e^x−1)`。把 `x` 换成 `−x`，化简得

$$
G(-x)=\frac{-x}{e^{-x}-1}=\frac{xe^x}{e^x-1}=G(x)+x.
$$

因此 `K(x)=G(x)+x/2` 满足 `K(−x)=K(x)`，是偶级数。在奇数次
系数上，这意味着 `−k_i=k_i`；模数不是 2，故这些系数都为 0。
于是 `B_1=−1/2` 单独处理，`B_3,B_5,…` 全部为 0。

令 `y=x²`，那么偶级数只需存成 `K(x)=C(y)`。所需数组长度从
`N+1` 降到 `floor(N/2)+1`。

### 5.2 不用计算双曲函数，也能得到代码中的两个数组

先写

$$
K(x)=\frac{x}{2}\frac{e^x+1}{e^x-1}
=\frac{(e^{x/2}+e^{-x/2})/2}
       {(e^{x/2}-e^{-x/2})/x}.
$$

分子只保留偶数次项，分母的奇数次项除以 `x` 后也成为偶数次。
把它们展开，便得到

$$
U(y)=\sum_{i\ge0}\frac{(1/4)^i}{(2i)!}y^i,
\qquad
V(y)=\sum_{i\ge0}\frac{(1/4)^i}{(2i+1)!}y^i,
\qquad C=U/V.
$$

它们也可以分别记为 `cosh(x/2)` 与 `sinh(x/2)/(x/2)`，但实现
不需要任何实数双曲函数，只需要逆阶乘和逐项乘 `1/4`。

手算前几项：

```text
U = 1 + y/8  + y²/384  + …
V = 1 + y/24 + y²/1920 + …
C = 1 + y/12 - y²/720  + …
```

`C` 中 `y` 的系数对应原级数的 `x²`，所以乘 `2!` 得 `B_2=1/6`；
`y²` 对应 `x⁴`，乘 `4!` 得 `B_4=−1/30`。下标与阶乘都应按
原次数 `2i` 恢复，不能误乘 `i!`。

### 5.3 半长求逆为什么不等于整程序时间减半

这一变形需要 `C=U·V^{-1}`，比前四名的直接求逆多了一次乘法。
它减少求逆的数组长度，但最终全卷积、填入奇数零项和输出仍有成本。
下面第五份源码会具体说明这次全卷积所用的变换长度。

## #339049：利用奇偶性改写生成函数

这份源码走 `main→Yorisou→bernoulli<mint>(N)`，数学路线与前四份不同。设 `y=x²`，代码构造

```text
F(y)=Σ_{i≥0} (1/4)^i · y^i/(2i)!       = cosh(x/2),
G(y)=Σ_{i≥0} (1/4)^i · y^i/(2i+1)!     = sinh(x/2)/(x/2).
```

于是 `F(x²)/G(x²)=(x/2)coth(x/2)`，而 `x/(e^x−1)=(x/2)coth(x/2)−x/2`。所以 `B_1=-1/2`，`B_{2i}=(2i)!·[y^i]F/G`，所有奇数 `B_{2i+1}`（`i≥1`）为 0。`bernoulli` 令 `n=N>>1`，只建 `n+1` 项 `f,g`，每项乘一个逐步更新的 `1/4`；`fps_div(f,g)` 求商；最后创建 `N+1` 个答案槽，放入 `B_1` 和偶数项。`N=0` 时 `f=g=[1]`、输出 `B_0=1`；`N=1` 时额外设 `B_1=-1/2`，边界吻合。

`fps_div` 实际先求 `g` 的倒数，再做一次 `convolution(f,g^{-1})`，并截断到 `n+1`。`fps_inv` 统计 `g` 的非零项：项数至多 160 时走稀疏 `O(n·项数)` 递推；大输入走 NTT Newton 倍增。`fact_inv`、`fact`、`inv` 是按需求扩展的静态向量，不像 #17797/#65329 一开始就固定预热全部上限。文件里较早定义过 `print` 的 `cout` 版本，但在本题 `Yorisou` 前，宏已把 `IN` 与 `print` 改写到缓冲 `read/println`，因此实际输入输出不是普通 `iostream`。

只做约半阶的倒数**并不保证总耗时也减半**。这份 `fps_div` 的末尾调用普通全卷积，即使只需要低 `n+1` 项，也先算长度约 `2n+1` 的完整乘积；在 `N=500000` 时，卷积长度约 500001、NTT 长度仍可达 524288，与前四份倒数最后一级的 NTT 长度同量级。它还要做独立的一次乘法与写出全部 `N+1` 个答案。故 86 ms 排在第五，不能据此否定奇偶性改写；需要同机、同 N、同 NTT/I/O 内核对照，才能量出数学降阶的净收益。

## 6. 把数学降阶与工程成本分开比较

| 实现选择 | 相对上游省掉或改变的工作 | 正确性条件或代价 |
|---|---|---|
| 直接构造逆阶乘分母 | 整次通用 `exp(x)`，及其导数、积分、卷积 | 必须多准备到 `(N+1)!` 的逆 |
| 高半段 Newton 求逆 | 无用低项、部分重复正变换、较长完整卷积 | 回卷只能落入丢弃的低半段 |
| 按实际输入扩展组合数表 | 小 `N` 时不初始化几十万项 | 动态扩展必须覆盖访问到的 `N+1` |
| 固定上限表与工作区 | 减少反复分配或扩容 | 小输入仍支付固定工作；容量须覆盖最大输入 |
| 奇偶压缩 | 求逆的长度约减半，奇数答案直接为零 | 多做一次 `U·V^{-1}`，保留 `B_1` 例外 |
| Montgomery / SIMD NTT | 蝶形的模约减和逐元素指令成本 | 模表示、整数值域和 CPU 特性必须匹配 |
| 缓冲数字输出 | 整数转字符和输出接口调用成本 | 最终仍要输出 `N+1` 项 |

Newton 算法本身的空间为 `O(N)`；固定表实现还占有按题目上界 `U`
预留的空间，若同时观察不同输入大小，更精确的写法是 `O(N+U)`。
例如 #65329 的 `fps_inv` 两个工作区各按 `3<<19` 个 `m32` 分配，
实际只使用当前变换长度的前缀；虚拟分配量、被访问的页面和 OJ 峰值
内存不是同一个指标。

“SIMD”是用向量指令一次处理多项，“Montgomery”是把反复出现的
模乘改写为低位乘法、加法和移位的一种模表示。两者可组合，但都
不改变求逆的数学公式。伯努利数的最大结构性简化发生在进入这些
内核之前：先识别分母系数已经有闭式。
