# io_batch

批量接口复用 [`io.h`](io.md) 的 Reader/Writer，不改变单次读写接口。
输入仍要求无符号十进制整数之间恰好一个空格或换行。

- `read_bulk<T, Digits>(in, span<T>)`：把输入字节块切成四个独立游标，减少连续解析
  对上一个数字结束位置的依赖。Digits 是最大十进制位数。
- `read_bulk9(in, span<u32>)`：每个游标一次读两个至多九位的整数，AVX2 同时归约
  八个数字；适合大量模数余数、坐标等输入。小段和块边缘复用 Reader。
- `write_bulk9(out, span<const u32>)`：值必须小于 10^9，每项用九列右对齐数字加
  一个空格。前导位置填空格，数字本身没有前导零；只用于允许重复空白的输出协议。
  Writer 容量至少 326 字节，默认容量满足。

多游标读取和定宽 SIMD 输出参考 Aiyiyi 的大卷积提交。固定字段消除了每个数字
更新可变长度输出游标的依赖，代价是小整数输出占用更多字节。接口按数组显式调用，
不会影响其他题解的输出格式。

除官方卷积数据外，验证覆盖十进制位数边界、输入分块边界、空数组和最小 Writer
容量。性能收益以完整题解为准；不能由大数组卷积的结果推断所有输入分布都更快。

图题还使用以下接口：

- `read_pairs6(in,count,emit)` 批量解析两个至多六位的无符号字段，按输入顺序调用 `emit(index,u,v)`。
- `read_triples(in,count,emit)` 对应 6/6/10 位三字段记录，调用 `emit(index,u,v,w)`；数值均须容纳于 u32。
- `read_triple_rows(in,span<Record>)` 使用四条独立解析流；Record 须可平凡复制，并能由三个 u32 聚合初始化。额外要求每条三字段记录独占一行。
- `write6`、`write_bulk6` 输出小于 10^6 的规范十进制数。分隔符可选空格或换行，不添加列宽填充。

前两个回调可以直接建图；回调不得继续读取同一个 Reader。范围约束由调用方保证。
