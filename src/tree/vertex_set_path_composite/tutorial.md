主解提供三种树形自适应实现：浅树沿父亲逐点应用；一般情形用普通 HLD 加紧凑

## 尝试过程

最初直接组合 HeavyLight 和通用 BidirectionalTree。正确性简单，但最坏的重链
分解会做许多链内查询，max 明显落后。第一步把每节点的两个方向压成共享斜率
与两个截距，并直接把覆盖节点作用于 x，减少中间复合函数；常数下降，最坏情况
仍是 O(log² n)。

随后按顶点和轻子树大小构造加权链内树，缓存左段加本点的前缀，使跨链和链内
代价相互抵消。它大幅降低不利分解用例的 max，但总耗时仍高。改回普通模运算、
用真正的加权中位数建树，都没有解决这个问题。

再把路径元数据改为按 DFS 序索引，端点只映射一次，用链头的 DFS 编号决定
上跳方向。这个改动使 max 达标，然而普通长链的加权树常数仍偏大。
加入浅树父链直算，又降低了 sum。最后按树形在父链、紧凑线段树、加权链树之间
选择，使长链不承担加权结构的成本。

最初自适应版本在每次 set/apply 时判断模式，max 仅比参考低约 0.01%，不足以
判断稳定收益。把三种算法分为具体类型，在进入操作循环前分派，获得更明确余量。

## 正确性

各候选通过 GCC/Clang 正式测例。另对任意编号、任意初始根、零乘数、奇合数模数
进行独立朴素路径对照，并覆盖拉长边后的二叉树以触发加权分支；ASan/UBSan 通过。
主解允许乘数为零，所有结构都不依赖函数求逆。
